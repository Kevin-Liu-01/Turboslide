### 1.2 Decisions

- `file` is refused on the studio's dispatchers on every store, not only hosted: the editor sends pictures as data URLs (`packages/chrome/src/inspector/asset.tsx`, the two e2e specs that call `asset.add`), so a path on the studio process is never a person's input, and report 04 F13 shows a cross site form POST reaching a checkout's `/api/actions` on localhost. The loopback names leave the allowlist on a hosted store only (`isHosted()`), because a checkout captures the Prototemplate dev server on 3005 (the round one test in `capture.test.ts`).
- The forwarded host rule is "narrow, never widen" without trust, so the round one test `a public forwarded name over a local Host refuses` and the M4 e2e row (`X-Forwarded-Host` off localhost answers 401) both hold, and the F11 spoof (`X-Forwarded-Host: localhost` over a public `Host`) refuses too. The rule lives in `packages/agent/src/http/dispatch.ts` (B4's file, framework free) because `auth.ts` is B3's this round; request 2 asks B3 to fold it into `requestHost` and `requireAgentAuth` so `/mcp` gets it in the same place.
- `authorize()` is generic over the record type. B3's `decide()` (`packages/identity/src/access.ts`, in the tree today) is `(record: AccessRecord | null, ctx: AuthContext, capability: Capability, options?) => Decision` over the identity package's fuller record, and its 403 carries the capability; B4's local `Decision` accepts it structurally. B3's `decide()` answers 401 when the context has neither a principal nor an agent, so once it is bound the window transport's stranger context (`anonymousContext()`) will log 401 denials for every call until `readPrincipal(request)` binds the session on day three; that is the expected shape of the shadow week, not a defect.
- The interim `decide()` reads `open: editor` for a missing record and withholds `remove`, `settings` and `transfer` (the owner's rows of 6.2), so the shadow log on day one names exactly the calls enforcement will refuse on unclaimed decks: Delete forever and the gear.
- `sharp.block` lives in the headless package (the untrusted decode path B4 owns) and runs at module load and before every `imageInfo`; `packages/effects/src/io.ts` is B5's, request 5 asks for the same call there so the render worker's `decodeImage` is covered when a source file is re-toned.
- The magic byte sniff and `limitInputPixels` are day three and four items of 8.5 that cost a few lines beside the R0 edits; landing them now closes report 04 F17's "sniff before sharp" for the intake path. The re-encode, the size caps per identity and the presigned path stay on days three and four.

### 2.2 Decisions and deviations

1. The bootstrap bearer is the matrix's deployment admin (`principal: { id: 'usr_admin', admin:
true }` beside the agent record), not an agent with the `admin` scope: B3's `decide()` reads
   the admin through `principal.admin` and gives an agent its owner's standing, and the bootstrap
   token's owner has no record on any deck. The author of its writes stays `agent:bootstrap`.
2. The record loader of this stage reads the checkout's `decks/<id>/.turboslide/access.json`
   through the schema package (SPEC-3 6.9 names the file), so enforce mode has real records to
   refuse on a checkout and `security.spec.ts` can seed one; B2's access store replaces it through
   `bindAuthorize({ loadRecord })` on day five and nothing else changes.
3. The nonce CSP is emitted from the middleware into the request context, but the two files that
   must read it (`apps/studio/src/router.tsx` for `ssr.nonce`, `__root.tsx` for the boot script's
   `nonce` attribute) are in no builder's list: request 2.4.2 asks the integrator for the two
   lines. Until they land, the report only policy reports the inline boot script and TanStack's
   own inline scripts on every page; that is the expected noise of the report weeks, not a reason
   to widen the policy, and `TURBOSLIDE_CSP=off` silences it on a dev server if it bothers a builder.
4. The web security switches of the serverless binary are dropped under
   `TURBOSLIDE_WEB_SECURITY=strict` and kept by default: the binary is Linux x64 and cannot run on
   this machine, so the `file://` subresource fixture measurement (8.10) is the verifier's preview
   run; when it renders without them the default flips in one line.
5. The presigned upload path is implemented on a local backend (a signed PUT to
   `/api/x/upload/put/<token>` streamed and sniffed on the instance) with the grant shape the
   private store's client upload will answer; the account boundary of this round creates no
   private store, and `@vercel/blob`'s client token is not a dependency of `apps/studio`
   (`packages/store` holds the package). The 3 MB rule and the caps are real now; the Blob backend
   is one more `backend` value when the store exists (docs/security.md section 10).
6. `apps/studio/src/routes/api/x.csp.$.ts` is a new file beside the three `/api/x/*` routes the
   plan names: the report only CSP needs an endpoint under a WAF visible prefix, and putting it
   under `/api/x/render/` or `/api/x/upload/` would count browser reports against R2 or R17. It
   has no WAF rule (SPEC-3 fixes R1 to R21); the route's own 60 per minute per address limit stands
   in.
7. `frame.ts` takes the frame's theme and asset resolver from the caller and the height from the

#### 2.6.4 Rules learned

- Server modules stay out of the browser's module graph: `start.ts` loads the request
  middlewares behind `import.meta.env.SSR`, and a `createServerFn` module that the client also
  imports (`decks.ts`, `render.ts`, `download.ts`, `agent-actions.ts`, `bundle.ts`) imports
  `./authorize`, `./flags`, `./ratelimit`, `./log` and `./tokens` inside its handlers, because the
  client transform keeps a module level import that is referenced outside a handler (measured: the
  editor failed at `packages/store/src/lease.ts` "node:fs has been externalized" through
  `start.ts > auth/middleware.ts > root.ts` when the imports were static).
- The upload token carries the in flight slot it took (`slot`), and `receiveUpload` releases it,
  so an abandoned grant does not hold the caller's concurrency slot past the token's expiry.
- `/api/x/csp` is exempt from the JSON body rule and the CSRF filter: browsers post reports as
  `application/csp-report` without `Origin`; the endpoint has its own quota per address instead.
- An empty body with a `content-length: 0` is not a body: `requiresJsonBody` lets it through
  whatever type the client stamps on it (Playwright stamps `text/plain` on an empty `data`).

### 3.2 Decisions and deviations

1. The verifier's fix for finding 17 is documentation: hosting.md says the quotas need Redis to
   hold hosted and the WAF rules carry the limits until Kevin installs Upstash. B4 did that in
   its own documents and, in its own code, made the state observable: a platform process on the
   memory backend logs one `config.degraded` line at start. Not `config.missing`: that alert pages
   on any line, and every cold start of a Fluid compute instance would page for a state the round
   chose on purpose; `config-degraded` notifies.
2. The condition is `root.isHosted() && VERCEL set`, not `isHosted()` alone: the builders' dev
   servers run `TURBOSLIDE_STORE=tmp`, which `isHosted()` counts as hosted, and a checkout is one
   process whose memory counter holds. The 4333 server of 3.3 logged no line.
3. No counter over the Blob store, on purpose and not as a deviation: the verifier's fix does not
   ask for one, a `BlobStore.write` per counted request would cost more than the request it counts
   (a thumbnail GET is 154 ms at p50 on the preview), and Blob commits are about 15 a second
   across a deployment (docs/hosting.md section 9). If Upstash is not installed by round four, a
   coarse Blob counter for the few expensive rows (exports, bundles, materialize) is the item to
   weigh then.
4. `Ratelimit.slidingWindow` replaces `fixedWindow` in `start.ts`: SPEC-3 8.3 names the sliding
   window and section 4 of docs/security.md said so, the code did not, and nothing recorded the
   choice. The `upstashLimiter` test drives a fake and does not depend on the algorithm; the real
   package is never loaded this round (the account boundary). The memory and kv backends stay
   fixed windows, as their docblocks say.
5. The honest sentence about the WAF: in log mode the rules limit nothing. Until the flip, and
   without Redis, no windowed request limit holds on the deployment beyond the platform's own DDoS
   mitigation; the docs say so and name the option Kevin has (flip the 429 rules first, because a
   429 is recoverable for a browser and a CLI alike, and keep the week for deny and challenge).
   The mode of `firewall/rules.json` stays `log`; the flip is Kevin's date (R8).
6. The verifier's "the 429 with the sentence" row stays FAIL on the preview by construction until
   `REDIS_URL` is set; the row to rerun then is the 401st anonymous render of an hour from any
   instance answering 429 with `Retry-After` and "Too many slide renders this hour. Try again
   later", and the `config.degraded` line absent from the boot log.
