### 1.1 C3-R1, `shapes.fill.colour` (C3-F7): the plate's focus effect

`packages/chrome/src/pickers/ColorPlate.tsx`. The mechanism is b3's C3.2: the effect keyed on `[anchor, onClose]` ended with `root.current?.querySelector('button')?.focus()`, and `ToolbarTail` passes `onClose={() => setPlate(null)}`, a fresh closure on every render of the tail, so a revision landing while the hex value was typed (on the memory tier the checkpoint of the swatch write of the same row, 2 s after it) re-ran the effect and moved the focus from the hex field to the None swatch; Enter then landed on that button, the plate stayed open and the value never reached the shape. The fix is the second shape b3 offered: the focus moved into `useMountEffect` (`lib/useMountEffect.ts`), run once on mount, and the outside click listener effect stays keyed on `[anchor, onClose]` with no focus call, so it follows the latest `onClose` (the plate closes through the caller that rendered it last) without touching the focus. `AnchoredPlate` (`ToolbarTail.tsx`) was not changed: its listener effect has no focus call. `ToolbarTail`'s `onClose` closure was not made stable: the file is not in this lane's list, and the plate is now right whatever the caller passes.

Test: `packages/chrome/src/__tests__/color-plate.test.tsx`, three cases: the first swatch has the focus on mount; the hex field keeps the focus and its value across a render with a new `onClose`; Enter on the field picks the typed hex and a click outside calls the latest `onClose`, not the first.
