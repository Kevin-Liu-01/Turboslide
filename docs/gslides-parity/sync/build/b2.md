### 1. What was built

All under this lane's "Owns" list.

- `packages/realtime/src/protocol.ts`: `PRESENCE_HEARTBEAT_QUIET_MS` (10,000) beside `PRESENCE_HEARTBEAT_MS` (5,000), the two constants this lane owns there and nothing else.
- `packages/realtime/client/room-client.ts`:
  - Acknowledgement by id (3.2, invariant 4). `coversOf(entry)` reads `Entry.covers` (B1's first commit; read structurally so a frame from an older server covers nothing). `acknowledge(entry)` settles every pending op the entry's `covers` names, and the op the entry's own id names when the entry is this tab's; `settleByCovers` runs first in `applyEntry` and applies the record's folded mutations once; `settleOwnEcho` (the byte match) stays as the fallback for a record without an origin and is never reached for a record that has one, so an equal fold from another tab is never taken for this tab's. `settledOps` (the newest 2,000 acknowledged op ids) makes a record's echo whose every op is settled repeat nothing whatever order the answer, the echo and the checkpoint frame arrive in. `take` at the position and `drain`'s later siblings go through `takeAtPosition`, which settles a record's echo, an applied sibling or an acknowledged op instead of applying it, so an echo buffered beside the answer's entries above a gap never doubles the batch. The POST's byte match record leaves the echo list after the answer's entries were taken, not before. `settleBehind` acknowledges by `covers` too.
  - The resync read's origins (3.2, invariant 10). `onResync(revision, since)` carries the tab's position before the resync and may answer a `ResyncAnswer` (`document`, `origins: { seq, opIds }[]`, `bounded`); a bare document is accepted as before. `settleFromResync` acknowledges every pending op an origin names at that record's seq and never re-sends it; when the answer is `bounded`, or on the blob tier when the head is more than `REPLAY_MAX_ENTRIES` above `since`, every op posted before the resync (an op id assigned) is dropped with the queue and returned to its author with the reject card's sentence (`UNPLACEABLE_SENTENCE`), and an op never posted stays and re-folds.
  - Undo (invariant 11). `transformSince` skips an entry under one of this tab's client ids or whose `covers` name an op the tab minted (`ownEntry`); a second tab of the same person carries another client id, so its entries are remote and the inverse is transformed past them.
  - The fields (3.4, invariant 5). The client's `rewritesText` mirrors the schema's: a `slide.set` of a slide field pointer rewrites the run that names that field alone, any other slide pointer every run on the slide.
  - The heartbeat (3.10). `heartbeat` arms each beat at `PRESENCE_HEARTBEAT_MS` while the pointer, the selection or the slide moved in the last `PRESENCE_QUIET_AFTER_MS` (30 s, exported here) and at `PRESENCE_HEARTBEAT_QUIET_MS` otherwise; `setPresence` notes a move when `pointer`, `selection` or `slideId` changed value (`pointerOn`, `presenting` and `follow` move nothing) and a move while the quiet beat is armed re-arms it at 5 s.

  - `announceRemoteText` tells the session under the pointer it keys its run by: a field's op travels at `/heading` and is drawn as `heading/text` (`render/slide.ts` data-run), so the announce carries `pointer: 'text'` for a field.

### 2. The field target convention, as built against B1

Read from B1's in progress tree at 13:10: `text.splice`, `text.mark` and `text.replace` take `blockId` `heading` or `lead` on a title slide and `big` on a statement slide with `path` the field's own pointer (`/heading`, `/lead`, `/big`; the reducer refuses another path for a field), resolved by the slide's kind (`slideFieldOf`), so a content slide's block whose id is `heading` stays a block. `rewritesText` treats `slide.set /heading` as a rewrite of the heading's run alone. `followTitle` derives the deck's title from the heading of the deck's first title slide while the title still reads the blank deck's title or the heading's plain text from before the op, and appends the title's inverse to the op's. The client mirrors every one of those.
