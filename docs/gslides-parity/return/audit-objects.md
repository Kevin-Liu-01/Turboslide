# Parked objects on production: the return audit

Auditor for the area "Parked objects: tables, charts, diagrams, code panels, word art, icons, materials, plates, connectors and the shape galleries", return round, 2026-09-18, against production https://turboslide.vercel.app serving `1d3ba31` (the focus round's ship). Headless Chromium through `playwright-core` 1.62.1 from the repository's `node_modules`, Node 24.13.0, viewport 1440 by 900 at device scale 1. No source file was changed and no git write command ran. The scripts live under the auditor's scratchpad (`return/objects/audit-objects.mjs` for run 1, `audit-objects-2.mjs`, `audit-objects-3.mjs` and `audit-objects-4.mjs` for the three follow-up runs) and import nothing from the repository but `playwright-core`. The evidence is under `docs/gslides-parity/return/audit-objects/`: the screenshots `01-` to `57-` (run 1), `61-` to `63-` (run 2), `71-` to `89-` (run 3) and `91-` to `100-` (run 4), the row tables `run-N-rows.json` (each with a `.jsonl` twin written row by row as the run went), the stdout logs `run-N.log` and the cleanup logs `run-N-cleanup.log`.

## Method

Four scratch decks, each created from `/new` by a double click on the title placeholder and a typed name, and each trashed and deleted forever through the product path at the end of its run (File > Move to trash, then Delete forever on /decks/trash with its confirm): `untitled-20260918-f2ht` (run 1, the whole battery, 85 rows, 869 s), `untitled-20260918-p8dm` (run 2, the toolbar Text box rows run 1 read while an object was selected), `untitled-20260918-yzqv` (run 3, the mechanisms behind the table failures and the charts read with the right svg root) and `untitled-20260918-fi6d` (run 4, the chart data grid scrolled into view, the Diagram panel under its own control prefix, and the show read from the visible slide). All four answer 404 on `/deck/<id>` and `/edit/<id>` (the four cleanup logs).

Every interaction was driven through the product's own controls: the menus by `data-control` (`menubar.<menu>`, `menu.<row id>`), the plates by their cells (`insert.table.pick.<c>x<r>`, `insert.shape.gallery.pick.<preset>`), the toolbar tail's controls (`toolbar.fillColor.<swatch>`, `menu.toolbar.borderWeight.weight-<n>`, `toolbar.borderDash.pick.<dash>`), the Format options fields (`formatOptions.size.width`, `formatOptions.chart.cell.<r>.<c>`, `formatOptions.chart.edit`), the Diagram panel (`insert.diagram.type.<kind>`, `insert.diagram.count.more`, `insert.diagram.insert`), the overlay handles (`handle.<id>.resize.<dir>`), the table cells by their runs (`data-run="<table id>/rows/<r>/cells/<c>"`), the cell right click menu (`.ts-context-menu`), the title row's Slideshow button (`present.open`) and the Download dialog (`dialog.download.<format>`, `.ok`, `.ready`). Every observed value is read from the DOM and from `window.turboslide.studio` (`describe().state`, `slide.get`). Human speed throughout: the mouse moves in steps with a pause between them, keys land 40 to 90 ms apart, double clicks are the browser's own, and every drag holds the pointer from down through the move stream to up. A failed interaction was repeated three times before it was called broken (twice for the twelve drawn presets, whose click twins had already failed three times on the same path, and for the rows of runs 3 and 4 that repeat a run 1 row); a pass on a later try is flaky; an interaction the script could not drive is not driven with the reason. The parked rows were reached with Tools > Advanced tools turned on from the Tools menu, once per browser context.

Where a later run corrected a run 1 reading, the table says so in the row's why and the result column carries the corrected reading: the chart rows of run 1 asked for an svg descendant of a block whose root element is the svg itself (rows 61, 64 and 66 to 69, re-read in run 3 rows 10 to 14); the export rows expected twelve slides where the deck had eleven (rows 83 to 85); the present rows read the `present.show` root, whose text is the toolbar's counter, instead of the visible slide (rows 79 and 80, re-read in run 4 rows 8 and 9); the Diagram row clicked `panel.diagram.*` controls that do not exist (row 70, run 3 row 16, re-driven in run 4 rows 6 and 7); the chart data row clicked a grid cell below the panel's fold (row 63, run 3 row 15, re-driven in run 4 row 5); and run 1 row 10 read the toolbar head while the drawn text box was still selected (run 2 rows 2 to 4). Every override is a script correction, never a product judgement, and the raw readings stay in the `run-N-rows.json` files.

The slides: each feature got its own slide added with the toolbar's New slide and the Blank layout from the Layout plate. On the first added slide the plate's Blank kept the two placeholders on the stage ("Click to add title", "Click to add text"; screenshot `07`), which FOCUS.md 2.2 recorded ("Apply layout carries untouched placeholders between layouts"); the objects landed beside them and nothing here depended on the placeholders. The PDF and the two PowerPoint files were read with `pdfinfo`, `pdftotext` and `unzip` from the machine.

Severity: 3 a seller cannot complete the task, 2 a wrong or lost result, 1 cosmetic, 0 no defect. Verdicts: return (it works today and a seller uses it), return after fixes (it worked or nearly works and the fixes are named), stay parked (it does not work and is not a seller's tool, or it is a designer's tool), not a feature (the row is not a product feature: a setup step, a record of a menu, or a block with no UI route). The "before" column cites the focus audits' tables under `docs/gslides-parity/focus/` and the shapes decision in `docs/FOCUS.md` section 4; where no focus audit measured the interaction it reads "not measured".

## What "boxes" can mean on production today

Kevin's word is "boxes". The candidates, read from the Insert menu in both views (rows 2 and 6, screenshots `02` and `04`), the grammar's block kinds (`packages/schema/src/blocks.ts` `BLOCK_TYPES`) and what each does today:

1. Text box (`insert.textBox`, the default view, and the toolbar's T button). One click places a 480 by 64 text object that opens in the caret state; a drag draws the box at the drawn size; typing lands (rows 8 and 9, run 2 rows 3 and 4). It is the only box in the default view, and it has no fill, border or corner radius controls: the text tail carries font, size, colour, lists and alignment (run 2 row 2), and Format options carries no Colour section for it.
2. Rectangle and Rounded rectangle (`insert.shape.shapes.rectangle`, `.rounded`, behind the switch). One click places a 240 by 160 shape, a drag draws it at the drawn size; the rounded rectangle draws an `rx` 8 corner; the toolbar Fill color, Border color, Border weight and Border dash write to the block and the svg; Enter on the selected shape opens a text run inside it; Format options carries Size, Position, Text fitting, Text, Colour, Shadow and Shape (rows 11 to 23). This is the labelled, filled box a seller draws in Google Slides (research 07 "Adjust an image or shape"), and it works today on the dark appearance this audit drove.
3. The Box block (`box`, "A bordered box with an optional text inside", `catalog.ts` label "Box", allowed in a content slot). It has no route in the product's UI: the Insert menu lists it in neither view and production has no palette button (`palette.open` is not in the toolbar, rows 4 and 7), so only the agent and the CLI can place one. The same holds for the Code panel (`panel`), Logo plates (`logoPlates`), Tile grid, Detail grid, Status board and HTML escape blocks: grammar blocks a layout or an agent writes, not objects a seller inserts.
4. The gallery presets, Callouts among them (`insert.shape.gallery`, `insert.shape.callouts`). Every preset other than the rectangle, the rounded rectangle and the ellipse inserts as the plain box path (rows 24 to 49), so a callout is a box with no pointer.

The reading: "boxes" is the rectangle shapes with a fill, a border and a label (candidate 2), which the focus round parked with the whole of Insert > Shape, plus the Text box a seller already has. The Box block (candidate 3) is not a feature a seller can reach and needs no decision.

## Summary

What works today, with the switch on. The minimal shape set is whole: Rectangle, Rounded rectangle and Ellipse insert by click and by drag as real geometry, select with the chip and eight handles, move from inside the selection, resize with the readout, take a fill, a border colour, weight and dash from the toolbar, open a label with Enter, and carry Size and Position in Format options, a nineteen row right click menu, Cmd+D, Delete and Cmd+Z (rows 11 to 23). Lines and arrows draw with their heads, and the elbow and curved connectors snap to the shapes' connection sites and follow the shape that moves (rows 76 to 78, run 3 row 18). Charts of all four kinds insert with sample data, draw, resize, change kind, gain series and categories, and their numbers are edited in the Format options grid (run 3 rows 10 to 14, run 4 row 5), the very thing the research names as Google's most cited chart complaint. Diagrams insert as a group from a panel with real glyphs and move together (run 4 rows 6 and 7). Word art places its text (row 71). Tables insert from the grid with a header row, take typing by double click, gain and lose rows and columns from the cell menu, append a row on Tab from the last cell, resize, and survive the show, the PDF and the native PowerPoint (rows 50, 52 to 56, 58, 60, run 4 row 8, rows 83 to 85). Every object survives a reload and the viewer; the PDF, the Perfect and the Editable text PowerPoint download with the objects in them.

What is broken, with the mechanism seen. Tables carry the defects a seller meets first. Tab from a cell that has been typed into ends the session instead of moving to the next cell: Editor.tsx 1599 to 1605 opens the next cell at once only when nothing was written, and otherwise defers it to `pendingEdit`, which did not open on production in five tries across two runs; the keys typed next then hit the selected table and, under the A1 typing rule, open its first cell with everything selected and replace it ("Next" landed in cell 1,1 and replaced "Head"; run 1 row 51, run 3 rows 4 and 5).
