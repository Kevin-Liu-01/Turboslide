### B4b#6 seam: the deck linter on the speed mark slides (b4.md request 7)

B4's request 7 names two rules of B5's package that misread the speed mark slides the 95 slide
import brings (`P:deck/slides/17` to `23`, html blocks carrying the files of `P:public/marks`).
Both fail step 15 and the editor's Check slides on a deck made from the GT template.

- `packages/lint/src/static/color.ts`: `color/tokens-only` reads the markup without its `<mask>`
  elements (`withoutMasks`). A mask's fills are luminance: white keeps, black cuts, and the plate,
  double cut and livery marks cut their letters with `fill="#000"`. A token there would invert the
  cut in the dark appearance. A colour outside the mask is still a finding.
- `packages/lint/src/static/type.ts`: `type/svg-label-min` reads the markup without its glyph art
  (`withoutGlyphArt`): a `<text>` element with `xml:space="preserve"` in a monospace face, which
  is how the ASCII mark draws its rows. A label beside it, or the same rows in a proportional
  face, is still a finding.
- `packages/lint/src/static/speed-marks.test.ts`: two tests over constructed html blocks with the
  marks' markup (the plate's mask, the ASCII mark's rows), each with the control that must still
  fail. The lint package: 15 files, 109 tests passed, 1 skipped; `tsc --noEmit` exit 0. ESLint
  reports one `no-shadow` warning in `color.ts` at the `ref` of the html sources loop, which was
  there before this change (`git show ea5fec35:packages/lint/src/static/color.ts`, the same loop).
- No deck in the tree holds a mask or glyph art today (`grep -rl "<mask\|xml:space" decks`), so
  no current finding moves; B4b's import is the first reader. The step 15 reading on the imported
  template is B4's.
