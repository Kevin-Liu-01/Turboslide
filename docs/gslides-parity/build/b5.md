## 2. Decisions taken where the SPEC was silent, and deviations

1. **Where the draft is created.** SPEC 6.1 says the first write calls `deck.create` through
   `createStoredDeck`. That call sits in `writeDeckFn` (server/write.ts): a write with
   `baseRevision: 0` against an id of the draft shape that the store does not hold creates the
   deck, then applies the write. The editor needs no draft flag for the save itself; the id shape
   keeps every other missing deck a 404, and a base above 0 names a deck that once existed.
2. **How `/new` renders the editor.** `EditorRoot` lives in `edit.$deckId.tsx` (the integrator's
   file) and is not exported at this writing. `new.tsx` reads it from the module namespace behind a
   typed optional (`(editRoute as { EditorRoot?: ... }).EditorRoot`) so the tree typechecks today
   and the page renders the editor the moment the export lands; until then `/new` shows the
   pending page (title, one sentence, a link to /decks). Request 1 below turns this into a plain
   import. I chose this over a direct import because a direct import breaks `tsc -b` for every
   builder until the integrator acts.
3. **The address change.** `history.replaceState(window.history.state, '', '/edit/<id>')` from
   `/new`, on the `turboslide:deck-created` event the `writeDeck` client wrapper raises when a
   result carries `created: true`; the router's own state object is kept so Back still works, and
   a later search toggle from the draft page navigates to `/edit/$deckId` explicitly.
4. **The auto-title lives in the editor's commit, not on the server.** A second `deck.set /title`
   appended server side would leave the local document's title stale and its undo entry short of
   the rename (one Cmd+Z would not remove both, SPEC 6.3). `autoTitleMutations` is therefore a pure
   helper the commit appends before applying locally and sending (request 1). It reads the title
   word from `TITLE_ROW.untitled` (the chrome's strings) rather than the store's
   `DEFAULT_BLANK_TITLE` because the store's templates module reaches `node:fs` at its top and the
   helper is client reachable.
5. **Node imports in createServerFn modules.** The Start plugin strips handler bodies from the
   client transform but keeps plain functions and route-level imports: a `cardOf` reading
   `deck.json` with `node:fs` in decks.ts and a `DEFAULT_BLANK_TITLE` import in new.tsx both broke
   hydration of every page (measured: "Module node:fs has been externalized ... Cannot access
   node:fs.existsSync in client code" on /decks). The manifest read moved to `root.ts`
   `deckCardFacts` (server only, handler referenced) and the title word comes from the chrome.
6. **The card menu** has Open, Open in new tab, Present, Rename, Make a copy, Download, Move to
   trash: SPEC 6.2's five plus the Present and Download the round brief names (the bundle
   download stays reachable, the presentation opens in a new tab as the old row's Present did).
7. **Recent** records opens made from the home page (`recordDeckOpened`); a direct visit to
   `/edit/<id>` is not recorded until the editor calls it (request 1c).
8. **The GT brand deck card** creates `gt-brand-<base36 stamp>` titled "GT brand deck" so the card
   works more than once (the slug of the title is taken after the first copy).
9. **The layout dropdown of print** is a native `<select>` with the two Now options and five
   disabled handout options; the stub sentence sits in the control's tooltip, since an `<option>`
   carries none. The parity audit checks menu items, not selects.
10. **`getDeck`'s default theme** is the deck's appearance (SPEC 7.2.3) rather than `dark`.
11. **The old landing spec's three behaviours** (`/` opening the newest deck, the /decks New deck
    form, the Export menu's PPTX download) encode what SPEC 6.1, 6.2 and 6.7 replace; the spec is
    rewritten. The old deck-transfer test "the editor offers Download deck bundle and Presentation
    opens present mode in a new tab" drove `export.open`, `export.bundle` and `present.open`, which
    B3's shell replaced; it now drives File > Download > Turboslide bundle (.zip) and leaves the
    Slideshow button to B6's present.spec.ts.

### What landed

- A sweep of the derived files, hosted only (`root.ts`, the section "Room on the temp volume").
  `sweepDerived(target, options)` is pure over two folders, `<state>` and `<state>/worker`, and
  knows the four layouts the studio writes: `worker/jobs/<id>` (finished when `job.json` exists,
  which the queue writes last; a folder without one is running and is never touched),
  `worker/cache/<deck>/<revision>`, `thumbs/<deck>/<revision>` and `worker/builds/<deck>/<file>`.
  It removes what nothing can ask for again: finished jobs and builds older than the download
  window (`DERIVED_KEEP_MS`, the `TOKEN_TTL_MS` of `tokens.ts`, 15 min: a download token and the
  tmp backend's `?job=&file=` URL live that long) and every revision folder but the deck's newest
  (a render always runs at the deck's current revision). Then it evicts the rest oldest first
  until the derived files fit `budgetBytes`. Nothing younger than `graceMs` (60 s) is evicted,
  because a job in flight may still read it. Emptied deck folders go with their last entry.
  `decks/` and `packages/` are never touched: on the tmp backend they are the store itself.
- The schedule (`sweepDerivedIfDue`, called by `ensureDecks`, which every hosted render, export,
  build, thumbnail, list and open passes through): the routine sweep every 30 s
  (`DERIVED_SWEEP_INTERVAL_MS`) with a 160 MB budget (`DERIVED_BUDGET_BYTES`: the volume is 525 MB,
  the browser 205 MB, the seed and packages 43 MB); when `statfs` reports under 128 MB free
  (`DERIVED_LOW_WATER_BYTES`) the budget is 32 MB (`DERIVED_PRESSURE_BUDGET_BYTES`, the newest few
  megabytes, which are the open deck's thumbnails). One sweep at a time per process; the clock
  lives on `globalThis` like the runtime, so a dev server reload keeps it. A sweep that removed
  anything, and every pressure sweep, logs one line: `turboslide hosting: sweep (routine|low-water|disk-full): removed N entries, X MB (jobs a, cache b, thumbs c, builds d); kept M entries, Y MB; Z MB free`.
- The retry (`retryWhenDiskFull`, pure; `withDiskRoom` binds it to this process's folders):
  `ensureDecks`, `listStoredDecks`, `hasStoredDeck`, `openDeckStore`, `ensureDeckAssets` and
  `storedAssetFile` run once more after an ENOSPC and a sweep with a 10 s grace
  (`DISK_FULL_GRACE_MS`); `createStoredDeck` sweeps and does not run twice (a half-made folder
  would make the second attempt a 400). A second ENOSPC is a `DiskFullError` with `status: 503`,
  `code: 'disk_full'`, `retryAfterSeconds: 5` and a message that names what failed and says to
  retry in a few seconds; `isDiskFull` is false for it, so a nested wrapper does not sweep twice.
  In a checkout `withDiskRoom` runs the function as it is.
- `ensurePackages` and `exportBlobClient` forget a rejected promise, so a materialization that
  met ENOSPC is tried again by the next request instead of failing every request for the life of
  the instance.
- `docs/hosting.md` documents the rules, the constants, the log line and the one gap (the Docker
  worker's folder).
