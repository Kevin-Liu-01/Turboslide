## 6. The requests protocol

- A change a lane needs in a file it does not own is a request in `docs/gslides-parity/focus/build/<key>.md` under a heading "Requests", numbered `R1`, `R2` and so on, each naming the file and the line or construct, the exact change (a diff or the sentence to write), why (the rank or the matrix row it serves), and who owns the file. The integrator applies it at the next merge or reassigns it, and records the answer in this file and in `BUILD-STATUS.md`.
- The owner of a file may apply a request that lands in their own file directly and record it in their note; the requester never edits the file.
- A request that changes a shared type (`MenuContext`, `EditorShellInput`, a schema type, an action's input) names every reader it affects; the integrator applies such a request at a merge and runs `tsc -b` and the package suites before the lanes continue.
- Nothing is committed until the ship step. Every note carries the commands run and their results; a step a probe cannot drive is "not driven", never "passed".
- Durable notes live under `docs/gslides-parity/focus/build/`; the session scratchpad is wiped at the date change.
