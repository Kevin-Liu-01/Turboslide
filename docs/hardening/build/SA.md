## HR-SA#2a: the browser that asked

Closes AUTH-4's first half. The magic link and the six digit code sign in only the browser that asked for the mail; another browser is asked for the code the asking browser shows.

- `apps/studio/src/server/auth/signin-binding.ts` (new): one better-auth plugin. Its after hook on the two mail requests sets `ts.signin_browser` (`__Host-` when hosted; HttpOnly, SameSite=Lax, 300 s; at most three entries, each an expiry and an HMAC of the address under the library's secret) and adds `pair` (eight characters, an HMAC of the link's token) to the magic link request's answer. Its before hook on `/magic-link/verify` reads the link's verification row (not consumed) and, when the cookie does not name that address, redirects to `/signin?confirm=<token>&next=<path>` (or answers 403 `OTHER_BROWSER` without a return address); on `/sign-in/email-otp` it answers 403 `OTHER_BROWSER` before the code is tried, so the refusal spends no attempt. `POST /api/auth/sign-in/pair` takes the token and the code and sets the cookie for the link's address, ten tries per ten minutes on the library's limiter.
- `better-auth.ts`: the plugin before the TanStack Start cookie plugin, and `notePairCode(ctx, token)` in `sendMagicLink`.
- The plate (`packages/chrome/src/auth/`): the sent step shows the code under "If you open the link in another browser, enter this code there."; a confirm step ("Confirm this browser") with the code field, Sign In Here and Start Again; `/signin` reads `confirm`; the page actions' `confirmBrowser` posts the code and opens the link again. The editor's window shows the code too (its request answers the same body), with no change to `EditorRoot.tsx`.
- The studio tests that sign in through the library carry the asking browser's cookie to the code (identity, actions, identity-d1, room, record-statements, token-at-rest). `record-statements.test.ts` now records the pair path: the link in the asking browser, the link in another browser (no session), the pair, the link again.
