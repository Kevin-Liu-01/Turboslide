A driver rule learned in the first spec run: the root `playwright.config.ts` sets no
`actionTimeout`, so a locator call whose result is swallowed by a `.catch()` (a snackbar's Undo
button that never comes, a parked menu row) waits for the whole test timeout and the row reads as
a timeout instead of a verdict. Every such call in this round's tests carries `{ timeout: 3000 }`
(5000 for a click with a fallback) and a parked row is reached by a visibility check, never by
`menuPath` alone.
