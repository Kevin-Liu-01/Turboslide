- **The band loader** (`live/index.ts`, 6.3 "The band loader"), in the same hunk, as landed (11:45 PDT, after v1.md "Added at 11:40"):

  ```ts
  export type BandModule = { start(ctx: LiveContext): void };
  /** a band may have several entries, imported together and started in the order registered */
  export function registerBand(band: BandId, load: () => Promise<BandModule>): void;
  ```

  The core observes each `[data-reserve="<band>"]` at `rootMargin: '200% 0px'`. When the band nears it imports, together, the band's markup module (`FILL_MODULES` in `index.ts`: `bands/<band>.generated.ts`, V1's, each `FILLS`) and the band's entries; writes each empty `[data-fill="<key>"]` inside the box from `FILLS[key]` (a placeholder that already holds an element is kept); records the slides as the build wrote them (for `cloneSlide`); draws the deck's state on them (`paintSlides`); sets `data-filled`; then starts each entry with `ctx.reserve` set to the box. A failing import or entry is caught and logged; the others start. A band with entries and no reserved box starts at once (the first pass's markup in the document). `LiveContext` gains `reserve: HTMLElement | null`. V1's `BandModule.fills` (v1.md "Added at 11:40") is the same mechanism held in the core's table instead of each entry, so an entry of the core (`startMark`, `startSeam`) needs no chunk of its own; V4 adds `people` and `patterns` to `FILL_MODULES` beside its `registerBand` lines.
- **`cloneSlide(key, state, instance)` and `registerDeckSlides(markup)`** (`live/index.ts`): a fresh root of any slide as the build wrote it (a slide a menu row added included, its objects renamed to its key), for a band that draws a slide no band inserted yet; the caller places it and draws the state with `paintSlide`. A clone of a slide already drawn on the page would carry that slide's freed places as if they were its rest, so every swap of a shown slide (the hero frame's filmstrip, the miniature's, Tailor's stage) clones through it. `registerDeckSlides(HOME_SLIDE_MARKUP)` is called by each chunk that imports `bands/deck.generated.ts`.
- **`paintSlides(container, state)`** (exported from `live/index.ts`): draws the page deck's state on every `[data-home-slides]` under `container`: the kit and the typed background, the customer's name, the counters and the skipped mark, the moved, resized, turned and typed objects, the styled, inserted and deleted blocks. V3's show and print clones and V4's people screens call it on markup they insert themselves, so every slide on the page draws one deck (LANDING.md 1.2 item 3).
- **Exports kept:** `applyKit`, `applyCustomer`, `customerText`, `renumber`, `markCustomer`, `tailorPlaces`; added: `snapshot()` on the store (6.3 "Exports across lanes").
