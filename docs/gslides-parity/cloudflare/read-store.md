The question this note answers: what the Blob backed store does against Vercel Blob today, which of those calls are on the hot paths, what a Cloudflare R2 backend has to provide to take its place without changing the store above the client, how large the store is and how it would move. The one sentence answer: the store already speaks to Vercel Blob through a six method interface whose every semantic (an etag that is the body's md5, a put refused when the name exists, a put conditional on the etag read, a prefix listing with upload times, a batch delete) R2's S3 API provides, so the backend is one new client module beside `blob-vercel.ts`; the four round write and its proofs stay as they are, most of the machinery built against Blob's CDN lag and listing lag becomes unnecessary because R2 reads are strongly consistent, the store fits the R2 free tier at seller traffic and costs about $15 a month at the pipeline's September volume, and the two things that need a decision are how browsers read the public files (a Worker on `workers.dev` or a custom domain on a Cloudflare zone, and `turboslide.com` is not one) and R2's one write per second per key limit, which the checkpointer's loop can exceed.

### 1.4 What exists because of Vercel Blob's two lags

Two measured facts shaped half of `blob-store.ts` (1239 to 1258): `list()` lags `head()` by up to a minute, and the public URL serves an overwritten body stale (the SDK's `useCache: false` bypasses the CDN for private stores alone, `blob-vercel.ts` 166 to 169). The work built against them: the snapshot as the proof of the current document (1316 to 1327; `docs/hosting.md` 266 to 294); the pull that walks records by number and never lists (1299 to 1303, 1340 to 1380); the manifest naming the bodies a pull proves (519 to 536); `StaleMirrorError` when nothing proves (452 to 459, 1796); the fresh deck index (684 to 702, 758 to 794) and the phantom folder memory (682, 2584) around the lagging folder listing; the removal by name (2890 to 2898); the `version` wait loop in `get` (`blob-vercel.ts` 165 to 194); the record read through `head` before its URL (1274 to 1283); `provenGet` with the immutable copy and the cache busting fetch (`access-store.ts` 18 to 21, 332 to 350, 382 to 420), which the leases (1599 to 1610), the access record, the indexes and the comments sidecar (`comments-store.ts` 343, 372, 377) read through; the presence record's copies (`presence-store.ts` 110 to 112), 4,149 objects and 29.8 MiB of the store on 2026-09-20 (`docs/HOSTING-MOVE.md` 31). On a store whose reads and listings are strongly consistent every one of these is a no-op that costs calls (the copies cost a put each) and none is wrong, so an R2 client can run under them unchanged on day one and a later cut can retire them.

## 3. What an R2 implementation needs

### 3.1 The way in

Two APIs reach a bucket. The S3 compatible API at `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` with an R2 API token, which yields an Access Key ID and a Secret Access Key shown once, scoped to "Object Read & Write" on a set of buckets (https://developers.cloudflare.com/r2/api/tokens/, read 2026-10-01: account tokens and user tokens; "Object Read & Write" grants "read, write, and list objects in specific buckets"; "You will not be able to access your Secret Access Key again after this step"). And the Workers binding (https://developers.cloudflare.com/r2/api/workers/workers-api-reference/, read 2026-10-01): `head`, `get`, `put`, `delete` ("up to 1000 keys may be deleted per call"), `list` (`prefix`, `delimiter`, `limit` "Defaults to 1000, with a maximum of 1000", `cursor`, `delimitedPrefixes` in the result), `put` and `get` with `onlyIf` (`etagMatches`, `etagDoesNotMatch`, `uploadedBefore`, `uploadedAfter`; "In the event that a precondition specified in options fails, put() returns null"), `httpMetadata` with `contentType` and `cacheControl`. The app's functions stay on Vercel in this design round, so the store's client is an S3 client in the Vercel function with the key pair in the environment; the binding is for a Worker that serves the public files (3.4) and for a Durable Object if that lands later (`research-options.md` 5b). The S3 client must issue a single `PutObject` per body and never a multipart helper: a single part put goes to 4.995 GiB (https://developers.cloudflare.com/r2/platform/limits/, read 2026-10-01) and the largest object the store holds is a 64 MB bundle (`docs/HOSTING-MOVE.md` 39), while a multipart object's etag is not the body's md5 (https://developers.cloudflare.com/r2/objects/multipart-objects/, read 2026-10-01: "The ETag of the completed multipart object is the hash of the concatenated binary MD5 sums of all parts, followed by a hyphen and the number of parts").

### 3.3 The one write per second per key limit

The R2 limits page (https://developers.cloudflare.com/r2/platform/limits/, read 2026-10-01): "Maximum concurrent writes to the same object name (key) | 1 per second" and "Concurrent writes to the same object name (key) at a higher rate return HTTP 429 (rate limited) responses." Vercel Blob has no such rule, so this is the one place the store's shape meets a new constraint. The keys written more than once a second today:

- `decks/<id>/deck.json`: once per commit (1884). On the blob tier a POST per edit at the client's 1,000 ms spacing keeps one instance at or under one write a second per deck; two instances committing the same deck inside one second give the second a 429 where today it gets a precondition failure or a commit. The 429 reads as "not now" (`isStoreBusy`), the route answers 503 with `retry-after` and the room client resends (`docs/hosting.md` 203 to 206; `room-client.ts` 1241 to 1257 as `docs/HOSTING-MOVE.md` 120 reads them), so the edit is kept and the outcome is a slower merge, not a lost write. On the redis tier the checkpointer commits one record per author per run back to back (`checkpoint.ts` HEAD 249, 196), so a run with two authors writes `deck.json` twice inside a second and the second put answers 429; the R2 client should retry a put that answered 429 once after one second (inside the 20 s document deadline, `blob-store.ts` 800), or the checkpointer spaces its records a second apart, and the synthesizer picks one.
- `decks/<id>/.turboslide/pulse.json`: after every commit, presence push and comments push from every instance (`blob-store.ts` 1940, 2668, 2805, 2851; `pulse.ts` 151 to 167). `putPulse` is best effort and swallows a failed put (164 to 166), and the safety tick heads the manifest every fifteenth tick (`pulse.ts` 38), so a 429 here delays a poller by at most that tick on the blob tier and matters not at all on the redis tier, which does not poll.
- `decks/<id>/.turboslide/presence.json`: at most every 5 s per deck per instance (`presence-store.ts` HEAD 76); two instances can collide inside a second, and a lost race is already `null` from `putRecord` (255 to 273).
- `index/fresh-decks.json`, `templates/index.json`, `system/logo-index.json`: on a create, a template save, a logo refresh; rare.

The other limit on that page that the store touches: "Maximum rate of bucket management operations per bucket | 50 per second", which the page's footnote says includes listing and does not apply to reading or writing objects; the listing makes one `folders` call per home page load and the prunes one `list` each, far under it.

### 3.4 The public reads

The rule that stands: a document is never readable by URL (`docs/hosting.md` 907 to 915, layout v2; `docs/security.md` 280), and a twin, a thumbnail, an export, a bundle, a build and an avatar are read by a browser from a URL (section 1.3). R2 gives three ways to serve the public set, and `turboslide.com` decides against one of them.

1. `r2.dev`. "Public access through r2.dev subdomains is rate-limited and should only be used for development purposes" and "To enable access management, cache, and bot management features, you must set up a custom domain" (https://developers.cloudflare.com/r2/buckets/public-buckets/, read 2026-10-01). Not for production.
2. A custom domain on the public bucket. "The domain being used must have been added as a zone in the same account as the R2 bucket" (the same page). `turboslide.com`'s nameservers are `dns1.registrar-servers.com` and `dns2.registrar-servers.com` and `www` is a CNAME into `vercel-dns-016.com` (`dig`, 2026-10-01), so it is not a Cloudflare zone and nobody in this round moves it; `generaltranslation.com` is on the same registrar nameservers (`dig`, 2026-10-01; `docs/HOSTING-MOVE.md` 47). `gtx.dev` is on Cloudflare nameservers (`summer.ns.cloudflare.com`, `felicity.ns.cloudflare.com`, `dig` 2026-10-01) and the General Translation edge Worker serves `https://cache.gtx.dev` (`/Users/kevinliu/gt/gt-cloud/apps/edge/README.md` line 7; the Worker is `gt-edge`, `apps/edge/wrangler.toml` lines 1 and 82). So a custom domain such as `<name>.gtx.dev` exists for the bucket only when the bucket lives in the Cloudflare account that holds that zone, which is the GT account's, and which account hosts Turboslide's bucket is Kevin's call (section 5). Reads through a custom domain go through Cloudflare's cache: "By default, only certain file types are cached" and the consistency page says a cached 404 and an overwritten object are served stale until the cache TTL expires. That is right for the digest named twins, thumbnails and avatars and wrong for anything overwritten, which is why the documents stay off every public path.
3. A Worker on its `workers.dev` hostname with the bucket bound, serving the public prefixes alone (`decks/<id>/assets/`, `.thumbs/`, `exports/`, `bundles/`, `builds/`, `u/`), setting `Cache-Control` from the object's `httpMetadata`, `Content-Disposition: attachment` when the query carries `download=1` (the Vercel Blob behaviour `export-jobs.ts` 367 to 370 relies on), `X-Content-Type-Options: nosniff` and `Cross-Origin-Resource-Policy` as the assets route does (`headers.ts` 77 to 95), and refusing every other prefix. Workers Free is "100,000 per day" requests and "10 milliseconds of CPU time per invocation" (https://developers.cloudflare.com/workers/platform/pricing/, read 2026-10-01); a passthrough of bytes from the binding is well under 10 ms of CPU; the limits page adds 128 MB of memory, 50 subrequests per request on the free plan and no wall clock limit on an HTTP request (https://developers.cloudflare.com/workers/platform/limits/, read 2026-10-01). No zone is needed, so this is the path that holds without a DNS decision, and it holds one bucket private with no second bucket. The fact that would force Workers Paid ($5 a month, 10 million requests): a gate day of the pipeline on a hosted preview, whose tabs read twins and thumbnails by the hundred thousand (`research-costs-actual.md` 32: 1.52 M CDN hits and 6.19 M misses on the personal project since 2026-09-01, most of them the gates); cut 1 of that note keeps the whole matrix on the local tier, and at seller traffic (18 production requests in three quiet hours, the same line) the free plan is not approached.

Either way `TURBOSLIDE_PUBLIC_STORE_HOST` becomes the Worker's or the custom domain's host, and the CSP (`headers.ts` 220 to 236), the avatar base (`avatar-tier.ts` 28) and the computed `BlobEntry.url` follow from the one variable. Two paths that read `.thumbs/` as a document under layout v2 need one decision: `migrate.ts` 81 to 86 (`isPublicPath`) leaves `.thumbs/` with the documents and `thumbs.ts` 300 to 311 then streams bodies instead of answering 302; for R2 the thumbnails are digest named and belong with the public set.

### 3.5 The Vercel side

The functions run in `iad1` (`docs/HOSTING-MOVE.md` 18). A bucket takes a location hint once, at creation: `enam` is "Eastern North America", and without a hint "the data location is set to Automatic by default", chosen near the caller that creates the bucket (https://developers.cloudflare.com/r2/reference/data-location/, read 2026-10-01); the bucket is created with `enam` from wherever the orchestrator runs. The per call latency from `iad1` to R2 is unmeasured (section 5); a commit is three sequential rounds plus the pulse (1.3), so the difference against the same region Blob store multiplies by four or five per edit on the blob tier and per checkpoint on the redis tier. Vercel's networking page names Fast Data Transfer as "Data sent between the CDN and the visitor's device" and Fast Origin Transfer as "Data sent between the CDN and Vercel Functions", "incurred on both the input and output data transfer when using compute or blob on Vercel", and lists no line for a function's own outbound fetch to another service (https://vercel.com/docs/pricing/networking, served as "CDN pricing and usage", last updated 2026-09-14, read 2026-10-01); the function's wait on R2 is paid as its GB hours.

### 3.6 The cost

R2 prices (https://developers.cloudflare.com/r2/pricing/, the page's last updated date 2026-10-01, read the same day): the free tier is "10 GB-month / month" of storage, "1 million requests / month" of Class A, "10 million requests / month" of Class B, egress "Free"; beyond it "$0.015 / GB-month", "$4.50 / million requests" Class A, "$0.36 / million requests" Class B. Class A is "ListBuckets, PutBucket, ListObjects, PutObject, CopyObject, CompleteMultipartUpload, CreateMultipartUpload, ..."; Class B is "HeadBucket, HeadObject, GetObject, ..."; `DeleteObject` is in neither list the page gives. "Egressing directly from R2 ... does not incur data transfer (egress) charges and is free." R2 is enabled by "Complete the checkout flow to add an R2 subscription to your account" and "R2 is free to get started with included free monthly usage" (https://developers.cloudflare.com/r2/get-started/, read 2026-10-01); whether the checkout wants a payment method is not stated on that page.

Against Vercel Blob's prices as `docs/SYNC.md` 195 recorded them on 2026-09-20 (simple $0.40 per million, advanced $5.00 per million, transfer $0.05 per GB, storage $0.023 per GB month, `del` free), the mapping is one to one: a simple operation is a Class B one, an advanced one is a Class A one, and the egress line goes.

- The store today: 17,201 objects and 1.266 GiB on 2026-09-20 (`docs/HOSTING-MOVE.md` 26), under the 10 GB-month free storage, $0.
- The pipeline's September: the store made 41.70 M simple and 1.88 M advanced operations and served 167 GB from 2026-09-01 to 10-01 (`research-costs-actual.md` 9). On R2 that is (41.7 minus 10) times $0.36, $11.41, plus (1.88 minus 1) times $4.50, $3.96, plus $0 of egress and $0 of storage: about $15.4 a month, against about $17 of simple operations, $9 of advanced ones and $8 of transfer on Vercel by the same note (9 and 44), about $34.
- A quiet day: 0.69 to 0.77 M simple and 0.01 to 0.02 M advanced operations on 09-27 and 09-28 (`research-costs-actual.md` 26 to 27), which over thirty days is 21 to 23 M Class B, $4.0 to $4.7 a month on R2, and Class A inside the free million. Those days still carried the guard's checks.
- Sellers alone: production logged 18 requests in three quiet hours (`research-costs-actual.md` 32); the store stays inside the free tier at that traffic.

So the store on R2 is free once the pipeline's gates leave hosted previews (cut 1 of `research-costs-actual.md`), about $4 to $5 a month at the quiet day rate with the guard's checks, and about $15 at September's gate volume. No R2 fact forces the Workers Paid plan; the public read Worker (3.4) is the only Cloudflare line that could, and only under hosted gates.

### 4.2 The copy

Cloudflare's own tools do not read Vercel Blob. Super Slurper's sources are "Amazon S3, Cloudflare R2, Google Cloud Storage (GCS), All S3-compatible storage providers" with S3 style credentials (https://developers.cloudflare.com/r2/data-migration/super-slurper/, read 2026-10-01), and Sippy fills a bucket from the same kinds of source as objects are requested (https://developers.cloudflare.com/r2/data-migration/, read 2026-10-01); Vercel Blob's API is its own SDK (`@vercel/blob`), not S3. So the copy is the application's, and the tree holds two shapes of it:

- `scripts/blob-copy.mjs` (lines 1 to 38 describe it): lists the source in pages of 1,000, heads the target to skip what is there with the source's etag, reads each body with `useCache: false`, puts it under the same pathname with `allowOverwrite: false`, the same content type and `cacheControlMaxAge`, compares the returned etag and falls back to an md5 of the bytes read back; eight in flight; `--skip exports-older-than=1d,turboslide-sidecars`; `--verify` and `--delta` passes with a state file. Written for a Blob to Blob copy with two tokens, tested against two in memory fakes alone and never run against a real store (`docs/HOSTING-MOVE.md` 113 to 122). Its target `put` becomes an R2 client's and the rest stands.
- `runMigrationStep` (`migrate.ts` 309 to 435) with `legacy` the Vercel client and `documents` an R2 client: `plan` lists the deck folders, `copy` puts every document the target lacks with `overwrite: false` and compares the etags (255 to 273), `verify` heads every document and compares snapshots byte for byte (280 to 303), `cutover` flips the layout, `delete` removes the public copies in batches of 50, `rollback` turns the reads back before the cutover; every step resumable from `meta.json`; `splitBlobClient` gives the dual read window while it runs. It routes documents alone (`isPublicPath`, 81 to 86; the deviation its header records at 14 to 15), so the twins, exports, bundles, builds and avatars take a second pass of the copy script's shape.

The etag comparison both rely on (`migrate.ts` 266 and 284; the copy script's step 5) holds across the two stores exactly when R2's single part etag is the body's md5, which 3.2 measures on day 0. The volume after the skip set is about 12,000 objects and 1.0 GiB, about eight minutes at eight in flight and about 0.3 s per object, eleven for the whole store (`docs/HOSTING-MOVE.md` 117 to 118). The cost: on the Vercel side 1.0 to 1.27 GB of transfer at $0.05 per GB and about 12,000 to 17,000 simple operations, under $0.15; on the R2 side 12,000 to 17,000 Class A puts, inside the free million. The store moves while it is copied (`docs/HOSTING-MOVE.md` 39 to 40), and two deployments read it (www.turboslide.com and turboslide.vercel.app, both from `main`), so the cutover is one of: the dual read window of `splitBlobClient` with both deployments carrying the R2 variables, or a freeze of the writes while the delta pass runs, which `docs/HOSTING-MOVE.md` 2.2 and 3 (83 to 91, 120) worked out for the Vercel to Vercel case, WAF redirect included.
