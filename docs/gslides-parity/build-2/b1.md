## Decisions

- A connector end off its site is a severity 2 validator note (`connect`), not a refusal: the
  document stays loadable after a hand edit and `line set` with `connect` moves the end back. A
  missing target, a line target and a site out of range are refused at severity 3.
- `padding` and `valign` without `pos` are refused on shape and text only; a box keeps the round
  one flow padding.
- `rect` has four connection sites in the standard's `cxnLst`; a box, picture, chart, table or
  text box target offers the eight sites of a rectangle (`rectSites`, the side midpoints then
  the corners), as SPEC-2 2.4.7 states. Until the interpreter lands every preset answers eight.
- The Inter italic source's name table reads "Version 4.000;git-a52131595" while the upright reads
  4.001; both come from the rsms/inter 4.001 release zip. `fonts.json` records the italic file's
  sha256 `0470791f15efd2987bdb50b24027c3f584a2cf9b7b63fbf86012c5f2e9abcc05`, 380904 bytes,
  italic angle -9.4.
- `block insert --pos` without `--after` lands the object last in `main` with z one above the
  highest, as Insert does in Google Slides; the first run of the walk put it first.
- A rotation about the selection writes half pixel coordinates; the first run of the walk wrote
  `166.79435682761346`.
- `block autofit none` writes `autofit: 'none'` (Do not autofit is a state in `AUTOFITS`).
- `slide.setLayout` to freeform on a slide that is a canvas already writes nothing; before this
  the freeform to freeform switch went through `convertLayout`, which re-sorted the objects by
  geometry.
- The `diagram` fixture slide is written by hand in the shape `diagram.insert` produces (rounded
  rectangles, text boxes and attached arrow lines in one group) because
  `packages/schema/src/diagrams.ts` is B5's and not in the tree yet.
- The asset `fixture-photo` has role `other` with `source.kind: 'file'`; role `mood` with a file
  source is an `asset/license-missing` finding.
- The GT opener's slide order: `slide to-canvas a,b,c` reports rows in deck order, whatever the
  order of the ids.

## The cost of one canvas write

Measured on this machine (Apple silicon, Chromium through playwright-core), wall time of the
whole CLI process, `--json`, from `scratchpad/walk/out/timing.tsv`:

| Command                                                                                    | Wall time      |
| ------------------------------------------------------------------------------------------ | -------------- |
| A plain write (`deck guides`, `text style`, `shape set`, `block rotate` on a canvas slide) | 0.64 to 0.75 s |
| `slide to-canvas <one id>`                                                                 | 1.35 to 1.59 s |
| `block set <grammar slide>#<block> /pos` (converts and moves)                              | 1.37 s         |
| `slide set-layout <grammar slide> --type freeform`                                         | 1.39 s         |
| `block insert <grammar slide> --slot main --pos`                                           | 1.42 s         |
| `block autofit <text box> shrink --apply`                                                  | 1.44 s         |
| `slide to-canvas` with six ids of the GT deck (one browser, one page)                      | 1.65 s         |

So the measurement costs about 0.7 to 0.9 s per action call on the CLI (launch, one render, one
page), and about 0.05 s per additional slide in the same call. The MCP stdio server binds the same
`headlessCanvasMeasurer` and pays the same cost per tool call; the studio binds the render worker
facade (B4).

### Finding 7 (severity 2): Align > Bottom with one object lands the bottom edge at 904

- Cause. `alignPositions` (`packages/schema/src/freeform.ts`) snapped the reference line for every
  reference when `snap` was on, and `block.align` turns snap on unless `snap: false` (the CLI's
  `--no-snap`). With the sheet as the reference the bottom line is 900; no GT guide lies within 6
  px of it (the bottom rule is 844, the content bottom 771), so `snapCoordinate` fell to the grid
  and `Math.round(900 / 8) * 8` is 904. The other five sheet lines are on the grid (0, 800, 1600, 0)
  or on a guide (450 is the content middle), which is why only Bottom missed.
- Fix. The snap applies to the selection's union only: the sheet's and the content box's edges and
  centres are lines themselves and stay exact, and a selection snap whose result would leave the
  sheet keeps the exact line (a block sitting on the sheet's bottom edge, aligned bottom with
  others, no longer carries the set 4 px off the sheet). `resolveAlignTarget` is the one place the
  default reference is decided (`'sheet'` for one block, `'selection'` for several); `alignReference`
  and `alignPositions` both read it. `store-actions.ts` is unchanged: the arithmetic is the schema's,
  and B4's `alignMutations` (`packages/viewer/src/Freeform.tsx`) calls the same function with snap
  on, so the editor's Arrange > Align and the CLI, MCP and window `block.align` agree with no change
  on B4's side (its 18 freeform tests pass unchanged).
- Design note, not a deviation. Google's Align has no snap at all (R05 C2); the round one choice to
  snap the selection's shared edge to the GT lines is kept as it was, only narrowed to the one
  reference whose line is an arbitrary number. Dropping the snap altogether would be a Google parity
  change for Kevin to call.
- Files. `packages/schema/src/freeform.ts` (`resolveAlignTarget`, `alignReference`,
  `alignPositions`), `packages/schema/src/freeform.test.ts` (one new case: the six sheet lines exact
  under snap for one block, `to: 'sheet'` and `to: 'content'` exact for several, a selection edge
  at 900 kept, a selection edge at 300 still snapping to 304), `packages/schema/src/actions.ts`
  (`block.align` doc and the `snap` description), `apps/cli/src/commands/freeform.test.ts` (one new
  test: `block align free --blocks ic --edge bottom|right|middle` lands on 868, 1568 and 434 with no
  `freeform/off-sheet` finding), and the regenerated contracts (`packages/agent/generated/{cli,
mcp-tools,describe,openapi}.json`, `llms-full.txt`, `skills/turboslide-studio/references/browser-api.md`).
