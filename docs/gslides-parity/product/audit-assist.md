# Audit: AI assist for sellers on an agent native editor

Written 2026-09-19 (the run at 18:28 Pacific) by the auditor of the area "AI assist for sellers on an agent native editor" for the product round. Production is https://turboslide.vercel.app serving `main` at 6e15d60. One scratch deck (`untitled-20260920-f4aa`) was made from `/new`, driven through the product's own controls with headless Chromium 1440 by 900 at human speed (playwright-core 1.62.1 from the repository root, Node 24), then moved to the trash through File > Move to trash, deleted forever on `/decks/trash`, and read back as 404 on `/edit/<id>` and `/deck/<id>`. The walk took 93 s over 42 rows (15 ok, 4 failed, 23 recorded readings); the four failures are named in the method section, and one of them is my own setup misfire. The agent surface was read with the production bearer from `~/.config/turboslide/hosts.json`; the token appears in no file under this folder.

Evidence is under `docs/gslides-parity/product/audit-assist/`: `walk.json` (every row and the facts read from the DOM and `window.turboslide.studio`), `agent-surface.json` (the live manifest facts), the screenshots `01` to `10`, and `scripts/` (`assist-walk.mjs`, `agent-read.mjs`, `walk.log`, copied from the session scratchpad `product/assist/`). The scripts import nothing from the repository but playwright-core.

Copy rules: what happens today is a reading, with the file and line or the screenshot; the proposal names the behaviour, the words, the control and the file. Value is 1 to 5 for the seller and the marketer; effort is 1 to 5; the reference names the product and the behaviour compared with.

## Summary

### What a seller feels today

A seller opens a deck and finds no assistant anywhere. The title row holds the name, the save state, Last edit, the collaborators, the comments glyph, Slideshow and Share (`walk.json` row 2, `01-editor-title-row-no-assist.png`); the slot where Google puts Ask Gemini is omitted in the menu model with the reason "A Google service" (`packages/chrome/src/menus/model.ts` 850, `omit('title.gemini', ...)`). The only words for an assistant in the product are behind Tools > Advanced tools: Extensions > Agent access, a dialog of MCP and API addresses for a developer (`05-agent-access-dialog.png`), and Tools > Advanced > Run an action, a palette of 235 raw actions with their ids and doc strings (`06-run-an-action-palette.png`). The one suggestion surface a seller can reach, Tools > Check slides, showed the same sentence twice with a specification citation and no Fix (`04-check-slides-panel.png`).

Search the menus, the seller's way to ask "where is X", matches only the row's label, its menu path and Google's label (`packages/chrome/src/menus/finder.ts` 65). "rename the customer", "change the customer name", "bigger text", "talk track", "hide slide", "send a pdf", "translate", "agenda", "summarize" and "help me write" all answered "Nothing matches"; "logo" answered "Long dash dot" through the subsequence rule (`03-search-*.png`, rows 5 to 26).

Underneath, the product is ready for an assistant in a way Google Slides is not: 169 named actions, 141 of them on all four transports and 125 of them writes, 150 implemented on production (`agent-surface.json`); one write carries many mutations, a note and an author of kind `human` or `agent` (`packages/schema/src/mutations.ts` 247 to 259); the identity system already has an `agent` trust state with its own mark (`packages/identity/src/marks.ts` 105, `resolve.ts` 18); the snackbar takes one action, Undo (`packages/chrome/src/Snackbar.tsx` 12); the right panel frame is one component (`packages/chrome/src/Panel.tsx`). But when an agent wrote to the open deck over HTTP during the walk (`text.replaceAll`, Acme to Globex, author `agent:assist-probe`), the slide changed with no banner, no snackbar and no mark; the deck name in the title row kept "Acme" while the slide read "Globex" (`07-after-agent-write.png`); Cmd+Z did not take the change back and wrote revision 8 over the seller's own last edit instead (rows 33 to 35, `08-undo-after-agent-write.png`); Version history folded the write into the seller's window as "Cork 184, Agent · assist-probe · 9 changes" (`09-version-history-agent-row.png`). Nothing in the product today calls a model: no model dependency exists in any `package.json`, and the judge loop (`scripts/judge-loop.mjs`) runs on a developer's machine through the Claude Agent SDK or the `claude` CLI.

### The ten items this round should do first

The top ten rows of the table, in its order:

1. Make an assistant write one step of the seller's undo (row 1). Every assist write goes through the editor's own `commit(mutations, label)` on the window transport and the snackbar after it carries Undo.
2. The Assist entry point and panel (row 2): a title row button where Google puts Ask Gemini, a Tools > Assist row, the panel in the right slot with a prompt box at the bottom and suggestion cards above it.
3. The card anatomy (row 3): every capability shows a proposal first, the seller accepts or dismisses, an accepted proposal is one write and one undo step, and a "Written by the assistant" chip sits on the changed blocks until the seller edits them.
4. Rewrite a slide for a named prospect or a shorter reading (row 4).
5. The model route (row 5): one server function, `claude-opus-5` with adaptive thinking at low effort, structured output shaped by the action inputs, prompt caching, the budget, the quota rows and the privacy sentence.
6. Translate a slide or the deck through General Translation's own `POST /v2/translate` (row 6), the company's product inside its editor.
7. A visible arrival for every outside write, with Undo, and the deck name following the first title (row 7).
8. Search the menus that understands a seller's words, and an "Ask the assistant" row when nothing matches (row 8).
9. Draft an agenda or a closing from the deck's outline (row 9).
10. Speaker notes for a slide and a one pager from the deck (row 10).

Row 11 (rewrite and translate from the object's right click menu) costs little once rows 3 and 4 exist and should ride with them.

### What to leave

- A deck from a brief laid out on the brand layouts (row 14): valuable, but research 07 names a seller who tailors an existing deck far more often than she builds one, and the layout picker's own rows still hold slides behind the switch (`slides.layout.*` in README "Held until every row passes"). Ship it as an outline the seller reads and edits first, with slides made by `slide.new` and filled by `slide.update`, no pictures, after rows 1 to 10.
- Tidy this slide with rendered before and after thumbnails (row 13): it needs `render.slide` per proposal, which is the render worker's cost; measure the render path first.
- The brand kit for the assist (row 18): with the theme editing round (SPEC-5 section 9), because the kit's voice rules and the theme record belong together.
- Image generation (Google's Help me visualize, Canva's Magic Media): the GT grammar puts two tone pictures the designer chose on the sheet and research 07 names no seller task for it. Not this round, and perhaps not this product.
- Run an action (row 20) stays parked; the Assist is the seller's route to the same actions.
- Round five's chat panel is a human to human room, not an assistant; its frame (`packages/chrome/src/panels/Chat.tsx` on `round-five/integration`: the Panel, a `log` region, a composer with Enter to send, a first line that says what is not saved) is the nearest built frame for the Assist panel and is read here, never merged.

## What exists today

The facts an assist would build on, read from `main` at 6e15d60 and from production.

- The action table (`packages/schema/src/actions.ts`): 169 ids, 141 on all four transports (`transports: A`), 10 window only, 8 CLI only, 125 mutating. Every mutating action takes `baseRevision` and answers 409 with the current document on a stale one; an agent write to a slide another author holds is 409 with the holder unless `force` (the manifest's rules, `agent-surface.json`). Production answers `GET /api/agent` 200 with the bearer (150 implemented, 0 not implemented for this instance) and 401 without; `/llms.txt`, `/llms-full.txt` and `/openapi.json` answer 200 without a bearer; `POST /mcp` answers 401 without one.

The deck caps allow 200 mutations per write (`docs/security.md` section 4).
- The editor's controller commits `(mutations, label)` as one history entry (`apps/studio/src/editor/controller.tsx` 792, 1762); undo is per author (655) and typing groups within 400 ms (493). ## The proposal

### The interface

- Entry point. One button in the title row, between the presence chips and the comments glyph, where Google draws Ask Gemini: the label "Assist", the sparkle glyph from the theme sprite, the tooltip "Ask for a slide, a rewrite, a translation or a fix; nothing changes until you accept" and the key Cmd+J. The menu model gains `now('title.assist', 'Assist', panel('Assist'), { turboslide: true, when: 'write' })` in `TITLE_ROW_ITEMS` and a Tools > Assist row before Check slides; both join Search the menus through `isFinderItem`. No toolbar control this round: the toolbar is the formatting row.
- The panel. `panel('Assist')` in the right slot through `Panel.tsx`, title "Assist", the frame Chat.tsx built on the branch: the cards above, the prompt box at the bottom (a textarea, Enter sends, Shift Enter breaks a line, `data-control="panel.assist.prompt"`), the first line under the title in `ts-tt-note`: "Your slide text is sent to the assistant's model provider under General Translation's account to write these suggestions. Nothing is written to your slides until you accept." When the panel opens with a slide selected it shows five suggestion cards before any typing: Tailor for a prospect, Make it shorter, Translate, Write speaker notes, Add an agenda. The seller types anything else in the box.
- Cards. One card per proposal: a sentence in the seller's words ("Slide 1: Acme becomes Globex in two places"), the before and after text with the changed words marked, Accept, Dismiss, and "Change the ask". A proposal over several slides is one card with a row per slide and one Accept. Accept commits one write through the editor's `commit(mutations, label)` with the label "Assist: <sentence>", author `{ kind: 'agent', name: 'Assistant', runId }`, so Cmd+Z is the step back and Change history lists it once. The snackbar after Accept reads the sentence with Undo.
- The mark. Blocks the assistant wrote carry `ext.assist = { at, runId, card }` and the stage draws the selection chip word "Assistant" on them, with the agent mark, until the seller edits the block; Version history shows the assistant's revisions as their own rows with the agent mark and the name "Assistant", never folded into the seller's window.
- Where is X. A question in the prompt box that names no slide is answered from the menu model: the model receives `finderRows(ctx)` (id, title, path, doc) and answers with one row and the sentence "Skip slide is under Slide, or right click a card. Open it"; "Open it" runs the item's effect through `onRunItem`, exactly as Search the menus does. When Search the menus finds nothing, its empty state gains the row "Ask the assistant: <phrase>" that opens the panel with the phrase.
- The right click menu. Two object rows under the click model's rule 6: "Rewrite with the assistant" and "Translate this text", each opening the panel with the block selected and the card ready.

### The model route

- The server. One server function under `apps/studio/src/server/assist.ts` (`createServerFn`, as `agent-actions.ts`), `POST` only, `authorize()` first with the request's identity, the `readOnly` flag, a new `assist` kill switch beside `comments` in `flags.ts`, and the deck read through the deck dispatcher (`deck.info`, `slide.get`, `export.text`, `render.slide`). The model call uses the official Anthropic SDK from the server function, never from the page; the page never holds the provider key.
- The model. `claude-opus-5` through the Messages API with adaptive thinking (on by default) and `output_config.effort: 'low'` for rewrite, translate fit, agenda, notes and where is X, `'medium'` for the outline from a brief; `output_config.format` with a JSON schema derived from the action inputs of the card (block ids, slot names and layout ids enumerated from the deck, so an answer that names a block the slide does not have fails validation before it becomes a card); streaming to the panel so the card fills as the answer arrives. Translation goes to General Translation's `POST /v2/translate` first, and the model only writes the fit sentence and the fallback when a Text is markup the service cannot take.
- Caching. The system prompt (the grammar rules the create skill states, the card contracts, the brand kit's voice rules) carries `cache_control` and never changes within a deploy; the deck text is the second cached block within a session; the prompt and the selection come last. `usage.cache_read_input_tokens` is logged per call so a silent invalidator shows in the weekly numbers.
- Budget. 24,000 input tokens per call (the deck text is cut by whole slides from the end with the sentence "The assistant read the first N slides" on the card) and 4,000 output tokens. At $5 and $25 per million tokens that is $0.22 per call at the caps; a 20 slide deck with 6,000 tokens of text, a 3,000 token prompt and an 800 token answer costs about $0.065 uncached and about $0.03 with the cached prefix. 60 calls per seller per day caps a seller at $13 on the worst day and about $2 on a typical one; thirty sellers at twenty calls a week is about $20 to $40 a week. The route logs `input_tokens`, `output_tokens`, `cache_read_input_tokens` and the model per call, without the deck text.
- Rate limits. Two quota rows in `ratelimit.ts` `QUOTAS` in the table's shape: `assistCallsPerMinutePerDeck` (anonymous 6, account 20, agent 60) and `assistCallsPerDay` (anonymous 20, account 300, agent 1,000), refused with 429, `Retry-After` and the sentence "Too many assistant requests. Try again in a minute"; a WAF rule r22 for `/_serverFn/**` assist calls per IP beside r1; the quotas hold hosted only with Redis (`docs/security.md` section 4), so until Upstash is installed the WAF rule is the limit that counts across instances.
- Privacy words. The panel's first line as above. For a deck whose `generalAccess.mode` is `restricted` the sentence adds "including this restricted presentation"; a link visitor sees the panel disabled with "Commenters and editors can use the assistant". The brand kit of another organisation names its own provider account and, where the provider supports it, its inference region (`inference_geo`), so a customer's deck never leaves the route the organisation chose; the line then names that organisation instead of General Translation.

### Guardrails

- Never a write without a card. The server returns proposals; the seller's Accept is the only path to a write, and the write is one revision and one undo step with Undo in the snackbar.
- Only the listed actions. The assist may write `slide.update`, `slide.insert`, `slide.new`, `slide.replace`, `slide.applyLayout`, `block.set`, `block.align`, `block.distribute`, `block.autofit`, `text.replaceAll`, `deck.copy` and `deck.rename`; never `deck.trash`, `deck.remove`, `share.*`, `comment.*`, `account.*`, `admin.*`, `deck.publish`. The list lives beside `SERVER_SIDE_WINDOW_ACTIONS` in `agent-actions.ts`.
- Validated before shown. Every proposed action input is parsed with `ACTIONS[id].input.safeParse` and the block, slot and layout ids are checked against the current slide before the card is drawn; a proposal whose `baseRevision` is behind the deck is re based on the seller's Accept or dropped with the sentence "The slide changed while this was written; ask again".
- The seller's lease. The write runs from the seller's page under the seller's own lease, so an assistant never takes a slide another person holds; the author stays `agent` so Version history and the marks tell the truth.
- Nothing leaves that the line does not name. Two routes only, the model provider under the organisation's account and General Translation's translation service; the standalone HTML, the exports and the published player carry no assist state but `ext.assist`.
- Off switch. The `assist` kill switch turns the panel into the sentence "The assistant is off on this Turboslide" and refuses the route with 503; the `readOnly` flag refuses Accept.
- No prose in the chrome from the model. The card's sentence is the model's; the buttons, the first line and the errors are the product's words, in sentence case, with no rule ids or specification citations.

### What to measure

- Per call, without the deck text: intent, slide count, tokens in and out, cache reads, latency to the first card and to the last, model, effort, outcome (accepted, dismissed, changed the ask, error), and undo within 60 s of Accept.
- Weekly: accept rate per intent (the target is above one in two), undo within a minute after Accept (below one in ten), the time from `/new` to a five slide deck with and without the assist, translate calls per target language and their overflow findings per slide, cost per seller per week against the $2 typical figure, the "Nothing matches" rate of Search the menus before and after the synonyms and the "Ask the assistant" row.
- Quality: the judge loop's six lenses (`docs/judge-loop.md`) over a weekly sample of accepted proposals, as the offline gate; a severity 3 finding on an accepted proposal is a bug of the card's prompt.

## Method

The walk (`scripts/assist-walk.mjs`), in order: `/new`, the title typed at 40 to 90 ms per key after a real double click on the heading (A1 rule 3), Escape, revision 1 and the `/edit` address; the title row, toolbar and menubar controls read from the DOM; New slide from the toolbar, a heading and three lines typed, a speaker note typed under the slide; Search the menus opened from the toolbar for 22 phrases with the rows and the count read each time; Tools > Check slides and its rows; Tools > Advanced tools on, the menubar read, Extensions > Agent access read and shot, Tools > Advanced > Run an action opened and ">replace" typed, the switch off again; back to the title slide; `POST /api/actions/text.replaceAll?deck=<id>` with the bearer and `x-turboslide-author: agent:assist-probe` (Acme to Globex at the current revision); the stage, the banner and the snackbar polled for 12 s; Cmd+Z with the stage focused; File > Version history > See version history read and shot; the New slide arrow's layout picker read and shot; `deck.info`, `export.text` and `slide.get` through the window API; then, in the finally block, File > Move to trash, Delete forever with its confirmation, and `GET /edit/<id>` and `GET /deck/<id>` read as 404.

The four failed rows: row 2 is my own regular expression matching the Help menu's control id, and the reading it records (no assistant control) stands; row 3 is the setup misfire named in table row 12 (the second slide's heading took the three lines through a stale rectangle, so the body stayed empty and Check slides reported two empty placeholders); row 36 read zero `[data-author]` rows because the version window was collapsed, and the window's text names the agent; row 38 expected the speaker note in `export.text`, and the note was gone because the Cmd+Z of row 35 had taken it, which is the finding of table row 1. Four console errors were the CSP report only notice about `upgrade-insecure-requests`, none from the product's code.

The agent read (`scripts/agent-read.mjs`): `GET /api/agent` with and without the bearer, `/llms.txt`, `/llms-full.txt`, `/openapi.json`, `GET /api/actions/text.replaceAll`, `POST /mcp` without a bearer, and the counts from the manifest, written to `agent-surface.json` without the token. The transport counts in the summary come from `packages/schema/src/actions.ts` because the manifest lists actions by group without their transports.

Not driven: a second browser (no multiplayer reading was needed for this area), 1280 by 800 (the brief for this area names no second viewport), and any model call (the product has none).
