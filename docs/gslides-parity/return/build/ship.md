# The return round, the ship step

The ship step of the return round (docs/RETURN.md section 6; the focus round's `docs/gslides-parity/focus/build/ship.md` is the shape), run on 2026-09-19 after the verifier's two passes on the merged tree (`docs/gslides-parity/focus/VERIFICATION.md` "Return round, pass 1" and "Return round, pass 2"). The binding acceptance is the core gate of FOCUS.md 6.2 with RETURN.md section 1: two runs on the enforce preview built from the tree with no code change between, a row passing only when it passes in both, and one run on production after the alias moves. The ship step verified the preconditions itself, ran the gate on the deployment of record once more, applied the ship rule to every row that differs between the runs, made the one seam fix the rule asks for, committed, pushed, and measured production. Times are UTC. Nothing here ran `pnpm install`, `pnpm add`, `pnpm exec`, `pnpm build` or `vite build` outside `scripts/check.mjs` and the `pnpm generate:contracts` script step 3 runs; the git write commands were the two commits and the pushes of section 8, and one `git checkout -- docs/gslides-parity/verification-3/parity-audit.json` to restore the file the verifier's check chain rewrote. The scratch files live under the session's scratchpad (never tracked); the evidence that belongs to the round is under `docs/gslides-parity/focus/verification/` with the prefixes `gate-preview-return-ship`, `return-ship-` and `production-return-`.
