## 2. Decisions

1. **The gesture previews over a provisional conversion and the release measures.** A drag on a
   grammar slide converts the slide from the stage's boxes at the press (`toFreeform` over
   `canvasBoxesFromMeasured`) so the preview draws the freeform slide the write will produce; the
   release runs `measureForCanvas` on the hidden sheet and re-runs the same gesture over the
   measured canvas, so the pos written are the measurer's (1.3) and the preview was at most a
   pixel off. When the hidden sheet cannot render (a test without layout) the stage's boxes stand
   in. The write is one `slide.update`, `slide.replace` first (1.6), and `actionForMutation`
   learned to carry a lone `slide.replace` as a `slide.update` too.
2. **The stage writes `block.set /pos` for a rotation, a flip, a group and a crop.** SPEC-2 6.1
   names the actions `block.rotate`, `block.flip`, `block.group` and `block.crop` as the write of
   a handle drag. Those actions run through the store actions with `withCanvas`, which needs the
   route's `measureCanvas` binding (merge 2); until then they refuse a grammar slide. The stage
   therefore computes the same fields itself (`rotateMutations`, `flipMutations`, `groupMutations`,
   `/trim` plus `/pos`) and commits one `slide.update` (or one `block.set`) with the conversion,
   which is what those actions write through the reducer; the agent spellings stay the CLI's and
   the menu rows'. Cmd+D on a canvas stays `block.duplicate` (round one); on a grammar slide the
   conversion travels with the inserts of the copies. `block.align` with `to` and `block.duplicate`
   keep the round one action calls where the slide is a canvas already.
3. **Cmd Up and Cmd Down on a grammar slide stay the round one slot reorder (`block.move`).**
   SPEC-2 6.1 row 13 asks for one stack per canvas on every slide kind. `editor.spec.ts` (not
   B4's) pins Cmd Down on the chip writing one `block.move` down the slot, and SPEC-2 1.6 keeps
   `block.move` between the slots of a grammar slide as a grammar write, so the stage keeps that
   behaviour for a real block and converts only for a kind's object that is not a block (the
   photograph, the plate, the title's mark), where a slot reorder has no meaning. The menu's
   Arrange > Order plans `block.move` on a grammar slot too (B3's `menuActionPlan`), so the key
   and the row agree. Recorded for the verifier's list.
4. **Crop mode writes `/pos` with `/trim`.** Google's crop handles shrink the frame over the fixed
   picture; `block.crop` writes `trim` alone, which would keep the frame and scale the picture into
   it. The stage writes both fields in one `slide.update` so the picture stays where it was and the
   frame follows the handles; a pan writes `/trim` alone.
5. **Cmd+I and the other marks with an object selected apply over the whole text.** SPEC-2 6.2
   binds the marks while a run is edited; Google italicizes a selected text box's whole text with
   the same chord. The stage does the same as one `text.replace` per selected text object.
6. **The equal spacing guides beat a line snap when closer.** `snapMove` runs the spacing snap
   after the line snap on each axis and takes it when its correction is smaller, so a box dragged
   near an equal gap lands on the gap and the two ticks draw.
7. **The overlay follows the stage's scroll.** Round one placed the overlay at the sheet's fit
   position; a zoomed stage scrolls the sheet inside `.pt-sheet-stage` while the overlay did not
   move. The Editor reads the scroller's scroll (`Sheet.onScroll`) and offsets the overlay while
   `zoom` is not `fit`.
8. **The clip lift is scoped to the editor.** SPEC-2 1.4 names `.ts-stagewrap:not(.is-present)
.sheet { overflow: visible }` in `Stage.css`; that selector would also lift the clip of the view
   route's Stage, whose sheet should clip like a thumbnail. The rule lives in `Editor.css` under
   `.ts-editor:not(.is-present)`, which is the editing case the row describes.
9. **`toGrammar` returns a `Slide`.** A converted title, statement or picture kind restores to its
   kind through `fromCanvas`, so the return type is `Slide`, not `ContentSlide`. The route's
   `convertedLayout` types the result as `ContentSlide` and reads the record from `ext.grammar`;
   both are the integrator's lines (request 2).
10. **The hidden measure root carries the present document's inherited text defaults.** The CLI
    measures the present document, whose body has the browser defaults (16 px type, normal
    spacing); the studio's body sets `font-size: 13px`, and the hidden `.ts-sheet` root inherited
    it. The theme leaves a few containers at the inherited size, and the title's `.left-mid` (the
    box around the inline mark svg, the heading and the lead) takes its line box from that font,
    so the mark measured at y 288.94 in the editor and 288.31 in the CLI: 289 against 288 after
    rounding, on the same Chromium (`.turboslide/b4/{cli-raw,editor-raw,probe-src}.mjs` print the
    raw rects of both). `mountHiddenSheet` now declares `MEASURE_ROOT_RESET` on the root
    (`font-size: medium`, `line-height: normal`, normal spacing, `text-transform: none`, the rest
    of the inherited text properties at their initial values) and leaves `font-family` and
    `color` to the renderer's `.ts-sheet` rule (`block-css.ts` line 9), which the studio and the
    present document both load; a first attempt with `font: initial` on the root overrode that
    rule and measured the sheet in Times. With the reset the title measures `mark [137, 288, 132,
84]`, `heading [137, 420, 901, 90]`, `lead [137, 536, 901, 75]`, equal to `slide to-canvas`.
    The visible stage inherits the same 13 px and keeps it this round: the Editor root hosts the
    overlay's chips and readouts, which inherit the studio's type, so the reset there needs a
    pass over the chrome inside the root (a sub-pixel difference between the stage before a
    conversion and the exported sheet, never a written value).
11. **Esc before a drawn text box's session opens keeps the box selected.** The text tool's
    insert travels through `commitCanvas` (a measure, then the write), and the caret session
    opens when the written document arrives (`pendingEdit`). Esc in that gap used to reach the
    stage's key handler and clear the selection, after which the session opened anyway. Now Esc
    with a queued session drops the queue and selects the box once it lands (`pendingSelect`),
    the state Esc inside the session leaves. `objects.spec.ts` presses Esc right after the write
    is logged and reads the box's frame.
12. **The caret stays inside the run.** A list item's run starts with its icon svg; a click on the
    icon, or Home before it, puts Chromium's caret outside the editable, in the item above's text,
    while the editable keeps focus, so `selectionOffsets` was null, Tab ended the session instead
    of raising the level, and the toolbar read nothing. `InlineText` now moves such a selection to
    the start of the run (or its end when it landed after the run) on `selectionchange`, and
    `plainOffsetOf` counts an element position from the first segment at or after the named
    child, so the position before the icon is offset 0 (`inline-offsets.test.ts`).
