Why the row tracks are `auto` and `minmax(<height>px, auto)` and not the `minmax(<row height>, 1fr)` docs/OBJECTS.md 3.3 item 3 wrote. A track whose minimum is a length turns its item's automatic minimum size off (CSS Grid 6.6: the content-based minimum applies only to an item spanning a track whose min sizing function is `auto`), so in a box shorter than the rows the item overflows its track instead of growing it; measured on the first drive with `minmax(54px, auto)`: forty words in the 320 px box gave a 211 px track under a 314 px cell, the text past the last rule. A `1fr` maximum is worse still: with a definite box the flexible tracks share the box and never grow past it. An `auto` track keeps the content-based minimum, so an empty row stands at its line box (the sheet's zero width space, 54 px at 20 px with the rule, the number `tableRowTrack` states), a wrapped cell grows its row, and `align-content: stretch` on the positioned table shares the extra evenly among the auto tracks, which is the behaviour the item describes. A set row height keeps `minmax(<height>px, auto)`, Google's minimum row height, and a table whose rows all carry heights (after a row seam drag, which writes every row) holds its text through the autofit: `readTableRows` reads a row's drawn pitch as never below its text, so `tableGrowMutation` writes `pos.h` up and the tracks get the room.
