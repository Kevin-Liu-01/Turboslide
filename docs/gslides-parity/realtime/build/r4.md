- The default host list is the design's five entries and nothing more (`*.vercel.app` considered and left out; request 7 names the consequence for a preview with a database).

### Deviations from the design, with reasons

- **better-auth's tables take the library's own D1 path, not this lane's Kysely.** `wrangler dev`'s D1 refused the library's generic SQLite index read of `getMigrations` (a join of `sqlite_master` against `pragma_index_list(tables.name)` and `pragma_index_info(index_list.name)`) with `D1_ERROR: not authorized: SQLITE_AUTH` on 2026-10-01, while the plain `sqlite_master` reads, `PRAGMA index_list('t')`, `PRAGMA index_info('i')` and `SELECT * FROM pragma_table_info(?)` all passed (the probe's statements are listed in "The servers"). The installed adapter runs its own D1 dialect and D1 index introspector when the `database` option is a binding shaped object (`batch`, `exec`, `prepare`; research-d1-auth.md 2.1), so `db.ts` hands better-auth `d1Binding(client)` (`d1-proxy-dialect.ts`), a facade whose `prepare().bind().all()` is one `/db/query` and whose `batch()` is one `/db/batch`; Turboslide's tables and the seed stay on the Kysely of the proxy dialect, with an introspector of the same D1 safe shape. The design's "`database: { db, type: 'sqlite' }` for the `d1` kind" (4.2) is therefore the other engines' line; the counters and the client are one.
- **The library's runtime schema check is off on the engine** (`advanced.database.validateSchema: false`, documented at `@better-auth/core` `init-options.d.mts`): it introspects every table once per instance (two calls, a dozen statements) and the boot path's `ts_schema` row carries the version instead (request 10).
- **The anonymous branch tolerates a dead store.** With the principal records on D1 the anonymous branch does read D1 (one indexed row through the 2 s cache); when the proxy does not answer, `requestIdentity` keeps the request's anonymous id and hands it its label for that request (`principals.touch(...).catch(() => null)`), as the design's "the anonymous branch needs no database" (3.8) reads once the records moved.
- **The session facts cache is on for the `d1` engine alone** (300 s; 0 on SQLite and Postgres unless `sessionFactsCacheMs` is given): the local engines read for free and the identity tests expect a write to be read on the next request; a Postgres deployment (none exists) would gain it in a line.
- **`ts_principal`'s columns are the design's snake case** (`principal_id`, `record`, `last_seen_at`, `expires_at`), unlike the camel case of the other `ts_*` tables, because 4.2 spells them so and R1's control tables are snake case too.
- **The second harness mode reads through the proxy by default** and through `wrangler d1 execute --json` on request (`TURBOSLIDE_SEED_D1=wrangler`), where 4.3 names wrangler alone: the bearer is in a spec run's environment on every origin the mode runs on, the route is the same the server uses, and a wrangler spawn is 2 to 4 s per read; both paths are in `identity-seed.mts` and the wrangler one was run once against `wrangler dev`'s D1 (section "The servers").
