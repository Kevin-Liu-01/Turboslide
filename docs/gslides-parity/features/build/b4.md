### 4. How a row reads on this tree

The drivers judge what the product does and never wait for a lane (docs/PRODUCT.md 8.1). A control that is not on the build reads not built with the control's id and its lane, which the gate records as not driven with that reason; a control that exists is judged, so a gesture row on today's product fails with the facts and names the FEATURES.md rank in its observed column (a table's one click that places no caret reads "the first click placed no caret (FEATURES.md 2.2 rank 2, B3)"). The dialog rows read not built on `insert.logo` while the menu row is not in `model.ts` (the integrator's file; the dialog `dialogs/Logo.tsx` is on the tree but nothing opens it), and judge the dialog the moment the row lands, without an edit here. The two upstream rows read the upstream from the refresh's dry run (`upstream`) and skip with the unit tests named on every origin but a preview set to the fixture or the outage.
