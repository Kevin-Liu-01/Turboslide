### 5. What a reviewer should know

- The intake sanitizes before sharp: `imageInfo` is called on the sanitized bytes, so the intrinsic size is read off the clean file and the 64 megapixel budget and `failOn: 'error'` never see the upload's own bytes on a hosted instance. A checkout's CLI still decodes the file as it came (the process policy carries no sanitizer there).
- The read ahead fetches the vector file once per file per page life and only when the selection becomes exactly one vector picture; no store call and no poll join the cost rows' states.
- `ClipboardStore.note` exists because `write` calls `navigator.clipboard.writeText(envelope)` after the copy event, which would replace the markup the event wrote; `read` answers the noted payload while the system text is still that markup, so Edit > Paste in the same tab pastes the picture and a paste elsewhere reads the markup.
- The `image` rule keeps only base64 raster data URIs; an `image/svg+xml` data URI is dropped as before (a nested document is not a raster fill).
