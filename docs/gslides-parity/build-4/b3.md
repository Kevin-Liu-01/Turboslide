### 1.2 Why the split reaches the entry

TanStack Router's automatic code splitting compiles a route file into a reference module (the `Route` with `lazyRouteComponent` importers for `component`, `pendingComponent` and `notFoundComponent`) and one virtual module per split property (`edit.$deckId.tsx?tsr-split=component`), each dead code eliminated to what it uses. On `BASE` the route file exported `EditorRoot`, so the reference module could not drop it and the whole editor stayed in the module the route tree imports on every page; `new.tsx` read the same module as a namespace at module level. After the split the route files export `Route` alone and read `EditorRoot` only inside their component, so the reference modules keep the skeleton, the loader function and the search validator, and the editor's graph moves behind the component importer. The dev server shows it (section 5, the module reads on 4343): the reference module of `/edit/$deckId` imports `EditorSkeleton`, `readEditorDeck`, `validateEditSearch` and the router; its `?tsr-split=component` module imports `EditorRoot` and `authorOfIdentity` from `/src/editor/EditorRoot.tsx`; the reference module of `/new` imports `TITLE_ROW`, `EditorSkeleton`, `readDraftDeck` and `validateEditSearch`. The bundle numbers are the integrator's step 6 and the verifier's step 31; the day 1 change measures nothing and claims no gain.

### 6.4 Deviations from SPEC-4 and the plan, argued

1. The Recent row's source (0.29, PP 3.1 item 3: "the loader returns the Recent row from `localStorage`"). A loader that runs on the server for the document request cannot read `localStorage`, and the row that home.spec.ts must find in the server's HTML has to come from the request. The record therefore has two copies of the same entries: localStorage (the browser's own, the source of "Opened 2 hours ago" and the Last opened by me order) and a cookie mirror `ts-recent` scoped to `Path=/decks` (so the editor's requests, the server functions and the thumbnails never carry it), pruned together to the newest twelve and capped at 3,000 bytes. The pattern is round three's view and sort cookie (SPEC-3 9.2 L1). A browser that refuses cookies gets the round two behaviour (the store's order, no row, the band hidden until mounted under the opened sort).
2. The Recent row is a row of its own above the store's cards, captioned "Opened on this device" (one row of four), rather than the first cards of the list: the streamed list may arrive inside the same document (it does on the file and tmp stores), so a row that lived in the Suspense fallback would be in the HTML only when the store is slow, and the row's cards would carry the list's control ids twice. The list under the "Recent presentations" heading keeps its sorts and its tests; the row's controls are `home.recent.<id>`.
3. The first design of the streamed list rendered a second `DeckList` (the last list) as the Suspense fallback during a refetch. React keeps a suspended boundary's children in the document hidden, so every card was in the DOM twice for the refetch's duration and home.spec.ts's Rename row failed on a strict mode violation. `useStreamedList` replaced it: one mounted list that suspends on the first promise and takes later ones through an effect. Recorded because a reader of PP 3.1 could build the first design again.
4. `getDeck`'s CDN header is set on the server function's own answer alone and only for the public shape of an open or published deck (`via` `open` or `publish`, no notes, no skipped slides, html blocks as notes); the plan's "keyed by deck and revision" alone would let the CDN keep an owner's shape (the html block frame, SPEC-3 8.4) or a restricted deck's payload under a URL a stranger may request. The document response never carries it (the `/_serverFn/` path test).
5. `/brand/**` takes a day with a week stale rather than 1.6's "immutable for a year": the twins are named without a content hash (`site.ts` `TWIN_PATHS`: `hero-dark.png` and the rest), and a year of `immutable` would pin a regenerated twin in every browser that saw it. `/home/**` (B2's content hashed shots) takes the immutable year as 1.6 says. `check-vercel-output.mjs` asserts a `cache-control` header per rule and not its value, so step 30 is unaffected.

On the three `'data-only'` routes the server's 404 body is the skeleton, not the access page: the router renders a data-only route's pending component on the server whatever the loader answered, and the `notFoundComponent` mounts with hydration (270 to 400 ms after the document on 4343; the probe of 6.6).
