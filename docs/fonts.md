# The font catalog

Where the faces come from, how a deck names one, how a face reaches the editor, the viewer, the
capture and the exports, and how to add a family (`docs/gslides-parity/SPEC-5-amendments.md` A5,
A6; the build notes are `docs/gslides-parity/build-5/b7.md`). Google Slides' Font menu lists
Google Fonts; Turboslide lists about twenty five open licence faces Google Slides also offers,
committed to the repository, and never fetches at build time or at run time.

## 1. The catalog

- `packages/schema/src/fonts.ts`: `FONT_IDS` (the membership, in order), `DEFAULT_FONT_ID`
  (`inter`), the four categories (`sans`, `serif`, `display`, `mono`) and the two licences
  (`OFL 1.1`, `Apache 2.0`). `Typography.family` is one of these ids; absent means the theme's
  face. The theme record's two roles (`themeEdits.fonts.text`, `.display`) take an id too.
- `packages/fonts/src/catalog.ts`: `FONT_CATALOG`, one row per id with `name` (the family name
  PowerPoint and Google Slides use), `category`, `weights`, `italic`, `licence`,
  `reservedFontName`, `files` and `source` (the google/fonts path at the pinned commit
  `GOOGLE_FONTS_COMMIT`); `catalogFont(id)`, `fontFamilyStack(id)`, `fontFamilyVariable(id)`,
  `fontAssetPath(id, file)`, `fontsInCategory`, `catalogSummary()` (the `font.list` answer).
- `packages/fonts/src/catalog-files.ts`: generated by the fetch script; per file the style, the
  weight or `wght` range, the bytes and the digests of the woff2 and of its TrueType source.
- `packages/fonts/src/names.ts`: the browser half (the family names, the generic families, the
  category words, the catalog version and the served paths) for the chrome and the studio, which
  never load the file table.
- `packages/fonts/src/used.ts`: `usedFontIds(deck, slides)`, the families a deck uses, in
  `FONT_IDS` order and never Inter.
- `packages/fonts/src/catalog-node.ts` (Node only): `fontFileBytes`, `fontFileDataUri`,
  `fontFilesWithBytes`, reading `packages/fonts/assets` or the materialized packages folder of a
  hosted function (`TURBOSLIDE_PACKAGES_DIR`).
- `packages/fonts/assets/<id>/`: the woff2 files (variable where the family ships one, the five
  inspector weights where it does not) beside the family's `LICENSE`. Inter's files stay where
  round one put them. The sizes per family are in `b7.md` section 6.
- `THIRD_PARTY_NOTICES.md` names every family with its licence and Reserved Font Name.

## 2. Adding or removing a family

1. Add the id to `FONT_IDS` in `packages/schema/src/fonts.ts` (the integrator's file; a request
   from the fonts lane) and its row to `FONT_SOURCES` in `packages/fonts/src/catalog.ts` (the
   google/fonts directory and what to take: `{ kind: 'variable' }`, `{ kind: 'static', weights }`).
2. Run `node packages/fonts/scripts/fetch-fonts.mjs --only <id>` once. It reads `METADATA.pb` and
   the licence text at the pinned commit, downloads the TrueType files, converts each to woff2 in
   the fonts venv (`.turboslide/venv`, fontTools with brotli; a format conversion alone, nothing
   subset or renamed, so a Reserved Font Name survives), writes the files and `LICENSE`, and
   regenerates `catalog-files.ts`. A family under a licence other than OFL or Apache is refused.
3. Add the name to `FONT_NAMES` in `packages/fonts/src/names.ts` and, when it is not the id in
   title case, to the picker's exceptions in `packages/chrome/src/font-picker-model.ts`.
4. `cd packages/fonts && ../../node_modules/.bin/vitest run` pins the lists, the files and the
   digests; `apps/studio/src/editor/font-picker-facts.test.ts` pins the browser half to the
   catalog.

Removing a family is the reverse; a deck that names a removed id fails validation on `family`.

## 3. How a face reaches a page

- The renderer writes `font-family: var(--ts-font-<id>, inherit)` on a block with a family
  (`typographyDeclarations` in `packages/schema/src/typography.ts`) and, on the sheet root,
  `--ts-font-<id>: '<name>', <generic>` for every used family beside its `@font-face` rules
  (`packages/render/src/fonts.ts`: `fontsCss`, `deckFontsCss`, `fontVariablesRule`). A document
  that never loaded the face inherits the theme's.
- The studio serves the faces at `/fonts/faces/<version>/<id>[+<id>...].css` (one `@font-face`
  group per family, `font-display: swap`, the sheet root rule) and the files at
  `/fonts/<version>/<id>/<file>.woff2`, immutable under the catalog's version; the `current` alias
  of the stylesheet is cached for five minutes (`apps/studio/src/routes/fonts.$.ts`,
  `apps/studio/src/server/fonts.ts`).
- The editor and the viewer mount one stylesheet link naming the families the document uses
  (`packages/chrome/src/FontFaces.tsx`, `link[data-control="fonts.faces"]`) and nothing for a
  document in the theme's face, so no font file loads before the ready mark unless the deck uses it
  (the `/edit` budgets of SPEC-4 4).
- A self contained document inlines the used faces as data URIs: the headless capture, the
  thumbnails and the PDF through `loadThemeBundle({ fonts: usedFontIds(deck, slides) })`
  (`packages/render/src/theme-node.ts`) or `renderDeck`'s `extraCss`, the standalone HTML through
  `renderStandalone`'s `fontSrc` (`packages/render/src/standalone.ts`). The callers that pass the
  used ids are named in `b7.md` section 9 (requests).

## 4. The surfaces

- The toolbar's Font dropdown, in Google's position left of the font size control
  (`packages/chrome/src/FontPicker.tsx`; `toolbar.font` in `menus/toolbar-tails.ts`): the selected
  block's family name, a plate with a search field, the families of this presentation first, then
  the catalog by category in Google's order, every label in its own face (a face loads when its row
  scrolls into view, never before), the theme's face as the first row, and More fonts at the end.
  A pick writes `block.set /typography` with the family; the theme's face removes the key. A table
  takes no family.
- More fonts (`packages/chrome/src/dialogs/MoreFonts.tsx`): Google's dialog form, the search and
  the category filter on the left with the licence line under every name, "In this presentation"
  on the right, OK applies.
- The theme mode's Fonts control (B6) lists the same catalog for the two roles through `FontList`.
- The pure rules are `packages/chrome/src/font-picker-model.ts`
  (`font-picker-model.test.ts`); the components are `font-picker.test.tsx`.

## 5. Actions and the CLI

- `font.list`: the catalog with its licences (`apps/cli/src/actions/font.ts`), on the CLI, the MCP
  server (`deck_list_fonts`), the HTTP surface and the window API (served, so the file table stays
  out of the client bundle).
- `turboslide fonts list [--json]`: one row per face; `--json` the action's output.
- The text style action carries `family`; `theme.set /fonts/text` and `/fonts/display` write the
  roles (B6).

## 6. Exports

- Editable text names the family in `a:latin typeface` and the residual line names the families
  PowerPoint may substitute on a machine without them (`packages/export/src/pptx/text.ts`, a
  request to B5 in `b7.md`); the Perfect raster embeds nothing because it is pixels.
- The standalone HTML inlines the used faces as base64 woff2 (whole files; the subset question and
  the sizes are `b7.md` sections 5 and 6).
- The PDF and the thumbnails load the files through the headless capture.

## 7. Tests

`packages/fonts/src/catalog.test.ts` (the lists agree, every file exists byte for byte with its
licence), `packages/render/src/__tests__/fonts.test.ts` (one `@font-face` group per used family and
none otherwise), `apps/studio/src/server/fonts.test.ts` (the route), `packages/chrome`'s picker
tests, `apps/studio/e2e/fonts.spec.ts` (the route, `font.list`, no font before the ready mark, a
family through the action, the picker and More fonts); `compare-to-shoot` is unchanged because the
GT deck uses Inter alone.
