### 3.1 `sync.viewer.live-updates`: the quiet tick counted a second tab of the same instance as nobody

The mechanism (VERIFICATION.md pass 2 F1 read the symptom; the code gives the cause): `blob.ts` `nextTickMs` asked the roster for rows of "another client" and filtered out every row this instance's own tabs had set (`ownClients`, filled by the presence route). X saw two rows, both its own, and no op landed on X (the commit was Y's), so it ticked at the quiet 10 s until its first pull moved `lastOpAt`; the verifier's two runs read words one and two at the 5 s bound and word three fast, which is that tick and the active window after it. The fix (`packages/realtime/src/blob.ts` `nextTickMs`, B1's file): company is a roster row another instance's tab set, a second row this instance's tabs set, or a second stream of the deck open on this instance (`state.listeners`, for a tab whose row has not landed yet); the quiet tick stays a tab's alone. `pollTickMs` (`pulse.ts`) is unchanged in code; its `others` input's sentence names the new reading. `blob.test.ts` gains the case (two streams on one instance tick at the active pace with an empty roster; one stream with two own rows ticks at the active pace); the existing quiet and active window tests pass unchanged (22 of 22, 06:25Z).
