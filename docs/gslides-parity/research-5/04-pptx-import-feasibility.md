# 04 PPTX import feasibility

Research report for round five, scope item D (File > Import slides from a PPTX, the Upload tab of the home page and of the Open and Import slides dialogs, Import theme). Written 2026-09-14 against main at d5d7f07. Every repository path below is read at that commit with `git show d5d7f07:<path>`; the working tree carries round four's uncommitted edits and was not used. Every external source is public documentation, read on 2026-09-14, listed in section 13 with its URL and the page's own last update date where the page states one.

## 1. Verdict

PPTX import into the block document is feasible in this round, without a new rendering engine and without Python at runtime. The reader is the Editable text writer read in reverse: `packages/export/src/units.ts` already fixes the unit conversions (7,620 EMU per sheet pixel, 120 px per inch, 0.6 pt per px), `packages/export/src/pptx/*.ts` already holds the tables that turn block fields into OOXML (preset names, dashes, line ends, bullet schemes, chart kinds, legend positions, number formats, merged cells, links), `packages/schema/src/shapes.ts` already carries the 135 ECMA presets by their `prstGeom` name, and `packages/export/src/ooxml/*.ts` already reads slide parts, shapes, groups, page size, slide names and title placeholders out of a package. What does not exist is a namespace aware XML parser, the placeholder and text style inheritance walk (slide, layout, master, theme), the media extraction into assets, and the report of what dropped. Those four are the round's work.

The reader cannot be lossless, and the report says exactly where: PowerPoint has per run font sizes and families, side borders on table cells, gradient and pattern fills, soft line breaks, 3D, text warps, SmartArt data models and OLE objects, and the block schema has none of them. Every such object lands as the nearest block plus a report line naming the slide, the shape and the reason, which is more than PowerPoint, Google Slides or Keynote tell their users (section 11).

Four decisions the round should take up front:

1. Every imported slide is a canvas slide: `kind: 'content'`, `layout: { type: 'freeform' }`, `template: 'blank'`, every block with `pos`. Google's layout semantics do not map onto the GT layouts, and the exact positions are the only thing every PPTX producer agrees on.
2. Two theme modes, mirroring Google's "Keep original theme" checkbox of the Import slides dialog (research/03 section c.3): `adopt` (the default) snaps colours within a threshold to the palette tokens and writes Inter for every family; `keep` writes every colour as a hex. Sizes stay exact in both modes and the `type/ladder` lint names the off ladder ones; `snapToLadder` is an option.
3. One reader, two entry points: `import.pptx` creates a deck (the home page Upload tab, File > Open > Upload) and `slide.import` gains a `sourceFile` so the Import slides Upload tab copies selected slides into the current deck through the same `ensureAssets` path it uses today (SPEC 6.5). A `dryRun` returns the mapped document without writing, which is what the dialog's thumbnail step renders.
4. The input passes through the store's own zip reader (`packages/store/src/zip.ts` `readZip`, which caps the inflated total), then `validatePackage` of `packages/export/src/ooxml/validate.ts`, and only then the mapping. A package that fails validation is still read (PowerPoint repairs such files too) and the report says so.

## 4. Units, the sheet and any slide size

The writer maps the 1600 by 900 sheet onto the 13.333333 by 7.5 inch page, so one sheet pixel is 7,620 EMU and `sz="1320"` is 22 px (units.ts). The reader generalises this to any `p:sldSz`:

- Scale. Let `cx`, `cy` be the slide size in EMU. If `cx / cy` is 16:9 within half a percent (the tolerance `isSheetAspect` of images.ts uses), the scale is `1600 / cx` px per EMU and the offset is zero. Otherwise the sheet fits the slide by the limiting dimension and letterboxes: 4:3 (`9144000` by `6858000`, the default the Open XML SDK's minimum presentation writes) fits by height, 1200 by 900 px at x offset 200; 16:10 (`12192000` by `7620000`) fits by height, 1440 by 900 at x offset 80; a portrait or banner size fits by width. The report states the source size and the bars. When round five's Page setup (scope E) lands, `import.pptx` gains `sheet: 'fit' | 'match'` and `match` sets the deck's sheet to the source size instead of letterboxing; the mapping below is written in sheet px in both cases.
- Lengths. `px = emu × scale`; the default text insets `lIns`/`rIns` 91,440 EMU and `tIns`/`bIns` 45,720 EMU are 12 px and 6 px on the 16:9 sheet.
- Font sizes. `a:rPr sz` is in hundredths of a point; `px = (sz / 100) × 12700 × scale`. On the 16:9 sheet this is `sz / 60`, the inverse of `szOf`. A `a:normAutofit fontScale` (thousandths of a percent, or the `"92.000%"` string form the SDK example shows) multiplies the size; the block also gets `autofit: 'shrink'` so the renderer's own pass keeps it fitting in Inter.
- Rotation. `a:xfrm rot` is in 60,000ths of a degree clockwise (`ST_Angle`); the probe wrote `rot="900000"` for 15 degrees. `normalizeRotation` brings it into `[0, 360)`. The SDK page for the group transform prints "1/64000 of a degree" in its remark; the simple type is the same `ST_Angle`, and the reader divides by 60,000 in both places. `flipH` becomes `flip: 'h'`, `flipV` `'v'`, both `'hv'`.
- Percentages. `ST_Percentage` values are thousandths of a percent as integers (`a:srcRect l="10000"` is 10 percent; `a:alpha val="18000"` is 18 percent, the value the writer's hairlines carry), and some producers write the `"NN%"` string form. The reader accepts both.
- Group child coordinates. A `p:grpSp` carries `a:off`, `a:ext`, `a:chOff`, `a:chExt`; a child's `a:off` is in the child space and maps to the slide as `x' = off.x + (x − chOff.x) × ext.cx / chExt.cx` (and the same for y), scaled and then rotated and flipped about the group's centre. The writer sets `chOff = off` and `chExt = ext` so its own groups are the identity (groups.ts).
- Stroke widths. `a:ln w` in EMU becomes px and snaps to `SHAPE_STROKE_WIDTHS` (1, 1.5, 2, 3, 4) on shapes, `TABLE_BORDER_WEIGHTS` (0, 1, 1.5, 2) on tables and `RuleBlock.weight` (1, 1.5, 2) on rules; the exact value goes to the report when the snap moved it by more than 0.25 px.

A `p:sp` whose `p:cNvSpPr` has `txBox="1"`, or whose geometry is `rect` with no fill and no line and a `p:txBody`, is a text box. ## 6. Fonts, colours and the two theme modes

- Fonts. The sheet has one family and the export set carries Inter's Regular and Medium cuts (fonts-map.ts `EXPORT_WEIGHTS`). Every imported run renders in Inter; `b="1"` is weight 600 on the block when every run is bold, else the `*bold*` mark. The report lists every source family with its run count (`report.fonts`), so a deck that leaned on a display face is visible at a glance. A monospace source family on a one paragraph body becomes a `panel` block; on a mixed body it reports.
- Colours. `adopt` mode (the default) resolves every colour to sRGB through the theme (scheme colour, `p:clrMap`, `a:clrScheme`, then `lumMod`, `lumOff`, `tint`, `shade`, `alpha` in the order the python-pptx colour analysis lists them) and snaps it to the nearest palette token when the maximum channel difference is 12 or less (of 255): `#000000` to `ink` (`#070707`), `#ffffff` to `paper`, the greys near `#3a3d44` to `ink-2` and near `#8a8f98` to `titanium`, `#12a37a`, `#f0a020`, `#e5484d`, `#2f5ce0` to the four semantic hues. Everything else is a hex, which the `color/off-palette` lint names at severity 2 as it does today. `keep` mode writes every colour as a hex. Translucent fills composite on the paper colour in `adopt` mode (the writer's `compositeHex`) and report; in `keep` mode the alpha is reported and dropped because `Color` has no alpha.
- Sizes. Exact px in both modes, rounded to a half pixel; `snapToLadder` runs `nearestLadderSize` and reports each move. Google's checkbox has no size semantics either.
- The second sheet theme of round five scope E (the Turboslide branded theme) is where a source theme's colours could become a theme rather than hexes; the reader exposes `report.theme` (the resolved scheme as twelve hexes and the two font names) so Import theme can build one from it later.

## 7. The round trip of Turboslide's own exports

The reader recognises its own writer and recovers what a foreign file cannot carry:

- Object names `ts:<slideId>#<blockId>[@g:<tag>][@<row>]` (shapes.ts `objectName`) give back the slide id, the block id and the user group tag; `import-ids.json` is not needed for these. A name that is not a slug is slugified and de-duplicated, as `ids.ts` does for the Prototemplate importer.
- `p:cSld name` is the slide title (titles.ts `setSlideName`); the hidden title placeholder `ts:<slideId>#title` (`cNvPr hidden="1"`) is skipped and counted, never imported as a heading.
- The masters `DECK_PAPER_<THEME>` and `DECK_PICTURE_<THEME>` and their objects `ts:master#frame/<i>`, `ts:master#cross/<i>/v`, `ts:master#cross/<i>/h`, `ts:master#wordmark` are the theme's frame and are skipped even with `includeMasterShapes` on; the report says `Turboslide master chrome skipped`.
- Row groups `@<block>/row/<i>` (a ruled `rows` block written as hairline plus key and value boxes) come back as `rule` and `text` blocks under the user group tag; rebuilding a `rows` block is not attempted and the report says so.
- Families `GT Inter Display`, `GT Inter Text <opsz>` and `GT Inter Text <opsz> Medium`, `Inter Medium` map back to weights 500 and 400; `b="1"` on a Medium family is 600 or 700 (the writer collapsed both; 600 is written).
- A Perfect file is detected by a picture named `ts:<slideId>#sheet` covering the page (at `COVER_OFFSET_IN`) over runs whose fill carries `a:alpha val="0"`. The default imports the text layer at full alpha and drops the cover raster with the report line `Perfect file: the page raster was dropped, the text layer was imported`; `keepPageRaster: true` writes the raster as the slide's bottom picture and the text over it, which double draws and is meant for archival.
- Tables written with `addTable` (`a:tbl` with `gridSpan`, `rowSpan`) and charts written with `addChart` (cached values) round trip through 5.6 and 5.7; `hyperlink: { slide: n }` came out as an internal slide relationship with `action="ppaction://hlinksldjump"` and comes back as `#s/<id>` by position; the writer's `numCol` on `a:bodyPr` returns as `typography.columns`; the connector attachments written by `toConnector` return through `a:stCxn` and `a:endCxn`.

The residual of a round trip on the gslides-r1 fixture deck (packages/schema `__fixtures__/gslides-r1`) is the acceptance measure of fixture 5 in section 10: every block id, every text, every position within 1 px, every table cell and chart value.

## 9. The action, the surfaces and the guards

- `import.pptx` (group `deck`, `mutates: true`, transports `cli`, `mcp`, `http`, `window`). Input: `file` (a path on the machine or a `data:` URL, as `asset.add` takes) or `url` (an `https` URL, 200 MB at most, the bundle cap); `into` (the deck id; a slug of the file name when omitted, `-2` suffixed when taken, as `deck.unpack` does); `theme: 'adopt' | 'keep'`; `snapToLadder`; `includeMasterShapes` (default true); `includeHidden` (default true, as `skip: true`); `includeComments` (default false); `splitMixedSizes` (default true); `truncateTables` (default true); `keepPageRaster` (default false); `sheet: 'fit' | 'match'` once Page setup exists; `dryRun`. Output: `{ deckId, slides, blocks, assets, report }`, the report also written as `decks/<id>/import-report.json` (the Prototemplate importer's convention) and `import-ids.json` for stable ids on a re-import of the same file.
- `slide.import` gains `sourceFile` (a `.pptx` path or `data:` URL) as an alternative to `sourceDeckId`, with `slideIndexes[]` (one based positions in the file) instead of `slideIds[]`, and the same `after`, `sectionId`, `baseRevision`; it writes one `slide.insert` per slide in one write and copies the assets through `ensureAssets`, as it does for a deck source today. The Import slides dialog's Upload tab runs `import.pptx` with `dryRun: true` to render its thumbnails through the existing renderer, then `slide.import` with the chosen indexes.
- CLI: `turboslide import <source> --into <deckId> [--theme adopt|keep] [--snap-ladder] [--no-master-shapes] [--comments] [--dry-run] [--json]`, where a `.pptx` source runs the reader and a directory runs the Prototemplate importer that `apps/cli/src/commands/import.ts` wraps today, so the existing command grows rather than a second one appearing; `turboslide slide import --file deck.pptx 3,5-7 --after <slideId>`. MCP: `deck_import_pptx` and the extended `deck_import_slides`. Window: `run('import.pptx', input)`. HTTP: the upload goes through the bundle upload ticket route (`bundleUploadTicket`, `maxBytes` 200 MB) with the `.pptx` content type `tokens.ts` already knows, then the action runs server side, because assets are written through the store and pushed to Blob.
- Menus (`packages/chrome/src/menus/model.ts`): `file.importSlides` and `file.open` keep their rows; their Upload tabs accept `.pptx` and the refusal sentence of SPEC section 12 retires from the tab, the snackbar list and `menu-model.test.ts`; the home page Upload tab (research-4 05) accepts `.pptx` beside `.zip`; `file.new.templateGallery` is untouched. Import theme stays disabled until the second theme exists, with `report.theme` as its future input.
- Refusals, each a sentence in the dialog and a `TypeError` in the CLI: a `.ppt`, `.pps`, `.pot` (binary, by the OLE signature `D0 CF 11 E0`); a `.pptm`, `.ppsm`, `.potm` (macro enabled, by content type); an encrypted package (an OLE container); a `.odp` (round five E's ODP is an export; the reader does not read ODF); a zip64 archive; a package over 200 MB or inflating over 400 MB; a package with no `ppt/presentation.xml`. A package that fails `validatePackage` on relationships or content types is read anyway and the report carries the validation issues, because PowerPoint's own repair pass opens such files.
- Guards: `readZip` caps inflation; `@xmldom/xmldom` expands no external entities and the reader rejects a part with a `DOCTYPE`; part names are normalised through `resolveTarget` and looked up in the map, never joined to a path; media is sniffed by signature (`assetProblem`) and capped per picture by tier (25 MB anonymous, 50 MB account and agent) and per file by the bundle cap; links pass `blockLinkSchema` (`https`, `http`, `mailto`, `tel` and the slide forms) and everything else is dropped and reported; text is plain (the markup escapes `*`, `[` and a standalone `GT`); alt text is cut at 512 characters; a slide whose JSON exceeds `CAPS.slideMaxBytes` is split at the z order midpoint into two slides and reported; the whole import runs under the write quota of the deck's tier like a bundle upload.

## 11. How PowerPoint, Google Slides and Keynote report import fidelity

- Google Slides. Google's page "Work with Microsoft Office files" (support.google.com/docs/answer/6055139, read 2026-09-14) lists the PowerPoint types it opens (`.ppt` newer than Office 95, `.pptx`, `.pptm`, `.pps`, `.ppsx`, `.ppsm`, `.pot`, `.potx`, `.potm`, `.odp`), states that files can be saved back only as `.pptx`, and names what changes: "Embedded charts and videos in Word and PowerPoint files will be converted to images" and "SmartArt images will be converted to Google Drawings"; macros are unsupported. There is no per file report; the user finds the differences by looking. The Import slides dialog (research/03 c.3) offers only "Keep original theme".
- Keynote. Apple's Keynote compatibility page (apple.com/keynote/compatibility, read 2026-09-14) is a feature table. Supported: most 2D and 3D chart types, text formatting, shapes and images with shadows, reflection and transparency, hidden slides, slide numbering, presenter notes, "the majority of PowerPoint transitions" and "the majority of PowerPoint object builds", comments, ink imported as drawings. Partial: "Unsupported fonts are substituted", SmartArt "imported as a shape", not all slide master types, stock charts converted to line or bar, hyperlinks to files unsupported and no hyperlink anchors on charts, media limited to the types iOS plays. Unsupported: WordArt and text effects, text box overflow, image effects, object masks, OLE objects, surface charts. The page does not describe the warning sheet Keynote shows on open; that Keynote lists substituted fonts and removed features in a dialog is unverified here.
- PowerPoint. PowerPoint opens `.pptx` natively and reports nothing on a well formed file; on a damaged package it offers a repair pass. Microsoft publishes a Supported, Partially supported and Not supported table for the OpenDocument Presentation format; this report could not reach that page and does not quote it (unverified).
- pptxtojson, the closest open source reader, states an overall fidelity figure ("roughly 80%+") and returns no per object report.

Turboslide's report is therefore stricter than any of the three products: every dropped or substituted object is a row with the slide, the shape name and the reason; the dialog shows the counts ("42 objects imported, 3 shown differently, 1 dropped") with a Details view listing the rows, the way the Download dialog's Details lists the export report; the same report is the action's output for agents and lands beside the deck as `import-report.json`.
