### 1.2 The record and the two actions (7.1; R10 3.4)

- `setPreference(prefs, path, value)` writes on a copy through the pointer helpers of `pointer.ts` (`setAt`: an existing member, an array index, the length or `-` to append; an absent value deletes and a missing member is left alone), then validates the whole record against `preferencesSchema`, so an unknown member (`/theme`), a bad enum (`/units` `pt`), a bad row or a bad tag is refused with `PreferenceError` (a `TypeError`, so every transport answers 400 through `errorStatus`) carrying `code` (`invalid_pointer`, `invalid_field`, `unknown_field`) and the offending `pointer`. The empty pointer is refused: `prefs.set` writes one member (the action's input already says `min(1)`).
- The removed defaults rule of R10 2.3 is an invariant of the write, not of the dialog: after every write that touches `/substitutions/rows`, a default row (by `from`) present before and absent after joins `removedDefaults`, and a default row present after leaves it; a write to `/substitutions/removedDefaults` itself is taken as given. `normalizePreferences` (the read side) appends a default row that is neither in the table nor in `removedDefaults`, so a default the round adds appears once and a removed one never comes back.
- The two word lists are sets: `starred` unique in order (a second `/starred/-` of the same deck is a no op), `spelling.dictionary` unique and sorted in code point order (R10 4.8 "a sorted array of words, case sensitive"; `Intl.Collator` was not used so every runtime sorts the same).
- `prefs.get` answers `{ path }` without `value` for a missing member (the output schema's `value` is optional), `{ path: '', value: <record> }` for the whole record.
- The handlers read `deps.preferences`; a dispatcher composed without it answers `noPreferencesStore(id)` as a plain Error (a composition gap is not the caller's fault, so neither 400 nor the misleading 501 sentence "lands in GS5"). The compositions are request 1.

### 1.3 The mirror and the one time migration (7.1; R10 3.2)

- The mirror is the record as JSON under `ts-preferences`, read through `normalizePreferences` (a mirror written by an older shape fills its members), over a `StorageLike` (`getItem`, `setItem`, `removeItem`) so the schema package never touches `window`; every access is guarded because `localStorage` throws in a private window or under a blocked site data setting. The shell reads it in a `useState` initializer for first paint and reconciles with `prefs.get` on load (request 4, day 3 with the dialog); the record is the truth (SPEC-3 0.17).
- `migrateLegacySettings(storage)` reads `ts-editor-settings` (`SETTINGS_STORAGE` of `packages/chrome/src/editor-shell.ts`, spelled in the schema module as `LEGACY_SETTINGS_STORAGE`) for `spellcheck` and `announce`, turns them into `prefs.set` writes (`/spelling/underline` false, `/accessibility/announce` true), applies them to the mirror at once so first paint shows them, and hands them back with `commit()`. Only a value away from the record's default travels (R10 3.2's reason: a second browser of the same principal that never changed a toggle must not overwrite the first's choice), so a browser on the defaults marks itself done with no write. With writes, the mark `ts-preferences-migrated` is set by `commit()` after the record acknowledged them, so an offline first load retries on the next one. The legacy record is left as it is: the other stored settings stay per browser, and `spellcheck` remains the toggle's visual state until day 4 wires `tools.spelling.underlineErrors` to the preference.

Decisions:

1. The budget is a row per tag plus a total, set from this first measurement with about ten percent of headroom (`DICTIONARY_GZIP_BUDGETS`, `DICTIONARIES_GZIP_BUDGET_TOTAL` in `packages/spelling/src/index.ts`), as R10 4.4 says the number is "the builder's first measurement". R10's 400,000 working figure holds for five tags; `pt` (1.38 MB, the Brazilian dictionary's 4.5 MB word file) and `nl` (826 KB) exceed it and are not cut: a dictionary is never edited, both load lazily and only for a deck in their language (7.2 "lazily loaded dictionaries"), and the row is the regression gate. A dictionary that grows past its row fails step 35 until the row is raised with the reason recorded here.
2. The files are stored gzip compressed (`index.aff.gz`, `index.dic.gz`) and the Worker inflates them through `DecompressionStream('gzip')` (day 4): `.aff` and `.dic` have no registered media type, so a host serving them as `application/octet-stream` would not compress them on the fly (Vercel compresses text types; the Vite dev server compresses nothing), and 5.4 MB for `pt` on the wire would defeat the budget. With the bytes compressed on disk the measured bytes are the served bytes on every host, and the repository carries 3.4 MB instead of 12.7 MB. R10 4.4's file names `index.aff` and `index.dic` were its sketch; 7.2 names the folder alone. The check compares the inflated bytes with the installed package's (sha256 in the manifest), not the gzip bytes, so a zlib version change never fails it.
3. The licence option per tag (`DICTIONARY_LICENCES`) is the permissive or weak copyleft one of each package's SPDX expression (R10 summary item 2): `es` and `pt-PT` under MPL-1.1, `pt` under MPL-2.0, `nl` under BSD-3-Clause, `fr` MPL-2.0, `en` and `en-GB` the SCOWL notice. Each package's `license` file is copied verbatim as `LICENSE` beside its pair and served with it (an MPL file's notice travels with the file). No GPL only dictionary (`de`, `it`) is copied; the check refuses any folder under `public/dictionaries/` that is not one of the seven tags unless the flag file `.gpl-accepted` is present there, which is the switch for Kevin's decision (17; R10 12 item 1).
4. `dictionaryTagFor` answers null for a language without a dictionary (R10 5.2 "no match gives `missing`") instead of the placeholder's English fallback, so the card can say "No dictionary for <language>; the browser's marks apply" rather than checking German against English; `en-US`, `en-AU` read `en`, `pt-BR` reads `pt`, `en-GB` and `pt-PT` their own.
5. The catalog module imports nothing, so `scripts/check-dictionaries.mjs` reads the tables through Node's type stripping the way `apps/cli/bin/turboslide.mjs` runs the sources; the tags, packages, licences, file names and budgets have one home. The manifest carries no timestamp so `--write` is reproducible.

### 1.5 Deviations and decisions recorded

1. `normalizePreferences` fills an absent member with its default instead of refusing the record (the integrator's day 0 `parsePrincipalRecord` refused any deviation from the strict schema). A principal record written before a member existed keeps its name, avatar and grants; a wrong type or an unknown member still refuses the whole record so a later shape is never silently narrowed (SPEC-3 7.1's rule). This is "its migration" of MILESTONES-5 B5 item 1 on the record side.
2. The legacy migration writes only non default values (1.3), a narrower reading of "migrated once from `ts-editor-settings`'s `spellcheck` and `announce`" chosen so two browsers of one principal never fight; recorded for the verifier.
3. `prefs.set` deleting a default substitution row appends its `from` to `removedDefaults` on the write path (1.2), so an agent editing the table through `prefs.set` alone (R10 2.3's three calls) gets the same rule the dialog gets.
4. `apps/cli/src/commands/prefs.ts` is a new file B5 wrote because the acceptance line `turboslide prefs set /units cm && turboslide prefs get /units` needs a command parser and no lane's "Owns" row names it; its route in `cli.ts` is the integrator's (request 2). The file follows `commands/deck.ts`'s `set` (the value as JSON then a string, `--unset`).
5. The public folder's names: `LICENSE` in capitals beside `index.aff.gz` and `index.dic.gz`; the packages spell their notice `license`.
