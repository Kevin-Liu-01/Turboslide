# Focus audit: pictures and backgrounds

Auditor for the area "Pictures and backgrounds", focus round, 2026-09-15, against production https://turboslide.vercel.app (round four at commit `ec61c6b`; the scratch deck ids carry 2026-09-16 because the server names drafts in UTC). Headless Chromium through `playwright-core` 1.62.1 from the repository's `node_modules`, Node 24.13.0, viewport 1440 by 900 at device scale 1. No source file was changed and nothing was run against the checkout. The scripts live in the auditor's scratchpad (`focus/images/`) and import nothing from the repository but `playwright-core`; copies of the scripts, the judgement file and every run's log are under `focus/audit-images/scripts/`. The evidence screenshots are under `focus/audit-images/` (run 2 at the top level, the later runs under `run-3/` to `run-8/`); the raw tables are `run-1.json` to `run-8.json` beside them, each with every row's evidence, the console errors and the failed or refused requests of the run.

## Method

Every interaction of the brief was driven through the product's own controls at human speed: the menus and buttons by `data-control` (`packages/chrome/src/menus/model.ts`), the overlay handles by `data-control="handle.<id>.resize.<dir>"`, `.rotate`, `.crop.<dir>` and the frame edge `.ts-frame-edge[data-side]`, the readout `.ts-readout`, the chip `.ts-overlay .ts-select-chip`, the guides `.ts-guide`. The mouse moves in steps with a pause between them, keys land 40 to 90 ms apart, double clicks are the browser's own, drags hold the pointer from down through the move stream to up with Shift or Alt held on the keyboard. Every observed value is read from the DOM and from `window.turboslide.studio` (`describe().state`, `slide.get`, `slide.list`). Files reached the editor three ways: a PNG through the file chooser Playwright answers (`Upload from computer`), a drop dispatched with a `DataTransfer` holding the file (Playwright's documented file drop pattern, the one path headless Chromium offers for a desktop drag), and a real paste (`navigator.clipboard.write` of the PNG, then Cmd V). The pictures by URL were a PNG on a host outside the allowlist (raw.githubusercontent.com), one on the allowlisted public host (upload.wikimedia.org) and one on the company domain (https://generaltranslation.com/api/og-home). Every failed interaction was repeated three times before it was called broken; a pass on a later try, or on another deck after a failure on one, is flaky; an interaction the script could not drive is not driven with the reason. The PDF was read from the download and checked for the `%PDF` header, one `/Type /Page` per slide and `/Subtype /Image` objects.

Eight runs, each on its own deck from `/new` with a second slide added from the toolbar, all trashed through File > Move to trash and Delete forever on `/decks/trash`, and all answering 404 on `/edit/<id>` and `/deck/<id>`:

- Run 1 (`untitled-20260916-gv8b`, 456 s): the four insert paths failed and the script stopped for lack of a picture; its trash card was not on `/decks/trash` within 30 s of the move and was deleted forever on the next look (`cleanup-and-diagnose.mjs`).
- Run 2 (`untitled-20260916-3fma`, 1510 s, 66 rows): the whole brief. Every UI insert path failed on this deck (the mechanism is in the summary), so the picture for the battery was placed through the window API, the same `asset.add` and `block.insert` the dialog dispatches, and every row after that drove the UI.
- Runs 3 and 4 (`untitled-20260916-qbf5`, `untitled-20260916-dquq`): retests. On both, the Image by URL row on the company domain left a refused write card over the editor that Escape does not close, and every click after it hit the card; only their insert, delete and window API dither rows stand.
- Run 5 (`untitled-20260916-5n17`): the New slide click did not take, the draft never had a server record, and the run was stopped; `/edit/<id>` answers 404.
- Run 6 (`untitled-20260916-adfi`, 1186 s, 31 rows): the retests in a safe order, the two URL rows last with the card dismissed after each, the sync state (`revision`, `serverRevision`, `pending`, the room transport) recorded before and after every picture write.
- Run 7 (`untitled-20260916-mtyn`): Image by URL as the first object on a content slide that is not a canvas yet.
- Run 8 (`untitled-20260916-vody`): the horizontal centre snap with no competing edge.

A diagnostic script also opened `untitled-20260916-8e3g` to call `asset.add` on an untouched draft; the draft never had a server record and answers 404.

## The table

One row per interaction. The result is the decisive one across the runs; the evidence names the run, its deck and the row in that run's JSON, and quotes the recorded observation (the sync state, the DOM values, the server's answer, the console). Severity is 3 when the seller cannot complete a top task, 2 a wrong or lost result, 1 cosmetic, 0 for an interaction that works. Need is core (a seller's weekly task per research/07-sales-users.md sections 2 and 3), useful (helps, but a seller finishes without it) or park (rarely needed by a seller, or a designer's tool).

## Summary

### What works

Once a picture is on a canvas slide, the object model around it holds. Selection shows the chip, the eight handles, the ring and a picture toolbar tail. A drag by the frame edge moves the box by exactly the pointer's distance, guides show while dragging and the box snaps to another object's edge and to the slide's horizontal centre line; the arrow keys nudge by 1 px and by 10 px with Shift. All sixteen handle drags (eight handles, plain and with Shift) put the box where the pointer says, show the size readout during the drag and clear it after, and the toolbar's Undo restores the box every time; Alt resizes from the centre; the ring rotates and Undo restores the angle. The whole crop cycle works: double click, the toolbar button or Format > Image > Crop image enters crop mode, the edge handles trim the frame, Enter writes the trim and shrinks the box to the frame, Undo and Redo move the trim both ways, and Reset image removes it. Format options opens from the toolbar with Picture, Adjustments and Dither; the Transparency and Brightness sliders write the adjustment and the picture fades or brightens on the sheet; Adjustments > Reset clears them. Replace image by URL from the company domain swaps the asset and keeps the box. Slide > Change background and the toolbar Background button set a slide colour from twelve swatches or a hex field, Reset to theme removes it, an uploaded background picture covers the sheet at the bottom of the stack when the write lands, and Remove picture takes it away. The slideshow shows the picture and the coloured ground and Escape returns to the editor. File > Download > PDF produced a two page PDF with the picture as an image object in 5.6 s. Delete removes a selected picture. Upload, drop and paste insert the picture in 1.5 to 4.2 s when the room is connected and no write is pending.

### What is broken, and the mechanism seen

1. Picture writes refused as stale, silently (upload, drop, paste, Replace image by upload, background by upload; severity 3, core). The editor's `call` in `packages/viewer/src/Editor.tsx` stamps `asset.add` with `revisionRef.current`, the revision of the document the page holds, while the hosted store is one revision ahead whenever a write is still pending or retained (the sync facts read `pending 1, retained 1` before every refused try). The server function answers `baseRevision N is stale; the document is at revision N+1`; `insertPicture` catches it and returns, so the seller sees nothing, and the Replace path shows the raw sentence in the snackbar. On deck `3fma` the state lasted for minutes: the first upload's asset was accepted by the server (the response carries the asset) but the write never reached the editor, no block was inserted, and every later `asset.add` on the deck was refused. On decks `qbf5` and `adfi` the same three paths landed when nothing was pending, which is why the insert rows are flaky rather than broken. Replace image by upload failed on all six tries on two decks because a retained write was pending at that point of the run each time; the paste and drop that came right after another picture write failed on their first try for the same reason.
2. A picture as the first action on a new deck (severity 3, core). `asset.add` runs server side against the Blob store before the draft's first write has created the deck: the snackbar reads `No deck untitled-… in the Blob store`, and the room is still on the memory tier with the poll transport. A seller who opens a new deck and puts the customer's logo on it first gets a store error.
3. Image by URL (severity 3, core). Three defects stack. The hosted allowlist (`HOSTED_ALLOW_HOSTS` in `packages/headless/src/capture/shared.ts`) admits only generaltranslation.com, prototemplate.com, glyphfield.com and the two Wikimedia hosts, and the refusal tells the seller to pass a CLI flag (`pass --allow raw.githubusercontent.com (SPEC 11 captureHosts)`). The one public host on the list answers the server's fetch with HTTP 403. With an admitted URL on a canvas slide, the dialog's `block.insert` (`packages/chrome/src/dialogs/ImageByUrl.tsx`) sends `{ id, type: 'shot', asset }` with no `pos`; the freeform layout refuses it (`/slots/main/0/pos: Block "shot-…" needs a position box (pos) under the freeform layout`), the editor shows the reject card "A change was not applied" with the mutation JSON, the title row reads "Couldn't save, retrying", every click is blocked until Dismiss, and the fetched asset stays in the deck as an orphan. The same insert on a content slide that is not a canvas yet lands as a flow block. Change background > Choose image > By URL routes into the same insert rather than a covering picture, so it fails the same way on a canvas slide.
4. The Dither controls (severity 2, park). The toolbar Dither button and Format > Image > Dither dispatch `picture.dither` through the shell's generic action path with no slide id, block id or dither field; the snackbar reads `picture.dither: invalid input at /slideId: Invalid input: expected string, received undefined` and nothing is written. The action itself works (the same field through the window API draws the screen) and the Format options Dither section rewrites the preset, so the defect is the wiring of the two controls.
5. Edge resizes (severity 2, core). The shot figure keeps the picture's aspect: after an e drag the picture stood 251.7 css px tall in a 211.5 px box, after n and s drags 42 px short of the box, while corner drags fill it. This is the deferred W7 of hotfix 4 and the seller sees it every time a logo's box is stretched by one edge.
6. Cosmetic (severity 1). The URL dialog's live preview loads every partial address as the URL is typed (151 `ERR_NAME_NOT_RESOLVED` console entries in run 2 and 18 rate limited CSP reports). Escape in crop mode commits the trim the same way Enter does, so a crop in progress cannot be cancelled. The horizontal centre snap caught a 1 px miss but not a 3 px miss and lost to an edge guide on the title box, while the vertical centre snap caught 3 px. ### What a seller needs here

Research 07 puts "swap a customer logo or screenshot" and "insert a new image" among the weekly tasks, with drag to replace and paste as the fast paths, Replace image keeping the frame so the layout survives, Format options for transparency and crop, Change background for one slide, and present and PDF at the end. On production the second half of that list holds: crop, transparency, replace by URL from the company domain, the background colour, present and the PDF work well. The first half is where a seller stops: the picture the seller has on disk or on the clipboard lands only when no write is pending, fails without a word when one is, cannot go in first on a new deck, and cannot replace an existing logo by upload; a URL that is not on the company domain is refused with a developer's sentence, and an admitted one on a canvas slide leaves the editor blocked behind a card. The fixes are small and named: stamp `asset.add` with the room's server revision (or route it through the write queue like every other write) and surface a refusal in the snackbar, create the deck before the first picture write, and give the URL dialog a position box on canvas slides. Under Kevin's directive to keep what works, Image by URL and the Dither controls can leave the toolbar and menus until they are fixed; Recolor is not on production, and the background picture by URL and the materials rows are a designer's tools.
