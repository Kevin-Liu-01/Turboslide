# Judge sales: the return round document read as a seller

Judgment of `docs/RETURN.md` (the return round, 2026-09-18) from the sales user's side, written 2026-09-18. The lens is the seller of `docs/gslides-parity/research/07-sales-users.md`: a person who opens a deck that exists, tailors a few slides per prospect, adds a table or a chart of numbers when the pricing slide needs one, presents over a call and sends a link or a PDF. Four questions were asked of the document: does the return list bring back what a seller would miss (tables, boxes, the formatting rows) and what "worked actually well"; is "make them work a lot better" specified concretely per feature against Google Slides; does anything return that did not work or that nobody measured; is the wording plain. Every claim below names the audit row, the matrix id or the file at `1d3ba31` that proves it (`git show 1d3ba31:<path>`). Nothing was run against production for this judgment; the evidence is the four return audits, `core-matrix.json`, `docs/FOCUS.md`, the research and the production sources.

## Verdict

Revise. The return list is the right list for a seller: tables, the rectangle with a fill and a label, connectors, charts edited in place, the formatting rows, Distribute, Rotate, Group and the Appearance switch all come back, the galleries that draw a box for every preset stay parked, and the table fixes are the five a seller meets in the first minute. The chrome section answers each of Kevin's three chrome sentences with measured pixels and after pictures. The document fails on evidence in six places: the one block Kevin has called a box was never driven because the audit did not open the palette production has; the PDF and PowerPoint rows for the table cell repeat a verdict the audit's own evidence contradicts; a flaky download and four toggles return on the flip alone; the inbox returns on a sentence nobody measured; and the ship outcome of a failed row on a core feature is undefined, so a JPEG defect could park the PDF. Two working rows are parked on grounds the rules do not give, and seven words break the copy rules.

## 2. Is "make them work a lot better" specified against Google Slides

Where the audits found a defect, yes. Tables: five fixes with mechanisms and a "Better than before" paragraph that reads as the seller's task (type a row of numbers with Tab, align the number columns right, add a column, drag a column edge, the same table in the show, the PDF and the PowerPoint). Charts: the grid first in the panel and Edit data opening it, against Google's spreadsheet detour. Shapes: the text colour fix, the light appearance row, the label by Enter and double click. The default view defects of 2.14 (the cover title takes no formatting, a Format menu row marks the whole box, two Cmd+Z for a typed field) are concrete, each with the file and the line, and they are the defects a seller hits on the first slide tailored. The chrome specification (section 4) is the most concrete part of the document: geometry, tokens, states, ARIA and keyboard, each with the before and after picture.

Where the audits found nothing broken, the document writes "No fix" or "return as they are" (2.3, 2.6, 2.7, 2.11, 2.12, 2.16, 2.17) and stops. The directive asks for "a lot better", and the audits name gaps the document drops: View > Mode > Viewing keeps the toolbar drawn in all three modes where Google's Viewing hides it (audit-surface row 56 and the verdict's own note); Clear formatting leaves inline marks with "Nothing to clear" where Google clears them (audit-formatting row 60, severity 1); no row drags a connector's end to a new shape, edits a diagram label or edits word art (2.3, 2.6, 2.7 add them as not driven). For those features "better" is not stated (rejection 10). One more silence: every table, chart and diagram row was driven on the dark appearance only, which 2.2 says for shapes and 2.4 to 2.8 do not say for the objects a seller adds most (rejection 9).

## 4. Is the wording plain

Mostly. The sections are full sentences in sentence case, no em dash appears, no heading ends in a period, the verdict words are the audits' four, and "not driven" is used for every step nobody drove. Seven terms break the copy rules:

- "pill" for the Slideshow button (4.1 "the pill's right edge", 4.3 "the glyph and the pill", the row `chrome.split.collapse-900` "a 58 px pill").
- "the separators law" (4.2) and "the law" (4.2 items, the row `chrome.separators.toolbar-dividers`). The plain word is rule.
- "rhythm" (4.3 heading "The right cluster's rhythm"; audit-chrome uses it too). The plain words are gaps and heights.
- "below the fold" (2.5). The plain words are "out of view".
- "leaks into every download a seller sends" (2.18). "Reaches every download" says it.
- "8 px of air each side" (the row `chrome.separators.toolbar-dividers`). "8 px of space" says it.
- "lane", "lanes", "integrator" (section 6 and every fix). The previous judgment flagged the same words; a reader outside the round cannot resolve "B3". Section 6 defines them, which helps, but the fix sentences of section 2 ("B5 owns them", "B1, severity 0") still read as round jargon.

Section 7's README paragraphs use research 07's naming (Slideshow, Format options, Change theme, Download) and no engineering noun; "the arrow keys work on it" promises the plural where only ArrowDown is specified in 4.1.
