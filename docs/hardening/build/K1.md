## What each push does

**HR-K1#1.** `vercelBlobClient`'s put names a max age when the caller names none on a public store: a year for a twin (`decks/<id>/assets/`, `d/`, `u/`; digest names, never overwritten), 60 s for everything else. Before: production's public store answered `decks/gt-brand/deck.json` with `public, max-age=2592000` (passive GET, 2026-10-09 00:47 UTC, load 144). Pins: `blob-vercel.test.ts` against a stand-in Blob API reading the header the SDK sends; the hosted smoke row `document cache 60 s` on the scratch deck of HR-SD#5, the public host read from the policy's `img-src`.

One note on the year for twins: the store never overwrites a twin (`overwrite: false`), but a few asset names are not digests (`assets/<id>.recipe.json`, page captures `assets/<id>-light.png`), so an asset removed and added again under the same id with other bytes would be served stale from a browser cache for up to the max age. A month carried the same risk before; the spec chose a year.

**HR-K1#2.** `getThumbnail` decides per stored object whether to answer a 302 or the bytes (`storedThumbIsPublic(url)`: false for a `*.private.blob.vercel-storage.com` host, under `TURBOSLIDE_BLOB_ACCESS=private`, and for a non web URL), instead of from `TURBOSLIDE_BLOB_PRIVATE_TOKEN`. Before: the route test over a split client at layout v2 answered `302` to the private URL (load 129). After: 200 `image/png`, no `location`; the public object keeps its 302. The spec's pin said `image/webp`; thumbnails are PNG.

**HR-K1#3.** `newAssetKey()` (22 base64url characters, about 132 bits, first a letter or digit) for every record `recordNewDeck` writes; `keyedTwinsClient` maps a keyed deck's `decks/<id>/assets/<file>` to `d/<id>/<assetKey>/assets/<file>` under every caller, installed in `layoutBlobClient` and the dev blob tier; the viewer payload's asset base is `https://<TURBOSLIDE_PUBLIC_STORE_HOST>/d/<id>/<assetKey>/` for a keyed deck on the blob store (production's CSP `img-src` already names `ggmycvj7j6224ay5.public.blob.vercel-storage.com`). A bundle upload keeps the derived key because its unpack writes the twins before the record.

Deviations from the spec's file list, each for a reason in the code: no change to `upload.ts` (it handles the presigned upload; twin names are minted by the asset writers in materials, headless, logos and the slide import, several of which ignore the put's answer, so the keying happens in the client under them); no `asset.set` rewrite (the manifest keeps `assets/<file>`); no change to `apps/cli/src/records/access.ts` 122 (it synthesizes the record of a checkout folder that exists already, which keeps the derived key by the spec's own rule, and a checkout has no Blob store); no change to `templates.ts` (template folders are not keyed).

**HR-K1#4.** `migrate-storage rekey` between `verify` and `cutover` (copy every twin under the key, verify by etag, then write the key with the etag read; a deck without a record skipped; a deck not yet verified listed under `failed`); `delete` also takes a keyed deck's old twins after a last copy of any written since; `migrationClients` opens the public store by its own token, not the deployment's client; the private token is read as `TURBOSLIDE_BLOB_PRIVATE_TOKEN` or `TURBOSLIDE_BLOB_PRIVATE_READ_WRITE_TOKEN` (the dashboard's name); `docs/hosting.md` section 10 records the stores Kevin connected and the run order.

**HR-K1#5a.** `apps/studio/src/server/stored-files.ts`: a link `/api/download/s.<token>` signed with the download secret (purpose `stored`), naming the store path (only `exports/`, `bundles/`, `builds/` of that deck), the deck, the principal it was minted for and an expiry ten minutes out; the route serves it only to that principal, its aliases or the key's owner (403 otherwise), 410 once expired, 404 for a forged token or a missing file, and streams the file in 1 MB parts through the deployment's client, which routes by the layout (so the link works on either store). Every producer answers the link: the sync export (`storeExportFiles`), the batched merge, the stored copies of a queued job, the web page build (`builtFileLink`), the bundle over the body cap (`storeBundleCopy`). A job record keeps `{ name, bytes, path }`; each poll and each re-sign mints the link for its own caller (`downloadsOf`). The routes pass their own caller (`export.$deckId.ts`, `x.export.$.ts`, the bundle route's ticket identity). Not spent on use: the principal is the capability, and a resumed download asks again. A job record written by this release is not read by the release before it (it carries `path`, no `url`): a rollback in the minutes of a running export answers that export as failed, and the person exports again.

**HR-K1#5b.** `isPublicPath` keeps `d/`, `u/` and `decks/*/assets/` alone; `exports/` and `bundles/` join `builds/` on the private store. After the production cutover only.

**HR-K1#6.** The hosted smoke rows `private document 403`, `twin URL not derivable` (required), `principal index private` (new), and `document cache 60 s` retired. Its readings come from production after the cutover.
