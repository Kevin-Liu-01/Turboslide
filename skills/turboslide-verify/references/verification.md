## Reading a sheet

Read `sheet-<theme>.json` first: `cells` maps each cell box to a slide id and number, so a judgment names a slide by id. Then open the render of the slide named. Render records carry the block boxes, line counts, font sizes and weights; read the structured record before the pixels.

## Judge lenses

One lens each, with stable names: layout, visual consistency and dark mode, copy and case, accuracy, completeness, art direction. Judges read the sheets by cell map first and then the renders, alongside the render records and the lint findings, and return findings at severity 2 and 3 only with evidence and a concrete proposal. A skeptic keeps or drops each finding; fixers work one slide each under a lease and report `verifiedBothThemes` and `residual`.

## Completion rules

- An overflow finding is a failure.
- A severity 3 finding blocks the ship step; the known list (`known-findings.json`) is the honest state of the deck, not a place to hide new findings.
- A resolved export call is not a verified export: read `export-report.json` and require `passed` and `geometryInBounds`.
- A frame timestamp is not an image: read the file and its dimensions.
- A resolved apply is only a React commit: wait for the render before reading pixels.
- A claim about a deck names the revision it was verified at.
