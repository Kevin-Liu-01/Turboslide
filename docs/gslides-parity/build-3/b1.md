### Decisions and deviations, recorded for the integrator and Kevin

1. `text.mark`'s `set` is `RunFlags`, which is SPEC-3 3.1's `RunMarks` plus `b` (the display
   run) and `link`; `clear` takes those keys too. Without them the inverse of a splice that
   removed a bold word or a link could not restore it, and the deliverable is "exact inverses".
   Additive; `RunMarks` itself is unchanged.
2. A replacement splice (`remove > 0` and `insert !== ''`) gives the inserted text the flags of
   the first character it replaces, as typing over a selection does in an editor; a pure
   insertion follows `insertAt`'s rule (the run that ends at the offset, else the one that starts
   there). SPEC-3 3.1 states the insertion rule only.
3. `shiftRange` treats an insertion exactly at an anchor's start as before the anchor (both ends
   move), and an insertion exactly at its end as after it; a replacement whose deletion begins at
   or before the trimmed start lands outside the range.
4. `share.requestAccess` is offered on `mcp`, `http` and `window` (the row's "window and http
   only" is read as the transports beside its `none` CLI cell, since the row also names the MCP
   tool `deck_request_access`; a CLI user holds a key and a role). `admin.migrateStorage` and
   `admin.mail.list` are `cli` and `http` (the row marks MCP none; no chrome surface exists for a
   storage migration or captured mail). `admin.bootstrap` is `cli` and `http` as the row says.
5. The comment writes (`comment.add` to `comment.react`) take an optional `baseRevision`, the
   comments revision, so "every mutating action takes baseRevision" holds and a stale value never
   refuses (5.2). The sixteen writes of `NO_REVISION_WRITES` take none.
6. `Assignment` is `{ to: Mention; by; at; done? }` (08 1.1 wrote `principalId`), because
   `comment.assign` takes a `Mention | null` and an invitation may be assigned before it binds.
7. Threads returned with their resolution carry it under `placement` (08 8 wrote `resolved`,
   which collides with `Thread.resolved`).
8. `principalIdSchema` refuses control and bidi characters only; the three formats of 0.17 are
   `PRINCIPAL_ID_PATTERN` and `principalKind` for callers that want them, and a checkout's file
   store author is `local:<name>` (a fourth form for the CLI's `--author`, to be confirmed with
   B3 on day 2).
9. `legacyAssetKey(deckId)` derives a deterministic 22 character key for the synthesized record
   so two instances agree without a write; the migration gives every deck a random key.
10. The `dither` validator issue carries the block and asset ids before the fixed sentence of
    10.1 (`Block "bg" dithers asset "x": the asset has no continuous source (sourceFile); the
committed twins are already dithered`); the sentence is `DITHER_NO_SOURCE_MESSAGE` verbatim.
11. `textOf` in `shiftAnchors` and `resolveAnchor` read top level blocks only (a group is a tag on
    its members, so every member has its own id; composite children are not anchorable this
    round).

exact flag convergence needs; `spliceText` and `reduce.ts` take it. `titleCase(text, before)` is

10,000 random pairs with pinned flags converge exactly outside two documented classes (a Title

pairs without flags converge on characters with flag differences only on inserted spans, 1,000
pairs run through `applyMutation` on the worked document, and a two client interleaving
demonstration records that concurrent inserts at one offset interleave by the tie rule and stay
converged, the accepted anomaly of SPEC-3 3.5. The reduce test reads
`__fixtures__/text-replace-records.json` (eight recorded round one and two records) and asserts
`text.replace` unchanged; the comments test runs 2,000 splices through `shiftAnchors` and asserts

### Decisions and deviations, recorded for the integrator and Kevin

- The comments filter flag is `comments --author-id <who>`, not `--author <who>` as SPEC-3 12
  spells it, because `--author` has been the CLI's principal flag since round one and the parser
  cannot carry both meanings on one command. The action input is unchanged (`author`).
- `share rotate-link` mints a new link record and revokes the old one (SPEC-3 6.4 "rotation mints
  a new record"); the answer carries the new `link` and its URL once.
- A checkout without a persisted access record treats every caller as the folder's holder (owner)
  until the first `share.*` write persists the record (SPEC-3 6.9, 09 1.6); after that the owner is
  fixed and every other principal reads its grant. The comment tests write before any share write,
  so every principal is an owner there; `share.test.ts` covers the 403 and 404 sentences after the
  record exists.
- `share.get`'s partial view (a caller without the `share` right) carries `revision`, so a grantee's
  `accept-ownership`, `decline-ownership` and `claim` base on the current record.
- `account.me` answers `principal.kind: 'local'` on a checkout; `principalSchema` in `actions.ts`
  admits `local` beside `anonymous`, `account` and `agent` (an optional widening; the hosted answer
  is unchanged).
- `version.diff` refuses `from` after `to` (TypeError) and a `to` past the current revision
  (RangeError).
- `picture.materialize`'s write path stays behind `StoreActionDeps.materialize` because
  `packages/effects/package.json` does not export `./dither` or `./dither-io` yet; `--dry-run` and
  `--prune` work, and a write without the binding answers the sentence naming the pipeline (exit 2).
  The fixture deck therefore carries no materialized variant and `picture/plate-clear` reports at
  severity 1 on `background-dither` until `turboslide picture materialize` runs, which the README
  says.
- `slide background-material` runs through the materials package's `captureMaterial` binding; the
  dither test accepts either a capture or the refusal that names the missing renderer.
- The `text.splice` `flags` field is the exact flag convergence rule; without it the inserted
  characters inherit the run they land in and two clients may differ on flags alone (documented
  in `transform.test.ts`).
- `deck.watch` over the file store long polls `fs.watch` through the store's `watchDeck`;
  `deck follow` mirrors a hosted deck through `version.list`, `deck.info` and `deck.watch` on the
  remote and writes byte identical records into `decks/<id>`.
- `apps/cli/src/record-actions.ts` carried one raw control character inside the regular expression
  literal of the bidi and control character class; the class is spelled with `\u` escapes now,
  which is why `grep` misread the file as binary during this stage.
