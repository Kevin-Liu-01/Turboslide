### Deviations

- The theme button's real cost. DESIGN.md 8.1 estimated 2 to 3 KB in the route chunk. The shared
  `ThemeButton` renders through `ToolButton`, which imports the editor's whole icon table, so the
  route now loads `ThemeButton` (1,608 B), the icon table's chunk (51,136 B decoded, 14,712 B gzip)
  and `ToolButton.css` (465 B) before `load`. The route chunk stays 53,248 B and every gated budget
  holds (the shared script is reported, not gated), but the first screen carries about 15 KB gzip
  more script than before. Requests below.
- The navigation's motion words stay "Pause Motion" and "Play Motion" in this push: `copy.ts` is on
  the seam list of DESIGN.md 10.0 and `design/round` holds no "DR-seam" merge yet. The sentence case
  names "Pause motion" and "Play motion" of DESIGN.md 8.1, the removal of the unused Light and Dark
  words and their test land in DR-D4#1b after the seam (the patch is ready).
- The sprite file: the module and its test land here; the hashed file joins `assets.json` with the
  first band chunk that draws from it, so no file is served that the page never requests. The
  features table and the footer's glyphs are in the document, where a `<use>` of a sprite would
  request the file before the first scroll, so they stay masks.
- `live/index.ts` is V2's file in LANDING.md's lane table; the registry moved to `live/bands.ts` as
  DESIGN.md 8.16 directs overflow of the core to a band chunk. `registerBand` left the core (no
  caller outside it); LANDING.md 6.3's sentence naming it is stale.
- The radius row's tooltip clause reads the shared tooltip plate, which D2's working tree draws as
  `.pt-float` (6 px) and HEAD still draws square; the row passed on the working tree and holds once
  DR-D2#2 lands.

### Requests

- D2 (`packages/chrome/src/ThemeButton.tsx`, `ToolButton.tsx`): a `ToolButton` drawn with children
  and no `icon` (the theme button) still imports `icons.tsx` through its `Icon` import, so `/home`
  loads the editor's 51 KB icon table for one text glyph. Either `ThemeButton` renders the `.pt-ib`
  button with `tipProps` itself, or `ToolButton` takes the glyph from its caller.
- The integrator (`apps/studio/vite.config.ts`, `vite.deploy.config.ts`): every dynamic import of
  `/home`'s live core lists the route's static files (the theme button, the icon table and its
  stylesheet) to preload, which the route has already loaded; a `build.modulePreload
  .resolveDependencies` filter for the landing's live chunks would leave them out.
- D1 (`packages/lint/src/brand/source.ts` or `config.ts`): `css/z-index` reads two inline values of
  the landing's live code that order a slide's own content inside the sheet's stacking context
  (`live/paint.ts` 898, a block brought to front at 20 over the renderer's `order + 1`;
  `live/theme.ts` 92, the printed field's canvas at 10). Either the rule treats an inline z-index
  set on slide markup as local order, or the two lines are accepted, before DR-D1#5 enforces it.
