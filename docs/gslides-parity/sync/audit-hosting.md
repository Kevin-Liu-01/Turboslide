## 2. The plan, with Kevin's decisions and a default for each

### (a) The team project and how it deploys

Default: create `turboslide` on `general-translation` (root directory `apps/studio`, Node 24, Fluid compute, `iad1`; `apps/studio/vercel.json` carries the build and install commands, so the dashboard's Framework Settings stay at their detected values), connect `Kevin-Liu-01/Turboslide` with production branch `main`, and ask a team owner to switch the project's Git Sources rule from Inherit to Override and add `kevin-liu-01/Turboslide` for production and preview, the way `prototemplate` was handled by 2026-09-18. Kevin tries the Override switch himself first; if the dashboard refuses a Member, the owner does it. Reasons: no pipeline to run or maintain, preview deployments per pull request come with the Git integration, every deploy carries the commit it was built from, and the team already runs one project this way. The personal project must stop building from the same pushes (section (e)).

Alternatives, in the order to fall back: (1) GitHub Actions in `Kevin-Liu-01/Turboslide` running `vercel pull`, `vercel build` and `vercel deploy --prebuilt` with a `VERCEL_TOKEN` Kevin creates on his account scoped to the team and `VERCEL_ORG_ID` `team_8oC6z09EmYEXHlv0GgC6Gucu`; the team has no Deployment Sources rule, so a CLI deployment is not refused by policy, but whether the Git Sources rule also reads a CLI deployment's git metadata was not tested and would be learned on the first run; Actions minutes are free on a public repository; the workflow adds one file beside `check.yml`. (2) Transferring the repository to `github.com/generaltranslation` (the organization has public repositories, GitHub redirects the old address, Actions secrets move): heaviest, and it changes the address of a public repository Kevin has linked from the README and the product page. (3) A mirror repository: two sources of truth, last.

### (b) The store

Default: transfer `turboslide-decks` to the team instead of copying it. The store id, the public host, every twin URL a browser holds, every export and bundle URL in a record, and `TURBOSLIDE_PUBLIC_STORE_HOST` stay what they are; nothing is copied and nothing needs a hash. Before touching the real store, Kevin rehearses on a scratch store he creates on `kl01s-projects` (one object put through the CLI, the store transferred to `general-translation`, then the old token tried once and the object URL fetched once), because two facts decide the cutover and the docs do not state them: whether the personal deployment's baked token keeps working after the transfer, and whether a store connected to a project can be transferred without disconnecting it first. If the token survives, the two deployments serve one store for the minutes between the transfer and the redirect, which the store's conditional commits already allow between instances, and the cutover has no freeze at all. If it does not, the freeze is the gap between the transfer and the team's redeploy with the new token (the team's single build slot, queued behind `dashboard`, `landing` and `admin` under `WAIT_FOR_NAMESPACE_QUEUE`, plus a build that traces Chromium into eight 87 MB function directories; unmeasured at the audit and recorded at step 2 of the cutover in `docs/HOSTING-MOVE.md`; the "three to five minutes" this sentence carried until 2026-09-20 was a guess, corrected after judge-operations rejection 7), during which the personal deployment's writes fail as 5xx and the room client keeps the pending edits and retries (`packages/realtime/client/room-client.ts` 1206 to 1217).

Fallback, if the rehearsal refuses the transfer: the copy. A script `scripts/blob-copy.mjs` (not written this round) reads `SOURCE_BLOB_TOKEN` and `TARGET_BLOB_TOKEN` from the environment, lists the source with `list({ limit: 1000, cursor })`, and for every object reads it with `get(..., { useCache: false })` plus one `head` for `contentType` and `cacheControl`, then `put`s it under the same pathname with `addRandomSuffix: false`, `allowOverwrite: false`, the same content type and `cacheControlMaxAge`, and compares the returned etag with the source's (`packages/store/src/migrate.ts` 251 to 263 is the pattern; an object whose etags differ is fetched from the target and compared by md5 of the body, since a multipart upload's etag is not the body's md5). `--verify` re-lists both stores and compares counts and etags per prefix; `--skip exports-older-than=1d,presence` leaves out the 921 export files older than a day (302.4 MiB, no job record names them, the records are pruned at a day) and the 4,219 presence, pulse and copies sidecars (29.9 MiB, per instance state that regenerates). That leaves about 12,000 objects and 1.0 GiB; at eight in flight and about 0.3 s per object the pass runs about eight minutes, the whole store about eleven; the listing alone took 9.1 s. Blob costs of the copy: about $0.07 of data transfer, $0.09 of advanced operations and a cent of simple operations. `TURBOSLIDE_PUBLIC_STORE_HOST` becomes `<new store id lowercased>.public.blob.vercel-storage.com`. The write freeze for the copy's delta pass is the redirect flip itself (section (f)), because the product's own freeze does not hold on production (item 8 in the table): a WAF deny is the wrong tool since a 403 makes the room client return the author's edits as refused (`room-client.ts` 1219 to 1230), while a 429 or a 5xx keeps them pending.

The old store stays until the migration is verified and Kevin deletes it (with the transfer there is no old store; the rollback is the transfer back).

### (e) The personal project at zero cost

Production becomes one static deployment with no functions, no store, no environment variables and no build. Kevin deploys it from a folder outside the monorepo (or from `hosting/redirect/` committed this round) holding two files:

`vercel.json`:

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": null,
  "redirects": [
    {
      "source": "/:path*",
      "destination": "https://turboslide-general-translation.vercel.app/:path*",
      "permanent": true
    }
  ]
}
```

`index.html`: one line naming the new address, so the deployment holds a file and the root answers something if a redirect ever fails to match.

Project settings before the deploy (Kevin, dashboard): Git, disconnect the repository (so pushes to `main` never build here again; `"git": { "deploymentEnabled": false }` is the alternative if the connection stays); Build and Deployment, Framework Preset Other, Build Command override on and empty (the build is skipped), Output Directory override on and empty, Root Directory empty; Storage, disconnect `turboslide-decks` (moot after the transfer); Speed Insights and Web Analytics off. Then `vercel link --project turboslide --scope kl01s-projects` in that folder and `vercel deploy --prod`. The environment variables stay for the rollback window (a week) and are then removed, which retires the old secrets.

Acceptance: `curl -sI 'https://turboslide.vercel.app/edit/abc?x=1'` answers `308` with `location: https://turboslide-general-translation.vercel.app/edit/abc?x=1`; `curl -sI -X POST https://turboslide.vercel.app/api/actions/deck.info` answers `308` (the method survives a 308; the bearer does not: `apps/cli/src/remote.ts` `remoteAction` sends `Authorization: Bearer` with fetch's default redirect mode and Node's fetch strips `Authorization` on a cross origin redirect, so an agent's old host entry answers 401 on the team host until `turboslide login` for the new origin; the header-less `curl` proves the 308 and nothing about the bearer; corrected 2026-09-20 after judge-operations rejection 3); `vercel inspect https://turboslide.vercel.app` lists no `λ`; the project's Usage page shows zero function invocations and zero active CPU from the next hour; edge requests for the redirects fall inside the flat rate CDN tier (1 million per month) the team already has. What stays: the `kl01s-projects` platform fee of $20 per month, which is the team's, not Turboslide's.

### (f) The cutover order

1. Kevin's rehearsal on a scratch store (section (b)): learn whether the token survives and whether a connected store transfers. Ten minutes.
2. The team project exists, is connected, and its Git Sources override is in place; the environment variables of (c) are set; a fresh empty store `turboslide-staging` is connected for the gate; `main` deploys; `node scripts/hosted-smoke.mjs https://turboslide-general-translation.vercel.app --token-env TURBOSLIDE_TOKEN --template-copy` passes and `node scripts/probes/core-gate.mjs --base https://turboslide-general-translation.vercel.app --parked docs/gslides-parity/focus/ship-<commit>.json` passes twice (the gate makes its own scratch decks and cleans them up).
3. A thirty minute window announced to the sellers.
4. Disconnect `turboslide-staging` from the team project; transfer `turboslide-decks` to `general-translation`; connect it to the team project; read `vercel env ls --scope general-translation` and confirm `BLOB_READ_WRITE_TOKEN` is on production (connecting adds the OIDC variables, not the token; corrected 2026-09-20); redeploy the team's production so the token is in the deployment. Smoke on the team address: `/decks` lists the 72 decks, one opens at its revision, `deck.info` over `/api/actions` with the new bearer carries `counts.snapshots`.
5. Publish a WAF custom rule on the personal project: hostname `turboslide.vercel.app`, action redirect to the team address (a 307, effective at once, no deploy). Open tabs do not follow it: the redirect is cross origin, `apps/studio/src` sets no `Access-Control-Allow-Origin` header and the client posts with fetch's default redirect mode, so the browser refuses the redirected POST and stream under CORS, the client goes offline (`room-client.ts`, the lost answer path) and its queue stays in the old origin's IndexedDB; the drain of `docs/HOSTING-MOVE.md` section 5 runs before this step (corrected 2026-09-20 after judge-operations rejection 1).
6. Deploy the static 308 deployment of (e) to the personal project; when `curl` reads 308 from the edge, delete the WAF rule.
7. Watch: the personal project's Usage reads zero functions from the next hour; the team project's functions take the traffic; the store's writes continue (the newest `deck.json` etag moves when a seller edits).
8. After a week: remove the personal project's environment variables; the copy fallback's old store, if it was used, is deleted by Kevin once `--verify` read equal counts and etags.

With the copy fallback, step 4 becomes: the full copy while production is live, the WAF redirect (step 5) as the freeze, the delta copy of objects whose etag changed since the first pass (never over an object the team has already rewritten), then step 6.

### (g) The rollback

Delete the WAF redirect rule if it is still there and promote the previous production deployment of the personal project (Instant Rollback in Deployments); its environment variables are still set for a week, so it runs as before. The store: with the transfer, transfer `turboslide-decks` back to `kl01s-projects` and reconnect it; if the rehearsal showed the token dies at a transfer, redeploy `main` on the personal project afterwards so the new token is in the deployment (about ten minutes end to end, no edit lost). With the copy fallback the old store is untouched and the promote alone rolls back, losing the edits made on the team since the flip.

### (h) The split of work

Kevin: the rehearsal, the team project and the repository connection, the request to an owner for the Git Sources override (and the on demand build concurrency if the single build slot queues too often), the store transfer and connection, the environment variable values (generated locally, never in a file), the `ANTHROPIC_API_KEY`, the address decision and the registrar record if a subdomain is chosen, the WAF redirect rule, the static deployment's `vercel deploy --prod`, the Speed Insights and Web Analytics toggles, the deletion of the old store, `turboslide login` for the new origin. The pipeline (this round's builders): `docs/HOSTING.md` from this audit, `hosting/redirect/vercel.json` and `index.html`, `scripts/blob-copy.mjs` with `--verify` and `--skip` as the fallback, the hosted smoke and core gate runs against the team address once the bearer is in the environment, the kill switch fix (item 8) and the export retention (item 12) as code changes with their tests, and the README's address change in the same commit as the cutover.
