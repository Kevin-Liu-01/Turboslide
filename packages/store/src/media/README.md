# The media parsers

The intake of audio and video files (gslides-parity SPEC-5 0.18, 1.1 rule 6, 3.3; R11 1.1 to 1.5), framework free: no Node import, so the same modules run in the function, in the CLI, in the browser's drop path and in the bundle scan. The picture path has `sniffImage` before `sharp` sees a byte; this folder is the same rule for media, with Turboslide's own parsers in place of a dependency (R11 1.3's library table records why: `music-metadata` is a fitting test oracle, not a runtime dependency for untrusted input inside the function).

| Module       | What it reads                                                                                                                                                                                                                                                      | Bounds                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| `sniff.ts`   | The container by signature: `ftyp` at bytes 4 to 7 (ISOBMFF, with the major and compatible brands), the EBML header with its `DocType`, `ID3` or a Layer III frame sync confirmed by a second frame (mp3), `RIFF WAVE`, `RIFF AVI `, `OggS`, `fLaC`, the ADTS sync | the first 64 KB for the frame search                        |
| `isobmff.ts` | `ftyp`, `moov` > `mvhd` (version 0 and 1), `mvex` > `mehd`, `trak` > `tkhd` (the 16.16 size), `mdia` > `hdlr`, `mdhd`, `stbl` > `stsd` (the codes, the coded size, the sample rate and channels); a `moov` after `mdat` is reached by skipping `mdat` by its size  | 64 levels, 20,000 boxes, a `mdat` cut short is tolerated    |
| `ebml.ts`    | The header's `DocType`, `Segment` > `Info` (`TimestampScale`, `Duration`) and `Tracks` > `TrackEntry` (`TrackType`, `CodecID`, `Video` size, `Audio` rate and channels); an unknown Segment size (a live muxer, a MediaRecorder capture) runs to the end           | stops at the first `Cluster`, 16 levels, 20,000 elements    |
| `mp3.ts`     | The ID3v2 tag (synchsafe size, the footer flag), the frame header tables (MPEG-1, 2, 2.5; Layers I to III), `Xing` and `Info` with the LAME delay and padding, `VBRI`, and the exact frame walk when no header states the count                                    | the walk stops at the first byte that is not a frame header |
| `wav.ts`     | `fmt ` (PCM 1 and IEEE float 3, plain or `WAVE_FORMAT_EXTENSIBLE` through the sub format GUID), `data` (clamped to the bytes present); ADPCM, MP3 in WAV and every other tag refused with the tag named                                                            | 1,024 chunks                                                |
| `info.ts`    | One `MediaInfo` (kind, format, mime, extension, container, bytes, duration or null, size, codecs, sample rate, channels, brand, live, the per engine playability of R11 1.1) or one `MediaRefusal` sentence; `mediaFormatProblem` is the bundle scan's name rule   | never throws on bad bytes                                   |
| `bytes.ts`   | The bounds checked readers and `MediaParseError`                                                                                                                                                                                                                   |                                                             |

The duration is what ffprobe reports for the same bytes within 20 ms (`fixtures/media/facts.json`): an MP3 with an `Info` or `Xing` header and a LAME tag has its encoder delay and padding subtracted, which is why a one second tone reads 1000 ms and not the 1152 ms its sixteen frames hold, and a bare stream is walked frame by frame. A WebM without `Duration` answers `null`, which the browser fills through `media.info --refresh` (R11 1.3).

The tables every content type list reads are the schema's (`@turboslide/schema/blocks/media`: `MEDIA_MIME_BY_EXTENSION`, `MEDIA_KINDS_OF_MIME`, `MEDIA_BYTES_MAX`, `DECK_MEDIA_BYTES_MAX`, `mediaAssetFile`, `effectivePlayback`, `playbackProblem`, `formatDuration`) and the asset record's mimes and extensions are `@turboslide/schema/assets` (`MEDIA_MIMES`, `MEDIA_EXTENSIONS`).

Tests: `cd packages/store && ../../node_modules/.bin/vitest run media`, one file per module over `fixtures/media/**` (the generation is `fixtures/media/README.md`).
