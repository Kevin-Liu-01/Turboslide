## 2. The Slideshow split button: Enter and Tab

Read with a `keydown` listener on `window` in the bubbling phase, registered after the page's own listeners, so `defaultPrevented` is what the page left behind. Both runs read the same values.

The mechanism, read from `1d3ba31` and consistent with rows 7 to 12:

- Enter. `useEditorKeys.ts` 156 to 257 is a `document` key down listener. A bare Enter outside a field matches the key table's `commit` binding (`menus/keys.ts` 729 to 736, `K('Enter', 'Enter')`, scope canvas). `findItem('commit')` finds no menu item (line 238), so line 252 calls `h.runBinding(binding, event)`; `EditorShell.tsx` 1476 to 1481 answers `key.commit` with `current.editor.exitCrop()` and `true` whenever `current.editor?.exitCrop` exists, and the stage's handle always carries it (`Editor.tsx` 3118, `exitCrop: () => exitCrop(true)`; `exitCrop` returns at once when no crop is open, 2189 to 2191). Line 253 then calls `event.preventDefault()`, which cancels the browser's Enter activation of the focused button (a button activates on Enter's key down and on Space's key up, which is why Space works, row 9, and Enter does not, rows 7, 8, 12). A crop is never open in the title row, so the handler swallows the key for nothing.
- Tab. `Editor.tsx` 3241 to 3256 is the stage's window capture listener: for a Tab with no modifier, when an object is selected (`current !== null`) it cycles the selection and stops the event whatever element has the focus (the `fromControl` return at 3257 comes after it), so the browser's focus order never runs from the Slideshow half to the chevron (row 11); with nothing selected the branch returns at 3248 for a target outside the stage and the order runs (row 10). Audit-chrome row 16's two runs differed by whether an object was selected.

With audit-surface row 29 (try 1 cancelled, try 2 the file) the count is three cancelled of six attempts on three decks. The code path is `apps/studio/src/editor/controller.tsx` 2631 to 2650: `build.run` runs the build, then `triggerDownload(built.download.url)` (921 to 929) appends an anchor with `download=""` to the body, clicks it and removes it at once; the url is a signed one time download token (`apps/studio/src/server/tokens.ts` 105 to 114, `TOKEN_TTL_MS` 15 minutes, a nonce spent set at 117 onward). What cancels the browser's download between the click and the first byte was not identified by this drive: the route answered 200 for the same url a moment later (row 16), so the file and the token were good. The download that failed carried no file name (the token string), the one that worked carried `<deck>.html`, which says the browser dropped the request before the response's `Content-Disposition` reached it.
