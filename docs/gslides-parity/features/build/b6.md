### 5. Notes and decisions

- The licence classes (4.6, question 2): open is CC0, MIT, Apache, BSD, ISC and Unlicense (the store cache); credit is CC BY and CC BY-SA; unchanged is CC BY-ND; copyleft is MPL, GPL, LGPL and AGPL; everything else, a non commercial clause (`CC-BY-NC-*`), `PD`, `TODO`, brand-use, Trademark, Fair Use, Proprietary, Custom, Unknown and the free text sentences, is the brand's own terms. The tint is on for open, credit and copyleft (each allows a derivative) and off for unchanged and own; `PD` is not cached because the spec's list is explicit. Kevin may widen either list in one function each (`licenceClassOf`, `tintAllowed`).
- The appearance rule prefers a brand's own light and dark files over a tint, so GitHub on a dark deck inserts its `light` file, never a tinted mono; the row `logos.insert.mono-tint` names GitHub's mono, which the rule reaches only for a mark without the pair (Stripe, Figma). A tinted mono is a light and dark pair of twins, each in the kit's text colour of its appearance, and its `sourceFile` carries the deck's current appearance's colour.
- A non open mark's `sourceFile` carries the attribution `<desc>` too (4.7 "the deck's sourceFile carries it too"); "unmodified" for CC BY-ND means no tint and no other change to what the file draws.
- The search route is open to any caller who can reach the server (a read of public data, the same rows a browser can read from thesvg.org); the refresh takes the two credentials; the insert takes the page's session under `authorize()` or the bearer.
- In fixture mode a fresh instance builds its index inline on the first read (ten marks), so the preview's spec project needs no refresh call first; in network mode nothing builds until `POST /api/logo/refresh` runs (the cron, the ship step or a marketer's `turboslide logo refresh` once R11 lands), and the search answers `updatedAt: null` until then, the foot reading "Logos from thesvg.org" with no date. A lane driving the picker on a network dev server runs `curl -X POST -H 'Authorization: Bearer <token>' http://localhost:<port>/api/logo/refresh` once (about a minute for the reads pass on a fast connection; the budget resumes otherwise).
- The store budget (docs/SYNC.md 4, 6.1): the index is one `get` per instance on the first read and one `head` at most an hour on a request; a discovery (an unavailable variant, a newly cached open mark) persists at most once a minute per instance; a tile of a cached open mark is one `get`; an insert is two or three `put`s of asset files plus one record write; nothing here polls or starts a timer. The refresh's own writes are the cron's once a day.
- The tmp store's state folder lives under the overlay (`TURBOSLIDE_OVERLAY_DIR`, `/tmp/turboslide` by default, shared by every tmp dev server on the machine); B6's server ran on its own overlay so no other lane's overlay changed.
- The insert on a slide that is not a canvas converts it through `slide.toCanvas` first (a separate write, as `slide.setBackgroundPicture` does), so an agent's insert on a fresh deck's title slide is two revisions; the editor's path (`insertLogoAsset`) is one commit.
- The size rule is repeated in `Editor.tsx` because the viewer cannot import the chrome (the one way direction of the packages); the numbers are the model's and both are tested.
- P1 (4.5, `logos.kit.find-a-logo`): not landed. The condition of section 1 (the lane's P0 rows green on its own preview run) cannot be read on the checkout, and the button needs B1's kit target (R12) to do what its words say; landing it without the target would insert a picture instead of setting the kit. The handler side exists (`logo.insert { kit: true }`), tested in `logos.test.ts`.
- What is not driven here and why: the dialog's gestures (B1's dialog and B4's drivers; the menu rows are R1), the chip word (R6), the Tailor button (R7), the CLI clause (R11), MCP (the tool list is generated at the merge), and the rows on production (the ship's runs).
