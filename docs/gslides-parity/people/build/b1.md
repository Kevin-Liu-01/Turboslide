### Finding 2, fixed: `people.comment-departed-guest` on the blob tier

The mechanism, read in the code rather than guessed: `account.setName` writes the typed name onto the principal's deck index (`auth/actions.ts` 416 `propagate` awaits `access.noteDisplayName`, so the name is on the Blob store before the action answers) and drops the index row from the writer's instance cache; `access.ts indexFactsFor` keeps one row per principal for 5 s (`LINK_GRANT_TTL_MS`) and the drop bus is process local, so an instance that read the guest's row before the write (the guest's join, a presence post, the link exchange all read it) answers the nameless row for up to 5 s. The spec's guest types the name, comments and leaves, and A reloads about 4 to 7 s after the `setName` write; when the instance that serves A's reload is one that held the row, `resolvePrincipalId` (through `aa3afbe1`'s `carriedFacts`) read the cached row, the payload's view was the label, and the row read "Tantalum 753" with no trust word about 2 s after the reload. Two green and two red on one tree is that window.

The fix (`apps/studio/src/server/room.ts` `carriedFacts`, 12 lines): the resolver drops this instance's cached row (`dropLinkGrantCache(principalId)`, exported by `access.ts` since the focus round) before it reads the index, so a person whose record on this instance is absent or nameless is read from the store (the blob tier's proven read; a file read on a checkout); the name's read fills the cache and the choice's read takes it, one store read instead of two. The cost is one index read per such person per boot on the blob tier; `requestIdentity`'s read for the request's own principal (every presence post) keeps the cache, so the own chip rows' class of PEOPLE.md 6.4 is unchanged by this. The stored comment author's `label` is not carried into the view: it is the author's name at the write, which on the blob tier can be the label too (the writer's instance reads the same cache), so the index past the cache is the one carrier every surface agrees on.

The test (`room.test.ts` "resolvePrincipalId reads the name another instance wrote onto the deck index past this instance cache"): a fresh anonymous id resolves to its label, the index is written through `indexStore().update` without the writer's cache drop (another instance's write as this one sees it), and the second `resolvePrincipalId` reads "Noor Haddad" with `trust: guest`. The control run without the fix read the label ("Felt 610"); with it, the name. The folder the file index store writes under `.turboslide/users/` is removed in the test's `finally`.
