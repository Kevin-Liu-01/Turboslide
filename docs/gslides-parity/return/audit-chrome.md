# The chrome rows: separators, the title row's right cluster and the Slideshow split button

Audit of the editor's chrome rows on https://turboslide.vercel.app (commit `1d3ba31`), driven 2026-09-18 between 14:58 and 15:26 PDT with headless Chromium (playwright-core 1.62.1 from the repository root) at 1440 by 900, at human speed (mouse moves in steps, 40 to 90 ms per key, real double clicks, real drags), on three scratch decks created from `/new` and each trashed through File > Move to trash, deleted forever on `/decks/trash` and confirmed 404 on `/edit/<id>` and `/deck/<id>`: `untitled-20260918-eam3` (run 1), `untitled-20260918-pi28` (run 2, the main table) and `untitled-20260918-vnbg` (run 3, the before and after pictures). The scripts are `audit-chrome/audit-chrome.mjs` (runs 1 and 2) and `audit-chrome/after-pictures.mjs` (run 3); they import nothing from the repository but playwright-core. The tables of every run are `audit-chrome/audit-chrome-run1.json`, `audit-chrome-run2.json` and `after-pictures-run.json` with their logs beside them. The pixels (line thickness, colour, contrast) are read from the screenshots by a PNG reader in the script (zlib only), not from computed styles alone.

Run 1 read the show's state through a `state.present` key that does not exist, so its rows 10, 11, 16 and 17 report "present false" for shows that did open; run 2 reads the DOM the way `audit-present` did (`[data-control="present.show"]`) and is the record for those rows. Run 1 also opened its 2x context as a stranger (a fresh browser context is a new anonymous principal, so the deck opened without the save words or the Tools menu); its 2x pictures sit in `audit-chrome/run1-pictures/` and are not cited. Run 2's 2x context carries run 1's lesson: it copies the first context's storage, so it is the owner.

Production boots a fresh browser into the dark appearance (`data-theme="dark"`, nothing stored under `ts-chrome-appearance`); every "boot" measurement below is therefore dark first and light after View > Appearance > Light, which sits behind Tools > Advanced tools. Console errors on every page load: the report only CSP notice "The Content Security Policy directive 'upgrade-insecure-requests' is ignored when delivered in a report-only policy"; run 1 also saw one 502 resource. No page errors.

Severity: 3 the seller cannot complete the task, 2 a wrong or lost result, 1 cosmetic, 0 nothing wrong. Verdict: return (works today and a seller uses it), return after fixes (works or nearly works, the fixes are named), stay parked, not a feature (the row is not a product feature).

## Summary

What works. Every control of the title row's right cluster does its job with the mouse: the Slideshow half opens the show from the current slide and Escape leaves it (run 2 row 10), the chevron opens the Presentation options menu with `aria-expanded` and returns focus on Escape (row 9), Start from beginning opens the show on slide 1 (row 11, a row no earlier audit drove), Presenter view opens the second window on `/present/<id>` (row 12), Share opens its dialog and Escape closes it (row 18), the save words read "All changes saved" and the clock names the last editor (row 20), the comments glyph opens the Comments panel (row 21), Tools > Advanced tools shows the inbox plate and the Appearance rows, and View > Appearance > Light and Dark repaint the chrome at once and store the choice (rows 23, 26, 33, 35, 37, 42). The rows' boundaries all draw one 1 px line in `--pt-hair` where the SPEC 1.2 line law says they should, in both appearances, at 1x and 2x, and at 900 px.

What is broken, with the mechanism seen.

1. The Slideshow split button is two controls, not one (severity 1, the row Kevin's screenshot names). `ToolButton.css` styles `.pt-ib.is-solid` with `border-radius: 8px` on all four corners, `padding: 0 14px`, `gap: 7px`, `flex-direction: row-reverse`, `border-color: var(--pt-ink)` and a hover that inverts the button (transparent ground, ink text). Both halves carry `pt-ib is-solid`, and that selector (specificity 0,2,0) outranks every single class rule in `TitleRow.css` (0,1,0). Measured on production: each half has `8px 8px 8px 8px` corners, the arrow's `border-left` computes to `1px rgb(7, 7, 7)` in the light appearance (ink on an ink ground; `TitleRow.css` asked for `--pt-edge`), so across the seam at mid height the screenshot shows one unbroken 13 px run of ink and no divider; 1 px under the top edge there is a 6 px notch of paper between the two rounded inner corners, 2 px under it a 3 px notch, 4 px under it a 1 px notch. The play glyph sits after the word (`row-reverse`). Hovering one half inverts that half alone while the other stays solid (rows 7, 8, 29, 30). The word sits in `0 14px` padding, not the `0 12px 0 10px` the row's sheet asked for. The arrow half is 30 px wide (28 plus two 1 px borders). Kevin's screenshot is this state in the light appearance.
2. Enter does nothing on either half of the split button (severity 2 for a keyboard user; rows 13, 15, 16 in both runs, three tries each). Space opens the menu on the chevron and the show on the label (rows 14, 17). A button activates on Space at key up and on Enter at key press, so a document level key down listener that swallows Enter explains the split; the listener was not identified in this audit. The candidates read: `useEditorKeys.ts` matches the bare Enter to `keys.ts` line 732 (`commit`, "Exit crop mode", scope canvas) but `runBinding` in `EditorShell.tsx` answers false for it and prevents nothing; `useShellKeys.ts` prevents Enter only after typed digits; the stage's own selection keys were not read. In run 2 a Tab from the label did not move focus to the chevron either (three tries), where in run 1 it did; the reason was not found.
3. ArrowDown on the Slideshow half does not open the menu (row 15, six tries over two runs). The split button pattern has it; nothing in `TitleRow.tsx` handles the key.
4. The notes divider is drawn twice (severity 1). `EditorShell.css` gives `.ts-notes-slot` a `border-top: 1px solid var(--pt-hair)` and `NotesPane.css` gives `.ts-notes` inside it the same, so the seam between the stage and the notes pane is a 2 px line (y 803 and 804; `#3a3a3a` twice on `#070707` in dark, `#d2d2d2` twice on `#ffffff` in light) while every other seam is 1 px. Removing the slot's line leaves one (the after pictures).
5. The Presentation options menu is not aligned to its control (severity 1). The 220 px plate opens at x 1212 to 1432 under a chevron at x 1312 to 1342: the placement code clamps the plate 8 px inside the viewport, so its right edge sits 90 px right of the control and its left edge 100 px left of the chevron (rows 9, 31, the pictures `dark-12-split-menu-open.png`, `chrome/after-light-split-menu-open.png`). Google drops the menu under the control's right edge.
6. A second click on the comments glyph or the inbox plate does not close the panel it opened (severity 1; rows 21 and 25, three tries each). Both buttons carry `aria-pressed="true"` while the panel is open, so they read as toggles, but `onClick` runs `shell.runItem(panel(...))` which opens and never closes; the panel's own X closes it (`aria-pressed` back to false) and Google toggles the pane from the icon.
7. The deck's name is the first burst of the first write (severity 2, outside this area but read in the title row every run). Run 1 named the deck "Chrom" and run 2 "C" while the heading read "Chrome rows audit"; `deck.info` and the title row both show the short name and the Share dialog reads "Share C". The name is derived once when the first write creates the deck and does not follow the heading afterwards. The rename paths themselves passed in `audit-decks` rows 18 to 22.
8. The empty `+N` chip of the presence slot is drawn as an empty 32 by 24 box in `--pt-edge` while nobody else has the deck open (severity 1; row 22 and every right cluster picture). `.ts-presence-slot.is-empty` hides the four chip slots with `opacity: 0`; `.ts-presence-more.is-empty` has no such rule (`presence/presence.css`). With Tools > Advanced tools off the rule and the own chip are also absent (`title.presence.me` is parked), so the slot reads as one stray rectangle.
9. The inbox slot keeps its 60 px with the plate parked (severity 1, a rhythm question rather than a defect). The five fixed slots of SPEC-3 0.43 exist so a join or a notification moves nothing at first paint; with `title.inbox` parked the plate never appears, and the row shows a 76 px gap (8 + 60 + 8) between the comments glyph and the Slideshow button, visible in Kevin's screenshot.

What to bring back and what it needs. The Slideshow split button, Share, the save words, the clock, the comments glyph and the presence chips are in the default view already and stay there; the fixes are the spec in section 5: one wrapper that owns the outline, the ground and the corners, halves that are transparent inside it, a divider token that reads on ink, a hover per half that does not invert, Enter and ArrowDown, a menu aligned to the control, and Share sharing the control height and corner. The Appearance rows (`view.appearance.light`, `.dark`, `.match`) worked on every try in both runs and are the only way a seller in a light office gets light chrome, since a fresh browser boots dark; they should return to the View menu. The inbox plate and the own chip's account menu stay parked (docs/FOCUS.md 3.2); the toggle defect on the inbox is noted for whenever it returns. The separators need one law applied in three places (section 5b): the notes slot loses its line, the toolbar dividers take `--pt-hair-soft` at a fixed 20 px, and a `--pt-hair-on-ink` token joins `tokens.css` for lines drawn over a solid ink ground.

## 2. The verdicts by feature

- Slideshow split button: return after fixes. The show, the menu, Start from beginning and Presenter view work with the mouse and with Space; the control draws as two pills with an invisible divider and an inverting hover, Enter does nothing, ArrowDown does nothing, and the menu is not aligned to it. Section 5a is the fix.
- Share: return. Works; takes the control height and corner of 5c.
- Save words and the Last edit clock: return. Work as in `audit-decks`.
- Comments glyph: return after fixes. Opens; a second click should close.

## 5. The spec

### 5a. The split button as one control

- The wrapper `span.ts-title-slideshow` owns the box: `box-sizing: border-box; height: 32px; border: 1px solid var(--pt-ink); border-radius: 8px; background: var(--pt-ink); color: var(--pt-paper); overflow: hidden; display: inline-flex; align-items: stretch`. The 8 px is the corner `ToolButton.css` gives the solid call to action by Kevin's directive; the outer corners are the only corners.
- The halves are transparent inside it: `.ts-title-slideshow > .pt-ib.is-solid { height: 30px; border: 0; border-radius: 0; background: transparent; color: inherit; flex-direction: row; gap: 6px }`, and the play glyph goes before the word (Google's order). The selectors carry `.pt-ib.is-solid` so they outrank `ToolButton.css` without touching it; the arrow's own rules add `.ts-title-present-arrow` to the chain (`.ts-title-slideshow > .pt-ib.is-solid.ts-title-present-arrow`) so `border-left` outranks the `border: 0` above it (run 2's first version lost that fight; run 3 shows the corrected rule).
- The label half: `padding: 0 10px 0 12px`, the 12 px play glyph, the word Slideshow in `.pt-lb`; at or below 900 px the word leaves and the padding is `0 8px` (28 px wide).
- The chevron half: 28 px wide, `padding: 0`, the chevron at 14 px, `border-left: 1px solid var(--pt-hair-on-ink)`. New token in `tokens.css` beside `--pt-hair`: `--pt-hair-on-ink: rgba(255, 255, 255, 0.26)` on `:root`, `rgba(7, 7, 7, 0.26)` under `[data-theme='dark']`; a line drawn over the solid ink ground, where `--pt-hair` (ink at .18) is invisible. Measured with the equivalent `color-mix(in srgb, var(--pt-paper) 26%, transparent)`: `#474747` on `#070707` (2.17:1) light, `#b5b5b4` on `#f2f2f0` (1.83:1) dark, one pixel at every height (`chrome/after-light-right-cluster.png`, `chrome/after-dark-right-cluster.png`).
- Hover, per half, no inversion: `.ts-title-slideshow > .pt-ib.is-solid:hover { background: color-mix(in srgb, var(--pt-paper) 16%, transparent); color: inherit }` (a `--pt-plate-on-ink` token if the team prefers a token). ### 5b. The separators law

- One token for a row boundary: `--pt-hair`, 1 px, drawn once per boundary by the row named here and by no one else: the title row draws its bottom (the menu bar draws none); the toolbar draws its bottom (the filmstrip and the stage draw no top); the filmstrip draws its right (the stage draws no left); the right panel draws its left; the notes pane `.ts-notes` draws its top and the slot `.ts-notes-slot` draws none (today both draw: remove `border-top` from the slot rule in `EditorShell.css`, keep the pane's, so the handle stays on the one line); the bottom bar draws its top (the filmstrip and the notes pane draw no bottom).
- Vertical dividers inside a row (`.ts-tb-sep` in the toolbar, `.ts-presence-rule` in the title row, the seg dividers) take `--pt-hair-soft`, 1 px wide, a fixed height (20 px in the 40 px toolbar, 24 px beside the 24 px chips) and `margin: 0 4px` in a 4 px gap row (8 px of air each side), so a divider inside a row is lighter than the line between rows. Today the toolbar dividers are `--pt-hair` and read as boundaries.
- A line over a solid ink ground reads `--pt-hair-on-ink` (5a); `--pt-hair` is invisible there.
- Both appearances: a boundary must show in each. Measured today: `#d2d2d2` on white (1.51:1) and `#3a3a3a` on `#070707` (1.77:1); the dark composite is the more visible of the two and no line disappears in the dark appearance. If the light hairline is judged too faint the token moves to `.22` like the dark one; this audit does not ask for it.
- No line is drawn twice and no line stops short: the check is the column scan of `audit-chrome.mjs` (`seamsFromShot`) run on the whole editor picture, which reports the thickness of every seam.
