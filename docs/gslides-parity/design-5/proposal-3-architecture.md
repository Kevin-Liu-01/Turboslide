# Proposal 3, architecture: one document, one schedule, one scene for motion, media, equations, themes and import

Designer 3 of 3 for the Google Slides parity round five, written 2026-09-14 against Turboslide `main` at `d5d7f07` (round three and its hotfix; round four is in the working tree and every code fact below was read with `git show d5d7f07:<path>`). The angle is document and export first: the design starts from the block document (`packages/schema/src/deck.ts`, `blocks.ts`, `assets.ts`), the one string renderer (`packages/render/src/slide.ts`, `stage.ts`, `standalone.ts`, `print.ts`), the two PPTX exports and their OOXML post process (`packages/export/src/pptx/build.ts`, `ooxml/*.ts`, `scene/types.ts`), the present surface (`apps/studio/src/components/Slideshow.tsx`, `packages/viewer/src/present/*`) and the store (`packages/store/src/store.ts`, `templates.ts`), and places every round five capability so that the studio, the CLI, MCP, present mode and every export read one truth. Every schema field, action, renderer change, export change and fixture is named.

Inputs read in full: the eleven reports of `docs/gslides-parity/research-5/` (cited as 01 to 11 with their sections), SPEC-2 section 12, SPEC-3 section 17, SPEC-4 sections 0 and 7, `AGENTS.md`, `MILESTONES-4.md`, and the code named above plus `packages/schema/src/{actions,export,mutations,validate,catalog,canvas}.ts`, `packages/chrome/src/menus/model.ts`, `packages/export/src/{export-pptx,check}.ts`, `packages/viewer/src/present/{presentModel,presentSync}.ts`, `packages/render/src/blocks/render-block.ts`, `scripts/check.mjs`. No web page was read for this proposal; every external fact is cited through the report that read it, with that report's source key, and the reports list their URLs and read dates. Nothing was run, installed or committed.

Rules followed: plain technical English, sentence case, no em dashes, no metaphors, no trailing periods on headings, full sentences in body text. Google Slides is the behaviour reference and its labels and positions are kept where Google has the feature; no Google icon, artwork, template or theme asset is proposed; the glyphs Turboslide draws (the play glyph, the speaker glyph, the person glyph, the equation toolbar) are its own.

Decisions taken before this proposal and not reopened: the block document, the action table, one renderer and the Perfect export stay the foundation; every capability is an action with CLI, MCP and window handlers working on a local checkout and hosted; Google's labels and positions where Google has the feature; the Prototemplate look plus round four's identity; no Google services; motion never changes the Perfect export's pixel identity for a still; media and import respect the security plan; a slide size change is a document level decision the exports follow.

## 1. The one truth, extended

### 1.1 The rules

1. The document is the truth. A transition, an animation, a media reference, a page size, a language, a theme edit and an equation are fields of the deck or the slide, written through `slide.set`, `deck.set`, `block.insert` and `block.set` as today, so undo, version history, the operation stream, `deck.pack`, `deck.push` and `diff.run` carry them with no new mutation op. The one new op is none: `MUTATION_OPS` is unchanged.
2. The renderer emits the resting state (0.1). What a surface does with motion or media is a layer over the rendered nodes, addressed by `data-block` and `data-media`, never a second render path.
3. The schedule is computed once (0.2). `compileMotion` is pure, tested in Node, and its output is the input of the show, the standalone script, the PPTX timing writer and the ODP animation writer. Every writer's test compares its element tree against the same schedule fixture.
4. The scene is the one reader for the writers (0.4). `extractScenes` reads the document and the rendered DOM; `pptx/build.ts`, `odp/build.ts` and `svg/write.ts` read the scene. A field the exporters need (the schedule, the media records, the equation OMML, the page, the theme CSS, the language) is a scene field, so a fourth writer would read the same object.
5. Every capability is an action (SPEC 7.1). The CLI flags are the input's fields, the MCP tool takes the same object, the window handler runs the same store action over the editor's store, and the hosted `POST /api/actions/<id>` runs it server side. A control in a dialog or panel writes exactly one action.
6. The security plan applies to every byte that enters: the store's zip guard, a signature sniff before a decoder, per tier caps, `safeFetch` for URLs, the link scheme filter, no external entities in XML, no `<math>` from the escape block.

```ts
// packages/render/src/motion.ts
export type MotionSchedule = {
  steps: MotionStep[]; // steps[0] plays on entry, the rest on clicks
  hiddenAtStart: BlockId[]; // entrance effects hide their block first
  transition: { kind: TransitionKind; durationMs: number } | null;
};

  effects: { animation: Animation; delayMs: number; paragraph?: number }[];
  durationMs: number; // max(delay + duration) over the effects
};
export function compileMotion(
  slide: Slide,
  blocks: Block[],
  paragraphs: (blockId: BlockId) => number,

  schedule: MotionSchedule,
  sheet: { width: number; height: number },
```

Semantics (05 section 4, restated as the contract every consumer's test pins): a `click` opens a new step; `withPrevious` joins the current step at delay 0; `afterPrevious` joins the current step at the previous effect's end; a first `afterPrevious` or `withPrevious` joins step 0; `byParagraph` expands to one effect per paragraph, each its own step under `click`, chained under `afterPrevious`, together under `withPrevious`; entrance effects add their block to `hiddenAtStart`; a `playMedia` effect's duration is the media's remaining length after the trim, or the step's length when it loops; an animation whose block has no rendered node is skipped and named in the residual. `paragraphs(blockId)` is supplied by the caller: the renderer's `.para` count and list item count in the browser, the scene's `SceneLine.paragraph` count in the exporter, so the count is the same number on both sides.
