### Deviations

- `css/radius` was already enforced. Widening it to the ladder only accepts more values, so it
  stays in enforce mode; its two named exceptions (Slideshow 8 px, the search key chip 4 px) stay
  in `RADIUS_EXCEPTIONS` until DR-D1#5, because the tree still writes both literals until DR-D2#2.
- `css/no-shadow` reads an inset layer with no blur as a rule drawn inside the box (the table seams
  of `Editor.css`, the terminal's head line on `/home`) and not as a shadow, so it reports the two
  drop shadows DESIGN.md 3.4 removes and nothing else. The row `chrome.plates.separation` (D2)
  reads "no box-shadow with a blur or an offset"; D2 decides whether the inset seams count.
- `css/numerals` also reads `'tnum'` in a `font-feature-settings` list, the same figures written
  another way (research-type 2: 7 files).
- `packages/lint/src/brand/run.ts` and `run.test.ts` change, though DESIGN.md 10.1 names only
  `config.ts`, `css.ts` and `source.ts`: the report mode of five rules beside an enforced mode
  needs the run to list them apart.
- The popover reset adds `width: auto` and `height: auto` to DESIGN.md 2.3 item 4's list: the
  user agent gives `[popover]` a fit-content width and height, which would shrink a scrim with
  `inset: 0` to its content.
- `packages/chrome/PORTED_FROM.json` records `Layer.ts`, `place.ts` and the token changes.
- The build's log printed the checkout's local agent token (`.turboslide/token`, the localhost
  bearer the build mints, SPEC-3 7.7) once, and a tail of that log showed it in this lane's
  session. It is a token of this worktree's localhost surface alone; deleting the file mints a new
  one on the next build.
