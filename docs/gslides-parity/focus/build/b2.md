### F4. A right click on a text box whose run holds the caret opened no menu

The mechanism, reproduced on 4362 before the change (`repro-before.json`): a single click at a text
box's centre opens the session at once (the round one rule, gslides-parity SPEC 10.2), so a
collapsed caret is the common state of a right click on a text box; `Editor.onContextMenuEvent`'s

`surface.advanced.off-by-default` (the spec's `contextRows` clicked the block's centre, then right

Measured on 4362 (`repro-dup.json`), a row picked from that menu did nothing until the next

`element.blur()` since the run no longer holds the focus. So the second step: on a collapsed caret

### F5. Shift click on a second object added nothing while a text session was open

The mechanism, reproduced on 4362 before the change, is wider than the finding: after a click on a
text box's run, a Shift click on another box, a Cmd click and a plain click on another box all left
the session live on the first box (`data-editing` set, the run still `activeElement`), so a seller
had to press Escape before any other object took a click. Two causes met. `Editor.onPointerDown`
returned on any press while a session was live ("one outside ends the edit through its blur"), and
the blur it counted on no longer ended the session: this lane's rank 10 park rule in

and a press on the sheet outside the run moves the focus to the stage root (`tabIndex -1`), which
holds every run, so the caret came back on the next tick. At `2b12e31` the blur ended the session
and the first box stayed selected; the second box was never selected on that press either.

synchronously), and the Editor's pointer handlers end the session themselves in the pointerdown,
before the browser moves the focus, then run the press as a selection press in the same event

(unchanged); on the edited block outside its run the session stays and the park rule brings the
focus back, as before; on another object the session ends and the press runs below as that
object's, so a plain click selects it (and opens its run's caret where the round one rule says so)
and a Shift or Cmd click adds it to the edited block ("2 objects"); on the empty sheet, or on the
workspace outside the sheet (`onWorkspacePointerDown`), the session ends and the edited block

### 1. What this cycle built: the A1 click model

The click model of A1 for every object kind, text boxes and the title, subtitle and body
placeholders included. The model is three pure decisions the Editor's handlers read, so the rules
are pinned by unit tests without a DOM and the handlers stay thin:

- `keys.ts typingEntry(e, ctx)`: the character a printable key types into a selected text object,
  or null. A1 rule 4: a printable key (a letter, a digit, Space, a Shift letter) with one text
  object selected and no session opens the session with the whole text selected, so the first
  character replaces it (Google's behaviour); a named key (Enter, Escape, the arrows, Backspace),
  a chord, several objects, an object without a run, an open session, a field or a composition
  answer null. The stage's key table still binds no bare letter (SPEC 0.28); the letter is not a
  command, it is the first keystroke of the session.
- `InlineText.ts clickEntry(input)`: what a click on an object does when no session holds its run.
  One click always selects (rule 1), so the press that follows drags the object from anywhere
  inside its area (rule 2, b3's move gesture). The double click is the entry (rule 3): inside an
  open session it is the browser's word selection; on a group's member it selects the member; on a
  picture it opens crop; on a text object, a placeholder or a shape with text it opens the session;
  a line and an object with no run take nothing.
- `InlineText.ts entryCaret(entry, point)`: where the caret lands for each entry. The double
  click's point (rule 3), everything selected for a printable key (rule 4), the end for Enter.

The Editor wires these:

- `onPointerDown`: the single click branch no longer opens a session on a run (the round one
  `startEdit(run, {x,y})` is gone). A click selects the object and arms the move; the press inside
  the selected object's area drags it (b3's `armPress`). A Shift or Cmd click adds it. This is the
  half of A1 the verifier's F4 and F5 saw from the other side: the one click session claimed the
  drag, the right click and the Shift click.
- `onDoubleClick`: rewritten around `clickEntry(entryInputFor(slide, el, id, 2))`. `entryInputFor`
  tells a picture (a croppable block on a canvas or a shot, or a picture kind's photograph), a
  line, a shape and a text bearing object apart, and reads whether the object is a group member and
  carries a run. The text case opens the run under the pointer with the caret at the point, else the
  block's first run at its end, and prevents the browser's own double click word selection so the
  session places the caret itself.
- `onKey`: a printable key with one text object selected runs `typingEntry` and, on a character,
  sets `pendingInsert` and opens the session over the whole text; `enter` opens the first run with
  the caret at the end (`entryCaret('enter')`). Escape inside a session is the run's (InlineText
  `finish('escape')`, `endEdit` selects the block); a second Escape reaches the stage's table and
  clears the selection (`escapeSelection`). The `pendingInsert` character lands when the session's
  handle comes up (the render after `startEdit`), over the whole text the entry selected, so the
  first character replaces the text.

### Fix. The RangeError page error during the title battery (C2-F22, this lane)

`pageerror: RangeError: The range 0:30 is outside a text of 27 characters`, once in each of the
three cycle 2 walks (the preview, 4379, 4321), between `text.caret.cmd-a` and
`text.title.enter-commits` (b4's C2-R5). No row failed on it; it is the console noise the finding
asks to remove.

Cause. `InlineText.tsx reportCaret` reads the selection range from the DOM
(`selectionOffsets`, which counts the untrimmed content) and then reads the marks from
`readText()`, which returns the trimmed canonical text (`textFromNode(..).trim()`). When
`text.caret.cmd-a` does Cmd+A on a title whose run carries trailing white space, the DOM run is 30
characters and the selection range is `[0, 30]`, while the trimmed text is 27 characters. `marksOf`
then calls `marksOfRange`, which calls `schema/text.ts checkRange`, which throws once the end is
past the length. The write paths already clamp (`applyMark`, `openLink`:
`Math.min(selected[1], plainLength(text))`); only the caret read did not. The error is thrown from
`schema/text.ts` (not this lane's file); the fix is at the two callers this lane owns, so the
schema stays untouched.

Fix. Two changes, both in this lane's files:

- `packages/viewer/src/InlineText.tsx` `reportCaret`: read the text once, take its `plainLength`,
  and clamp the range to it before calling `onCaret`/`marksOf`, exactly as `applyMark` clamps. The
  toolbar now receives a range inside the text, not one past it.
- `packages/viewer/src/marks.ts` `marksOf`: clamp the incoming range to the text's `plainLength`
  at the boundary (`marksAt` already clamps its offset), so any caller that hands a range past the
  trimmed text collapses it to a caret read instead of throwing. Defence in depth for the marks
  reader the toolbar and the inspector share.

Test. `packages/viewer/src/__tests__/marks.test.ts` gains a case that reproduces the exact throwing
input: `marksOf('[Hello]{i} world', [0, 30])` no longer throws and reads the clamped marks, and a
range wholly past the text reads the caret at the end. A unit test, not a matrix row, because the
finding is a page error between rows, not a failing row.
