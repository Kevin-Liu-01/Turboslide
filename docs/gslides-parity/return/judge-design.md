# Judge: design

Judgment of `docs/RETURN.md` (the return round specification, 2026-09-18) against the four production audits under `docs/gslides-parity/return/` (`audit-chrome.md`, `audit-formatting.md`, `audit-objects.md`, `audit-surface.md`), their pictures and run JSON under `audit-chrome/`, the matrix file `docs/gslides-parity/focus/core-matrix.json`, `scripts/probes/core-matrix.mjs`, `scripts/probes/core-walk/`, and the sources at the production commit read with `git show 1d3ba31:<path>`. Lens: design and reliability. The questions asked of the document: is the Slideshow split button one control in structure, tokens, states and ARIA; is the separators law one rule drawn once in both appearances; are the before and after pictures cited and do they show what they are cited for; does every returning interaction have a matrix row with a driver that runs against a deployment; can the acceptance be gamed; is the lanes' ownership disjoint.

This judge ran no Playwright, touched no source file and ran no git write command. The pictures were opened and read; the after run's JSON (`audit-chrome/after-pictures-run.json`) was read for the measured values. Every claim below names the section, the audit row, the picture or the file that shows it.

## Verdict

Revise.

This is what Kevin asked for in the sentence about the slideshow and the dropdown.

## Notes

- The threshold in `chrome.split.one-box`, "at least 1.8:1", sits 0.03 above the measured dark value of 1.83:1 (`notes.after-dark.seam`); a one step rounding of the composite could fail a correct build. A threshold of 1.7:1, or a check against the token's own composite, is safer.
- The wrapper's `role="group" aria-label="Slideshow"` beside a button whose text is Slideshow reads the word twice in a screen reader; the pattern is acceptable and Google's structure was not measured, so this is a note, not a rejection.
- The two run rule of section 1 applies to the preview; production gets one run (FOCUS.md 6.2, "the last run of each origin"), so a flaky row can pass its single production run. The document could say why one run on production suffices, or ask for two.
- The inbox's return (2.16) rests on the sentence "a seller sees replies and mentions on a shared deck there"; research 07 has no row naming notifications or the inbox, so the decision has no research cite and belongs with open question 2.
- Section 7's README sentence "Enter, Space and the arrow keys work on it" promises more than 4.1 specifies (ArrowDown on the label only).
- The separators law drops the 1280 and 390 px widths SPEC.md 1.2 measured and uses 1440 and 900; the audit measured at those two, so the change is consistent with the evidence, but the law should say so.
- Kevin's sentence "make separator lines between our ui rows better" is read by the document as one owner per boundary and lighter in-row dividers; the audit found every row boundary already one `--pt-hair` line except the notes divider (rows 4 and 5), so the visible change for Kevin will be the notes seam, the split button's divider and the dividers of item 2. If "better" meant more visible, open question 4 is the one that answers it, and it has no picture pair today.
- The "Better than before" paragraphs of section 2 describe what the fixed product will do; they read as specification and are marked as such by their heading, so the copy rule (report what happened) is not broken, but a reader skimming the tables could take them for measurements.
