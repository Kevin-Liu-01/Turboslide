# Logo audit: a logo picker over thesvg.org

The auditor for the area "A logo picker over thesvg.org: easy logo adding and searching", written on 2026-09-20 against the shared checkout at `cbd4495` with the product round's uncommitted tree, and against production `https://turboslide.vercel.app` (the return round plus the caret hotfix; the bundle `index-Dkbo1pra.js`). Every observation below is read from a file on that tree (named with its line numbers), fetched from thesvg.org, its repository, svgl.app or Simple Icons with curl on 2026-09-20, or measured on production with Playwright at human speed on scratch decks that were trashed and deleted forever at the end of each run (both decks answered 404 on `/edit/<id>` and `/deck/<id>`). The scripts are `scripts/logo-walk.mjs` (the production walk; it imports nothing from the repository but `playwright-core`) and `scripts/raster-check.mjs` (a sharp run over the sampled marks) under `docs/gslides-parity/features/audit-logos/`, with the walk records `logo-walk-1.json` and `logo-walk.json`, the raster report `raster-check.json`, the registry numbers `thesvg-facts.json`, the sampled files under `svg/` and the response headers `thesvg-registry.headers` and `thesvg-svg.headers`. Nothing was fixed.

## 1. thesvg.org, read

The site and the repository. thesvg.org is a Next.js static export served from GitHub Pages: every response carries `server: GitHub.com` behind Fastly (`thesvg-registry.headers`, `thesvg-svg.headers`), the repository root holds a `CNAME` file and `has_pages` is true. The repository is `github.com/glincker/thesvg` (MIT for the code; 2,717 stars, 217 forks, created 2026-03-07, last pushed 2026-09-20 09:09 UTC). The title reads "7,417+ Free Brand SVG Icons for Developers and Designers"; `icons.json` counts 4,681 brand marks, 860 auth badges, 739 AWS, 626 Azure, 259 community, 214 Google Cloud and 38 Kubernetes icons in seven collections (the README's table says 4,675 brand marks), 141 categories and 13,301 variant files.

The index. There is no search endpoint; `llms.txt` says so ("fetch the manifest once and filter client-side") and names a gated `api.thesvg.org` as a roadmap item. Two static files serve every consumer:

- `GET https://thesvg.org/api/registry.json`: 1,497,387 bytes, `{ total: 7417, icons: [...] }`, each icon `slug`, `title`, `aliases`, `categories`, `hex`, `url`, `license`, `variants` (a list of variant keys). `cache-control: max-age=600`, `access-control-allow-origin: *`, `last-modified: Sun, 20 Sep 2026 06:39:58 GMT` (the site was rebuilt the morning of this audit). It answered in 0.40 s.
- `GET https://thesvg.org/api/categories.json`: 4,447 bytes, `{ categories: [{ name, count }] }`, 141 rows.
- `GET https://cdn.jsdelivr.net/gh/glincker/thesvg@main/src/data/icons.json`: 3,284,459 bytes, the source manifest with the fields the registry drops: `variants` as a map of key to file path (`"wordmarkLight": "/icons/vercel/wordmark-light.svg"`), `dateAdded`, `collection`, `collectionVersion`, `guidelines` (1,126 icons), `supersedes` and `supersededBy` (4). jsDelivr answers `cache-control: public, max-age=604800, s-maxage=43200`, so a browser keeps it seven days and the edge twelve hours.

The SVG addresses. `https://thesvg.org/icons/<slug>/<variant>.svg` and the mirror `https://cdn.jsdelivr.net/gh/glincker/thesvg@main/public/icons/<slug>/<variant>.svg`, `image/svg+xml`, CORS open, `cache-control: max-age=600` on thesvg.org. The registry's variant keys are camel case while the files are kebab case: `openai/wordmarkLight.svg` answers 404 although the registry lists `wordmarkLight` for OpenAI; `icons.json` carries the real path `wordmark-light.svg`. Of 276 files fetched for a random sample of 160 icons (`corpus-sample.json`), two did not come back: `cogvideo/default.svg` is 404 on the site and its file in the repository fails to parse (`xmlParseEntityRef: no name` at column 5569), and `nuxt/default.svg` answered 503 once and 200 on the recheck.

The search fields. The site's own search, the Figma plugin, the Raycast extension and the MCP server's `search_icons` all match over the manifest on the client: title and slug, with `aliases` as the extra field (849 of 7,417 icons carry an alias, 371 of the 4,940 brand and community marks; Google carries the Korean name, Aarch64 carries Arm64, AB Download Manager carries ABDM) and `categories` as the filter (the Figma plugin has a category dropdown; the MCP server lists categories with counts). The Figma plugin (`extensions/figma/README.md`) is the closest interaction reference: a search field, a category filter, one click inserts, a numbered badge on a tile opens its variant menu, a Recent row of the last twelve kept across sessions, Enter inserts the first result, Cmd+F focuses the search, Escape closes, and the plugin follows Figma's light and dark theme.

The categories. 141, with Software 3,780, Platform 2,556, DevTool 883, Community 503, AI 412, General 332, Finance 217, Library 189, Security 184, Database 169 at the head and one-icon categories (Accessibility, AI Medical Scribe, AntV, Autoscaling, Caravaning, Construction) at the tail. The cloud collections carry their own vocabulary (App Services, Azure Stack, Control Plane, Cost Management). The categories are a developer's taxonomy; a seller looks for a company name, not a category.

The variants. Every icon has `default` (7,417); `mono` 3,757; `wordmark` 311, `wordmarkDark` 126, `wordmarkLight` 121; `light` 195 and `dark` 195; `color` 157 (the default's alias on some icons); `16`, `32`, `64` on the 326 auth badges; `line` 38; and one-off keys (`icon`, `horizontal`, `lockup`, `lockupDark`, `logo`, `wordmarkMono`). Of the 4,940 brand and community marks, 3,757 have a mono, 315 a wordmark of any kind, 178 a light and dark pair, and 1,100 have the default alone. The README's words for the variants: default "primary brand color", mono "inherits text color", light "white, for dark backgrounds", dark "black, for light backgrounds".

Three SVGs, read (the files are under `svg/`):

- `figma/default.svg` (1,087 bytes): `width="54" height="80" viewBox="0 0 54 80" fill="none"` on the root, five `<path>` elements with hex fills (#0ACF83, #A259FF, #F24E1E, #FF7262, #1ABCFE) inside a `<g clip-path="url(#clip0_912_3)">`, and a `<clipPath id="clip0_912_3">` in `<defs>`. An id that would collide if two such marks were inlined on one page; harmless inside an `<img>` or a raster.
- `vercel/default.svg` (169 bytes): `viewBox="0 0 256 222" width="256" height="222"`, one `<path fill="#fff">`. The default is the white triangle for a dark ground, so it is invisible on paper. `vercel/light.svg` and `vercel/dark.svg` are 169 bytes each and differ at character 132, the fill. `vercel/mono.svg` (132 bytes) is Simple Icons' 24 by 24 path with `role="img"` and `<title>Vercel</title>` and no fill attribute, so it inherits `currentColor` and draws black inside an `<img>`. `vercel/wordmark.svg` (3,622 bytes): `viewBox="0 0 262 52"`, `aria-label="Vercel logotype"`, paths.
- `openai/default.svg` (1,702 bytes): `width="256" height="260"`, `fill="#fff"` on the path; white, invisible on paper. `slack/default.svg` (1,497 bytes): `viewBox="0 0 2447.6 2452.5"` with `enable-background`, four coloured paths, multi line formatting. `glincker/light.svg` and `dark.svg` are 2,350 bytes and differ at character 1290.

Commits under `public/icons` land most days: 30 between 2026-08-07 and 2026-09-18 (batches of one to eight icons, a fix of a dark variant, a fix of two dangling clip path references, the 858 auth badges on 2026-09-12); 903 icons carry a `dateAdded` on or after 2026-08-20; the `thesvg` npm package went from 3.3.2 (2026-09-02) to 3.3.8 (2026-09-18), seven releases in sixteen days. ## 2. What exists in the product today

The intake. `asset.add` takes a file path, a data URL, an http(s) URL or a presigned upload (`packages/schema/src/actions.ts` 2097 to 2172; "An http(s) URL to fetch, 25 MB at most"). The URL path is `fetchAllowed` in `packages/headless/src/capture/shared.ts` 446 to 486: the host must match the built in allowlist plus the caller's extra hosts (`assertAllowedHost`, 143 to 165); the hosted list is `generaltranslation.com`, `prototemplate.com`, `glyphfield.com`, `commons.wikimedia.org` and `upload.wikimedia.org` (82 to 94), the studio passes no extra host (`apps/studio/src/server/actions.ts` 427 to 447), and the refusal sentence reads "host <host> is not in the capture allowlist; pass --allow <host> (SPEC 11 captureHosts)". The bytes are sniffed by magic (`sniffImage`, 525 to 570) and on a hosted store the accepted set is png, jpeg, webp and gif: "svg is not accepted here; send png, jpeg, webp or gif" (600 to 604; `HOSTED_INPUT_FORMATS` 527). `packages/headless/src/capture/intake.ts` 69 and 178: "svg refused" on hosted; the re-encode path never sees an svg. The presigned upload declares png, jpeg, webp or gif alone (`apps/studio/src/server/upload.ts` 76 to 81) and "a fifth format or an svg is removed and refused with 400" (330); the seller's sentences are "the file is not a picture", "the file is over N MB" and "the upload did not finish" (53 to 57). The studio's intake policy is `allowPaths: false, hosted: isHosted()` (`actions.ts` 381 to 390).

The choosers. The Insert > Image > Upload from computer chooser accepts `image/*` (measured on production, run two row 3), so an `.svg` can be chosen. On the checkout, the Brand kit panel's Logo > Replace chooser lists `image/png,image/jpeg,image/webp,image/svg+xml,image/gif` (`packages/chrome/src/ThemesPanel.tsx` 592) and Tailor for a customer's logo chooser lists `PICTURE_TYPES` with `image/svg+xml` (`packages/chrome/src/dialogs/Tailor.tsx` 47, 189); both run `asset.add` with a data URL (`ThemesPanel.tsx` 340 to 368; `Tailor.tsx` 96 to 106), which the hosted intake refuses for an svg.

How an asset is served and drawn. `packages/store/src/blob-store.ts` 191 maps `.svg` to `image/svg+xml`; the assets route serves png, jpeg, webp and gif inline and everything else, svg included, as `content-disposition: attachment` with `content-security-policy: sandbox; default-src 'none'` (`apps/studio/src/server/headers.ts` 66 to 96: "the `<img>` tags the renderer emits never load an svg from this route on a hosted instance"). The page's CSP is `img-src 'self' data: blob: <store host>` and `connect-src 'self' <store hosts>` (205 to 212), so the editor cannot draw a thesvg.org mark or fetch its registry from the browser. A picture block is `<img class="picture-img">` at object-fit cover over the asset's twins (`packages/render/src/blocks/picture.ts` 1 to 13); an asset carries `twins` as a light and dark pair or one neutral file, `size`, `scale` 1 to 3, a `source` record (material, capture, photo or file; `packages/schema/src/assets.ts` 28 to 59, 155 to 197), an optional `sourceFile` and a `role`, and `logo` is already one of the ten roles (11 to 22). The Brand kit panel adds a logo with `role: 'logo'` (`ThemesPanel.tsx` 359).

The placement. Upload from computer places the picture through `insertPictureAsset` (`packages/viewer/src/Editor.tsx` 518, 3086), the path Image by URL also takes (`packages/chrome/src/dialogs/ImageByUrl.tsx` 100 to 125; the dialog exists on the checkout and is parked on production, `docs/FOCUS.md` 3.2). On production a 324 by 480 PNG landed at about 480 by 710 sheet px, the body slot's height, at the slot's left over the title runs and the GT mark (`05-upload-png-logo.png`); a 960 by 244 PNG landed at {136, 128} 480 by 122 sheet px over the first picture (`06-upload-png-wordmark.png`). A picture's right click menu lists Cut, Copy, Paste, Delete, Duplicate, Order, Rotate, Group, Center on page, Align, Replace image, Crop image, Reset image, Image options, Format options and Comment (`07-picture-context-menu.png`); the checkout adds Use on every slide (`packages/chrome/src/menus/model.ts` 1859; `packages/chrome/src/brand/UseOnEverySlide.tsx` 22 to 52 writes `/mark`, `/footer/logo` and `/footer/assetId` as one commit labelled "Brand kit: Logo").

## 4. What a seller and a marketer feel today

A seller who wants a customer's logo on the cover leaves Turboslide: they search the web, land on thesvg.org, Wikipedia or the brand's press page, download a file, come back, open Insert > Image > Upload from computer and pick it. If the file is the SVG every logo site offers first, the snackbar answers in a developer's words and nothing lands. If they find a PNG, it lands at the height of the slide over the title, they shrink it by a corner handle, drag it into place, and repeat on every slide that needs it, because New slide carries nothing and the right click menu has no row about every slide. The mark they find may be the white version drawn for a dark site and vanish on a light slide. Search the menus answers "logo" with a border dash. An agent on the CLI or MCP has the same four walls: the URL allowlist, the svg refusal, the User-Agent refusal from Wikimedia, and no action that names a logo. A marketer building the brand kit on the checkout has a file chooser that offers `.svg` and an intake that refuses it.

## 6. The feature, in one piece

### 6.1 The picker

Insert > Logo (`insert.logo`, the icon `building-office` from the sprite if it exists, else none) opens the dialog "Logo". The head holds the search field "Company name" with the focus, and the two controls Symbol | Wordmark and Colour | Mono. The body holds the groups Your brand (the deployment's default kit logo and the deck's `role: 'logo'` assets), Recent (the last twelve picks on this browser) and Results (the cache's matches, twenty at a time, more on scroll). A tile is 96 px: the mark at 56 px drawn twice, on the kit's light Background and on its dark Background, the title under it, a small count in the corner when the brand has more than one variant. The arrows move, Enter inserts the selected tile (the first result when none is selected), Escape closes; a click inserts at once, the dialog closes, the picture is selected on the slide. The foot holds the check Use on every slide, the licence row of the selected tile, the source sentence with the cache's date, and the Insert button. The empty state offers Upload. While thesvg.org is unreachable the picker works from the cache and the source sentence adds "thesvg.org did not answer at <time>".

### 6.2 The server route

`apps/studio/src/server/logos.ts` owns four things. The cache: `system/logo-index.json` in the store, built by `refreshLogoIndex()` from jsDelivr's `icons.json` (thesvg.org's `registry.json` as the fallback), trimmed to the picker's fields, with the two "reads" flags computed by rasterizing each new mark's default once at 96 px (the raster check measured 2 ms at the median, so a full first build is about a minute), and refreshed by `POST /api/logo/refresh` (the agent bearer, owner scope) on a daily Vercel cron. The sanitizer: an allowlist parser over the SVG (the elements svg, g, path, circle, ellipse, rect, line, polyline, polygon, defs, clipPath, mask, linearGradient, radialGradient, stop, title, desc, use, style; every `on*` attribute, `script`, `foreignObject`, `image`, `a`, `iframe` and any `href` or `xlink:href` not starting with `#` removed; a `<style>` kept only when it holds no `@import` and no `url(`; a `viewBox` added from `width` and `height` when absent), a cap of 256 KB before parsing (the largest sampled mark is 98 KB), and the parse failure answered as "This logo's file is broken on thesvg.org". The fetch: thesvg.org first, jsDelivr `@main` second, `User-Agent: Turboslide/<version>`, 10 s, 256 KB, through its own host list. The raster: sharp from the sanitized SVG at the density that yields 3x of the target box, into PNG twins; a mono variant with the kit's text colour written as the root `fill`. `GET /api/logo/mark/<slug>/<variant>.svg` serves the sanitized file for the tiles with `image/svg+xml`, `nosniff`, `cross-origin-resource-policy: same-site` and `content-security-policy: sandbox; default-src 'none'`, the last so a navigation to the file cannot run anything even though the sanitizer already removed it.

### 6.3 The actions

`logo.search` and `logo.insert` as item 8 defines them, in `packages/schema/src/actions.ts` under the group `asset`, so the CLI, MCP, HTTP and window transports carry them without hand written code; `logo.insert` joins the server side window actions and the draft creating actions in `agent-actions.ts`; the `logo` source kind joins `assetSourceSchema`. The CLI's `turboslide logo search figma` prints slug, title, variants and licence per row; `turboslide logo insert figma --kit` sets the kit's slots.

### 6.4 The export

This round the stored twins are PNG at 3x of the inserted box and the `logo` role is shot at 3x, so the PDF and both PowerPoint modes carry a crisp mark at the footer and the title slot sizes.
