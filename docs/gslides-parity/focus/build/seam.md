### 2. Found at the seam and fixed here

1. The offline blip does not end a streamed fetch (`realtime.spec.ts:543`, S1's new row). The row
   cuts A's held stream with `context.setOffline(true)` and expects `connected` false within 10 s;
   on 4394 it stayed true for the row's 10 s and, in a probe of this step, for 40 s. Measured with
   a raw stream from the page under the emulation: a heartbeat chunk arrived 2 s after
   `setOffline(true)` while every new request failed with `ERR_INTERNET_DISCONNECTED`, so the
   emulation keeps an established stream's bytes flowing. The browser does fire `offline` (and
   `online`; `navigator.onLine` follows). Fix in `controller.tsx` `sseTransport`: the `offline`
   event ends the stream (the fetch aborted, one report to the room client), which reopens it on
   its ladder once the network answers; the listener leaves with the stream. A laptop that changed
   networks gets the same reading, where before the tab kept a dead socket as connected. Test: the
   row itself (`:543`, section 3).
2. The runtime never reports a raw stream's abort (`VERIFICATION.md` C3-F1's shape on the
   preview). On the first preview of this step, quiet, one instance held the page's stream and
   three raw ones, refused the fourth to sixth open, and after the three were closed client side
   refused every open for 73 s with `identity 4/4, address 4/16, instance 4/256 (1 identities)` in
   the runtime log: neither the request's abort nor the body's `cancel()` reached the route, and
   the heartbeat's `enqueue` kept succeeding. Fix in `apps/studio/src/server/room.ts`
   `createStreamCloser`: a write that finds the controller's queue still holding the previous
   chunk (`desiredSize <= 0`) for `STREAM_READER_GONE_MS` (two heartbeats plus 5 s, 35 s) closes
   the stream and releases its slot; a burst of frames drains within milliseconds and never trips
   it. Test in `stream-counters.test.ts` (a live reader across a burst; a gone reader closed at
   the third heartbeat, released once, no write after). Whether the preview's runtime stops
   pulling when the browser goes is not read (section 5): every later run of the probe spread its
   opens over instances.
3. The persisted queue outlives a reconnect (`realtime.spec.ts:515` read "6 unsaved changes"
   where 3 were typed, run B). The record is keyed by client id (`pendingKey(deckId, clientId)`);
   a reconnect mints a new id and the ops travel and persist under it, and the record under the
   old id stayed with its ops marked unsaved, so the next page was offered ops that had landed.
   Before this step the emulated blips of the suite never ended the stream, so no run met it; a
   real drop always did. Fix in `room-client.ts` (the hello handler): when the id changes, the
   queue is persisted under the new id and the old key removed. Test "moves the record to the new
   client id when the stream reconnects, so the next page is never offered ops that landed":
   fails with the branch disabled, passes with it.
4. `presence.spec.ts:170` asserted the parked inbox plate in the default view (C2-F17, b7's
   C2-R21, standing since cycle 2). Rewritten to the amendment, never deleted: the default view
