### 1.2 What `themeCss(deck)` emits

One stylesheet, one rule per line, empty for a deck without `themeEdits`, for an empty record and for a record carrying only `name` or `background` (the renderer draws `defaults.background` itself, SPEC-2 2.6; Edit theme's Background writes both). The scope is `.ts-sheet:not([data-theme-base])`:

- Colours per appearance under `.ts-sheet:not([data-theme-base]):not([data-theme='dark'])` and `.ts-sheet:not([data-theme-base])[data-theme='dark']` (specificity 0,3,0 over sheet.css's 0,1,0 and 0,2,0): `--<token>` for the ten token slots in `TOKEN_NAMES` order; an edited `ink` recomputes `hair`, `hair-soft`, `cross`, `edge`, `thumb` as `rgba(r, g, b, alpha)` with the base alpha of `tokensFor(deck.theme)` unless the record pins one; `ok`, `warn`, `no`, `info` on `.ic.<hue>`; `raised` on `.panel`'s background; `link` on `.slide a`.
- Fonts: `--display`, `--text`, `--mono` as `'<Name>', <fallbacks>` through `fontStack(id)`.
- Frame: `frame.inset` writes `--rail` and `--cross-offset` (`crossOffsetOf`: the rail less half the cross, rounded); `rails: false` hides `.frame::before, .frame::after`; `rules: false` hides `.frame .rule`; `crosses: false` hides `.frame .cross`.
- Corner slot: `kind: 'none'` hides `.wordmark`; a `box` writes `--mark-left`, `--mark-bottom` as `calc(var(--ts-sheet-h, 900px) - <y + h>px)` (B4's page property with the default page as the fallback), `--mark-height`, the `.wordmark` width and a full size `svg, img`.
- Counter: `show: false` hides it; `side: 'left'` moves it to `left: var(--counter-inset)`; a `box` writes `--counter-inset` (from the left edge on the left side, else `calc(var(--ts-sheet-w, 1600px) - <x + w>px)`), `--counter-bottom` and the width.
- Chips: `show: false` hides `.ts-chips`.
- Type: each level of `THEME_TYPE_LEVELS` on its `TYPE_LEVEL_SELECTORS` (`h1`, `h2`, `.big`, `.lead`, `p`, `.cap`, `.pair figcaption`) with `font-size`, `font-weight`, `letter-spacing` in em.

### 1.3 Decisions and deviations

1. The scope. The day 0 seam scoped the override to `.ts-sheet[data-deck="<id>"]`, an attribute no sheet root stamps (`renderStage`, `Stage.tsx`, `Editor.tsx`, `LiveClone.tsx`, the print route). Every sheet root of every surface holds one deck, so the override scopes to `.ts-sheet:not([data-theme-base])` and needs no attribute; the Themes panel's GT and Plate tiles, which show a base theme without the deck's edits (9.2), opt out through `sheetRootAttributes(id, appearance, { base: true })` or the attribute on `LiveClone`'s root (a request to B2 when the panel lands, day 5). `themeCssScope()` therefore takes no argument.
2. `--inset` is not a variable. R03 4.6 lists `--rail` and `--inset`; the slide box inset (57 px, `stage.css`, B4's) is the content box and nothing in the theme mode moves it (R03 4.4), so the record's `frame.inset` is the rail alone and the cross offset derives from it. The counter's horizontal variable is `--counter-inset` (a distance from the counter's side), not `--counter-right`, so the left side reads the same variable.
3. The counter's font size stays a literal 13 px: the record has no counter size field, and a variable there would have moved the counter out of `tokens.test.ts`'s floor list for no reader.
4. `THEME_COLOR_SLOTS` lives in `packages/schema/src/validate/theme.ts`, not in `packages/theme`: the schema is the bottom of the dependency direction (SPEC 3.3 item 3) and the validator, the theme package, the chrome, the export and B3's Import theme all read one table. `link` and `info` are two keys although R03 4.2 maps both to `SEMANTIC.info`, because a record keyed by token could not hold Google's Link and Accent 4 apart. The hex map of `themeEditsSchema` is six digit, so the transparency R03 4.2 gives the four text and background slots needs the schema to admit `#rrggbbaa` on those keys (a day 5 request to the integrator, item 3 of section 1.5).
5. The hidden built in layout is a `customLayouts` entry `{ from: <built in id>, hidden: true }` under a `custom-` key, because the record's key schema admits custom ids alone; `validateLayouts` wants `from` on a hidden entry.
6. `render/theme-css.ts` imports `@turboslide/theme/theme`, which reads files with `node:fs`, because `packages/theme/package.json` has no `./themes` subpath yet (item 1 of section 1.5). Today the module's one caller is `scene/extract.ts` (Node). When the export lands the import moves to `@turboslide/theme/themes` and the module is browser safe for the editor's live preview.
7. `fontStack(id)` repeats the 26 family names of A5 with a generic fallback per category because B7's catalog does not exist yet (item 4 of section 1.5).
8. `tokens.test.ts` is named by both B4 (the `grid(page)` assertions) and B6 (the frame variables, "per theme" on day 6) and by neither "Owns" row. B4's `grid` and `--ts-sheet-w` assertions were already in the file when B6's `resolve()` edits landed on top; the two sets are disjoint and the file passes with both. Recorded so the integrator knows the file has two authors at merge 1.
9. `THEME_SPECS['ts-plate']` already states Plate's geometry (the left rail and bottom rule, no crosses, no mark, no chips, the same tokens, SPEC-5 9.3) while `sheetCss`, `stageCss`, `stageFrame` and `themePaths` answer the GT files for both ids until day 6, so a deck switched to `ts-plate` today draws as GT and nothing moves.

### 2.2 Decisions and deviations

1. The `./blocks/equation` subpath. `@turboslide/render` exports no `./blocks/equation`, and `package.json` is the integrator's, so the Node callers (the exporter's scene and math modules, `math.test.ts`) read the equation API through `@turboslide/render/theme-node`, which installs Temml at import anyway, and the lane handler module (bundled into the page) reads `equationMathml` and `loadEquationEngine` through `@turboslide/render/theme-css`, the one browser safe subpath this lane owns. Request R6 asks for the subpath; the re-exports move then.
2. The chrome subpaths. `apps/studio/src/editor/theme-mode.tsx` imports `@turboslide/chrome/ThemeToolbar`, which `packages/chrome/package.json` does not export yet (R11), so `tsc -b` reports one unresolved module in that file until the line lands, the precedent B7 set with `@turboslide/fonts/names` this round. `EquationToolbar` and `inspector/equation` are reached by the shell through relative imports once mounted (R12) and need no subpath for that.
3. The window transport. The controller's dispatcher registers window handlers one `on(...)` row at a time and does not spread `registerLaneActions`, so `equation.*`, `theme.*` and `layout.*` run on the CLI, the MCP server and the HTTP surface (the hosted `deckDispatcher` spreads the lane modules) and reach the window through the rows of R12. The two specs drive the actions through `POST /api/actions/<id>?deck=<id>` on the same dev server and read the page; the rows the shell mounts are skipped with the request named, never passed.
4. The wrapper's ids. Microsoft's example gives the Choice shape and the Fallback shape one `p:cNvPr id`; `rewriteEquations` writes one, and B1's renumber (`ooxml/ids.ts`, R05 6.4) then numbers every `p:cNvPr` once for the timing tree's references, so a built package carries two. Both forms are valid OOXML (only one branch is in the tree); `checkEquations` wants an id on each shape and no longer pins equality. The first export check of the fixture read INVALID on 19 wrappers for this reason; it reads VALID now.
5. `equation.render`'s box. The output's `box` is an estimate from the MathML tree (the glyph count times 0.6 em plus 0.35 em per operator, 1.25 em per stacked row) unless the composition provides `EquationLaneDeps.equationPng`, which measures with Chromium and writes the 2x raster for `--out png`; without it `--out png` refuses with the sentence. The renderer's own measure is the truth on the sheet. The parse finding uses the rule id `equation/parse`, which `RULE_IDS` does not carry yet (R7): the handler builds it, the unit test asserts the shape by calling the handler directly, and the dispatcher's output validation admits it once the rule row lands.
6. `theme.applyImported` writes the record's colours into both appearances: an imported scheme is one scheme, as Google's is. A face the catalog lacks leaves the theme's face (Inter).
7. Hidden built in layouts stay `{ from: <id>, hidden: true }` under a `custom-hidden-<id>` key, as day 1 decided; `layout.delete` on a custom layout clears `template` on the slides that named it in the same commit.
8. `applyCustomLayout` moves the title into the title placeholder, the first text into a subtitle placeholder, every remaining text and list into the body placeholders (split evenly), the first picture into the image placeholder, copies the layout's other blocks as decorations, and keeps the slide's free boxes where they are; a grammar block without a box stacks under the content; nothing is dropped unless it had no box and no place.
9. The theme mode is a component of the studio (`ThemeMode`) drawn from props the shell passes (the document, the revision, the shell's `renderSlide`, the window `invoke`, the shell's `commit`); its mount under `editorMode === 'theme'` and the `client('themeMode')` wiring are R12. Insert placeholder writes the layout's block list through the shell's generic `commit` (`deck.set /customLayouts/<id>/blocks`), because the action table has no `layout.insertBlock` row.
10. The override stylesheet in the editor's document: `themeCss(deck)` reaches the string renderer through the scene; the live editor needs a `<style id="ts-theme-css">` maintained from the deck (R14, one hook in `EditorRoot.tsx`), and the sheet root needs `data-sheet` from B4's R2 for the Plate rules. Until both land a `theme.set` writes the record and the exports follow it while the editor's sheet does not; `theme.spec.ts` records that row as not driven.
11. The dither preview budget lives in `effects/dither.ts`: `ditherFrame(..., { preview: true })` measures stages 2 to 5 and, once a family ran over 100 ms at a screen size on this host, draws Bayer 8 for that family at that size or larger in later preview frames (`frame.fallback`); a file render never falls back. The worker passes `preview: true` through R15. Measured on this machine at 400 by 225 cells (a covering picture at cell 2): the five patterns each run under 10 ms, so the fallback never fires here; the numbers are in `dither.test.ts`'s console line.
12. The halftone pitch is eight cells (the Bayer period), so `cell` scales the dot pitch as it scales every other pattern; R08 3c's two tone screen request (B4 R3) is unaffected because the block dither's screen is the box over the cell, never the page.
13. The crate agrees with the TypeScript at agreement 1.0 on 336 rows (both bindings, eight patterns, five angles, three seeds, three level counts, two images) because every stage is integer arithmetic or doubles in one operation order and the two transcendental calls (cos and sin of the screen angle) come from libm's fdlibm ports; `FRAC_1_SQRT_2` in the crate is the same double as the TypeScript's `0.7071067811865476` (asserted in Node).
14. `BUILD-RECORD.json`: the wasm rows were rewritten from the rebuilt files with `check-record.mjs --write` (run id null, `builtBy: local`, as round four's rows were); the Linux addon stays pending for `native.yml` (R10); `crateCommit` still names round four's crate commit because the crate's files are uncommitted until the ship step, which rewrites the record.
15. The render switch. `renderEquation` is complete and tested, and `deckUsesEquations` inlines the math face, but `render-block.ts` (the integrator's shared file) still draws the seam placeholder for `equation` (R17); the export gate's `a14:m` count and the flatten report's `perfect: true` hold either way because the OMML comes from the engine and the Perfect raster follows whatever the sheet drew. The gate rows below say which numbers were taken with the placeholder on the sheet.
16. `ExportReport.equations` rows: `build.ts` (B1's) counts `motion.equations.native` and `.raster` and pushes the raster rows into `motion.rows` under a `motion:` prefix (the day 0 wiring); the report's own `equations` rows and an `equation:` prefix are R13's second half.
