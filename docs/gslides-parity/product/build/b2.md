#### 1.1 Link detection (rank 9; `text.link.detect-url`, `text.link.detect-email`)

- `packages/viewer/src/marks.ts`: `linkOfToken` (a scheme address kept, `www.` and a bare domain
  with or without a path gain `https://`, an email becomes `mailto:`; a number, a version, an
  abbreviation and a word are not addresses: the last label must be two to twenty four letters),
  `detectLinkBefore(plain, caret)` (the token ending at the caret, a wrapping parenthesis and the

- `packages/viewer/src/InlineText.tsx` `autoLinkBeforeCaret`: on the `input` event whose
  `inputType` is `insertText` with white space (the space that has just landed) and on Enter
  before the break or the commit, the token before the caret becomes a link over the run model
  (`linkRange`) when it reads as an address and carries no link. Order of the writes: the pending
  burst flushes first (the letters and their splice), the editable is rewritten from the markup
  with the caret restored, the second flush carries the link alone as a `text.replace` of the
  span, which `typing-key.ts` never groups, so one Cmd+Z removes the link and keeps the text
  (measured: "See acme.com " stored `See [acme.com](https://acme.com)`, Cmd+Z stored `See acme.com`).
  The typed space is kept as the no break space Chromium writes for a trailing space
  (`keepTrailingSpace`): a collapsed trailing space is "insignificant" to Chromium's editing and
  was deleted on the next keystroke (measured: `</a>today` with no space). On Enter the caret is
  nudged past the anchor before the break (`nudgeCaretOutOfLink`), and before every printable key
  at the very end of a linked span, so the browser never continues the anchor.
- `packages/schema/src/text.ts` `insertPlain` and `insertAt`: a pure insertion at the end of a
  linked run leaves the link (the letters keep the run's other marks) unless the run that starts
  there carries the same address (the caret is inside the link). Google's rule; measured before
  the change: the DOM had "today" outside the anchor and the document put it inside

  old expectation that read offset 22 of `MARKED` as "inside" the link (it is the link's end) now

- The preference: `InlineText` takes `detectLinks` (default on) from the Editor's `linkDetection`
