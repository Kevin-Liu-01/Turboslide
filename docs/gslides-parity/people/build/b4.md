### The mechanism, read in the code

Two per instance caches sit between a choice written on one instance of the blob tier and the plate another instance draws, and the second one is filled from the first, so their windows add up.

1. `access.ts indexFactsFor` keeps one deck index row per principal for `LINK_GRANT_TTL_MS` (5 s). `account.setAvatar` writes the non picture choice onto the index (the carrier of 3.13) and drops the row on the writer's instance alone (`noteAvatarChoice`); the drop bus is process local, so an instance that read the row before the write (a presence post, the boot before the Apply) answers the old choice until its row expires, up to 5 s after the write.
2. `room.ts resolveRequestIdentity` caches the resolution of a request identity for `IDENTITY_CACHE_MS` (5 s), keyed by the principal id alone. The identity it resolves carries the record `requestIdentity` built from the index row of 1, so a resolution made while the row was stale is held for 5 s more, and a resolution made at the end of the row's window holds the old plate until about 10 s after the write.
3. The reload's boot (`write.ts readEditorDeckFn`, `readDraftDeckFn`) and every presence post read through both, and the client draws the roster's own row over the payload (own-identity.ts `ownPrincipalOf`; the builder starts from the row when it differs from the payload, `c6e10ede`). So a reload served by an instance holding the old row carries the old choice in its payload, and its first presence post, served by another such instance, draws the old plate on the row; the next heartbeat is 5 s later (`PRESENCE_HEARTBEAT_MS`), and the poll's 10 s bound after the reload lands inside the sum of the two windows.

That is the verifier's second reading exactly: the chip read `initials` 10,048 ms after the reload with the Glyph tab unselected (the payload's choice was the old one, so the builder started from it; no presence post inside the bound came from a fresh instance). The first reading (54 cells against 38) is the same class one row earlier: the `people.mark-renderers-agree` row's Apply of a glyph a moment before, held by an instance's caches, so the payload carried that glyph's seed while the room's row carried the new one, and the two reads of the driver straddled the flip.
