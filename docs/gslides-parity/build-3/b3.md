### 2. Decisions

1. Where the types live. SPEC-3 6.2 prints `Principal`, `AuthContext`, `Capability`, `Decision`
   and `decide()` in one block and names `decide()` as `@turboslide/identity`'s; B1's seam row
   names `AccessRecord`, `Capability`, `Role`, `Decision` in `packages/schema/src/access.ts`,
   which landed in the tree while this stage was in progress. `packages/identity/src/access.ts`
   defines the record types structurally to the JSON of 6.1, so B1's `AccessRecord` (and any
   record `accessRecordSchema` parses) is assignable to the type `decide()` takes: every field
   name and nullability matches B1's, `assetKey` is optional here because a record synthesized
   before the migration has none in some callers, `createdBy` is the string `legacy` on a
   synthesized record as in B1's. Request R4 asks the integrator to make identity depend on
   `@turboslide/schema` at merge 1b and replace the duplicated record types with `import type`
   from `@turboslide/schema/access`, keeping `Principal`, `AuthContext`, `Decision` and `decide()`
   here. Until the package is installed, identity imports nothing from another workspace package,
   which is why its tests and typecheck pass today without a `package.json`.
2. The seal. 7.1 says "seals it with h3's seal"; the framework's `sealSession` and
   `unsealSession` (`@tanstack/react-start/server`) take the request event from the async
   context (`getH3Event()`), and `readPrincipal(request)` must work from a plain `Request` (the
   agent routes, the unit tests, B4's `authorize()` call sites). h3's underlying `seal` is a
   transitive dependency (`iron-webcrypto`) that no package declares. The cookie value is
   therefore `v1.<base64url payload>.<base64url HMAC-SHA256>` through WebCrypto, the payload the
   id and the issue time in milliseconds; a random UUID carries nothing to encrypt, so integrity is
   the property the cookie needs, and `crypto.subtle.verify` is constant time. Recorded as a
   deviation (section 3) for the integrator; switching to iron's seal later changes one module and
   the format version.
3. The cookie name off localhost over plain http. `__Host-` requires `Secure`, which browsers
   accept from https and from localhost. A dev server reached from another machine over plain
   http (research 09 6.5's LAN case) cannot set it, so `anonymousCookieName(request)` answers
   `ts_id` there with the same attributes minus `Secure`; the reader accepts both names, and a
   hosted deployment only ever mints the prefixed one.
4. The secret's three sources. `TURBOSLIDE_SESSION_SECRET` when set (at least 32 characters); on
   a checkout a generated 64 hex character value at `.turboslide/session-secret` (mode 0600, the
   folder is gitignored), so `pnpm dev` needs no variable and the identity survives a restart (03
   D2); hosted without the variable, an HMAC of `TURBOSLIDE_TOKEN` under a fixed label, so every
   instance agrees, with one warning naming the variable and never a value. The fallback exists
   because previews and production run this round without new variables until the ship step sets
   them (request R7); rotating the bearer would rotate every anonymous identity, which is another
   reason to set the variable.
5. SHA-256 in TypeScript. `labelFor`, `markHash` and `preferredHueSlot` are synchronous because
   the chrome computes them while rendering; WebCrypto's digest is a promise and `node:crypto` is
   out of a browser safe package. The block function is 90 lines and pinned to the published
   vectors.
6. The name rules use the full Unicode security tables, not a subset. `confusables.json` (126 KB
   after formatting) and `identifier-status.json` (32 KB) are imported by `names.ts` only, so the
   browser bundle carries them only where a page imports the name rules (the prompt validates on
   the server through `account.setName`). Script detection uses the engine's own
   `\p{Script_Extensions=...}` tables against UAX #31's Recommended scripts list, so Limited Use
   and Excluded scripts (Cherokee included) are refused at any mixture; the Moderately Restrictive
   level is computed as UTS #39 5.2 states it. Digit systems come from a generated list of the 76
   `Nd` zero code points.
7. A third refusal sentence. 6.8 fixes two sentences for the prompt (reserved, already in use).
   A name that fails the validity rules (empty, too long, no letter, a bidi control, a refused
   character, a mixed script, mixed digits, edge punctuation) gets "Use 1 to 40 letters or digits
   in one script", which says what to do next and names nobody. The three are
   `NAME_REFUSALS` in `names.ts`; request R5 asks B6 to mirror them in `menus/strings.ts`.
8. The reserved list is 7.2's plus 10 F44's: `administrator`, `support`, `moderator`, `general
translation`, the role words `editor`, `commenter`, `viewer` and the trust word `guest`.
   A reserved word, a label word alone, the label grammar and a blocked word all answer "That
   name is reserved", so the sentence never says which list matched.
9. The LDNOOBW check is a word boundary match on the case folded skeleton, English always and
   the request's `languages` when a list for the primary tag exists; only `en` ships this round
   (the other lists are one fixture each when a request needs them). "Bismuth" and "Analyst" pass
   because the match is by word, which is 11 5.3 item 6's rule.
10. `decide()`. The three argument call is the seam B4's `authorize()` makes; the fourth
    argument holds `now` for the expiry checks and `missingRecord: 'notFound'` for R8, when a
    missing record stops synthesizing `open: editor`. The published token is hashed inside
    (`tokenHash` over the package's own sha256), so no caller supplies a hasher. The cells follow
    09 2.1 with `readComments`; the link visitor and the legacy `open` mode never get `share`,
    `settings`, `trash`, `restore`, `remove`, `publish`, `transfer` or `follow` whatever the link's
    role (the "Link visitor" column); an agent's cells are its owner's intersected with its scopes
    where `readComments` is granted by `read` or `comment` (B1's `SCOPE_CAPABILITIES` agrees) and
    `transfer` and `follow` are never a token's; `follow` also needs an account with a grant or
    the ownership, so anonymous principals and link visitors cannot be followed (4.4). The highest
    role across the owner, grants, exchanged links and the open mode wins; a tie prefers the
    grant over the link over the open mode. The 403 member carries `capability` for the body of
    6.2 and there is a 410 `gone` member for a revoked publish token (6.4); B4's local `Decision`
    already has the 410 member.
11. The principal record. The fields of 7.1 with `notificationSettings` as Google's three levels
    (`all`, `forYou`, `none`; the default `forYou`, Google's owner default is unverified, 0.55) and
    `livePointers: { collaborators: true, mine: { [deckId]: boolean } }` (4.6: the own pointer is
    per deck, off by default). `KvClient` is the three ioredis methods the store needs (`get`,
    `set` with a millisecond TTL, `del`); the TTL is the store's on Redis and the record's own
    `lastSeenAt` plus 90 days on the file store, and both reject an expired record on read so the
    two tiers agree at the boundary. The file store names files by the id with every character
    outside `[A-Za-z0-9_-]` replaced, which only touches `agent:<tokenId>`; the three prefixes
    keep the names apart.
12. Hues. `hueFor(slot)` is the table; `preferredHueSlot` is `sha256(principalId)[0] mod 6` plus
    one; `assignHueSlot(preferred, held)` is the room's rule and lives here so B2's roster and B6's
    presence slot share it. `markSpec` colours only when the caller passes the granted slot, so a
    stored surface can never carry a hue by accident. The test recomputes the WCAG ratios (every
    hue at 3:1 or better against `#070707`, `#ffffff` and `#f2f2f0`) and the pairwise CIE76
    distances under the Machado protan and deutan matrices (at least 20 delta E), the floors of
    11 2.2.
13. Marks. `markSpec` is complete; `renderMarkSvg`, `renderMarkBits` and `renderMarkPng1` wait
    for `@turboslide/effects` to be installable from identity (`bayer8`, `encodePng1`), which is
    the integrator's `package.json` (R1). The PNG renderer will live on its own subpath
    (`./marks-png`) because `packages/effects/src/png1.ts` imports `node:zlib`, and a browser safe
    entry must not pull it in; `renderMarkSvg` and `renderMarkBits` stay on `./marks`.
14. `resolvePrincipal` takes synchronous lookups (`record`, `alias`, `account`, `token`) the
    caller fills from the stores it holds, so the chrome, the CLI and the server resolve one way
    from their own caches. An author string that is none of the three formats (a round one or two
    `Author.name`) resolves as a guest with that text, so old records render honestly as typed
    text rather than as a person; an aliased anonymous id renders as its account with the check
    badge; a missing or deleted account renders as "Deleted account".

### 3. Deviations from SPEC-3, recorded for the integrator and Kevin

- 7.1 "seals it with h3's seal": the seal is an HMAC-SHA256 through WebCrypto (decision 2), not
  iron's encrypt and sign. Same cookie name, attributes and lifetime; a format version in the
  value.
- 7.1 `__Host-ts_id`: the name is `ts_id` on a plain http request off localhost (decision 3); on
  every hosted request and on `pnpm dev` at localhost it is the prefixed name.
- 11.4 `TURBOSLIDE_SESSION_SECRET`: a hosted deployment without it derives the secret from
  `TURBOSLIDE_TOKEN` and warns (decision 4) instead of refusing to boot.
- 6.2's `Decision` gains `capability` on the 403 member and a 410 `gone` member (decision 10).
- 11 4.1: the given name check of the label words against the SSA national baby names data has
  not run (the data is a zip of yearly files no report fetched); the LDNOOBW check has. The list is
  provisional on that one test, as the report says.

### 2. Decisions

1. The mark's raster and its text are two layers. `renderMarkBits` draws the plate, the ring and
   the badge; `renderMarkSvg` emits that raster as one `<path>` (rows merged, so a 24 px chip is a
   few dozen rects and a 256 px preview a few thousand) and adds the initials as an Inter `<text>`
   and the picture as an `<image>`. "1,000 marks equal in SVG and PNG" (16.6) is asserted on the
   raster: the PNG's bits equal the SVG's path cells for every spec, size and theme. The PNG of an
   initials mark is therefore the plate without the letters; a bitmap font would have put a second
   drawing of every letter beside Inter's. B6 may prefer `renderMarkPng1` as a data URL for the
   256 px builder previews (the SVG at 256 px weighs about 100 KB).
2. The Bayer fraction is approximate at chip sizes: an 11 by 11 cell window over the 8 by 8 screen
   is not a whole tile, so density d lights about d eighths, within 0.1, and a denser plate never
   unlights a cell of a lighter one; the test pins that rather than an exact count.
3. `@better-auth/api-key` and `@better-auth/passkey` are not in this checkout (better-auth 1.7
   ships both as separate packages). The API key records are Turboslide's own table with the
   plugin's columns, so a later swap reads the rows; the passkey plugin is off and
   `signInMethods()` reports the sentence "Passkeys arrive once the address is final" until the
   domain is fixed (0.20) and the package is installed (R10).
4. The bearer resolver is synchronous because the routes that exist call `requireAgentAuth` without
   an await (B4's `serve()`). `node:sqlite` reads synchronously; Postgres answers from a cache
   refreshed every 5 s and after every write in the process, so a revocation on another instance
   lands within that window, the class of the kill switch cache (0.33).
5. The static bearer is confined to `admin.bootstrap` once a key record exists (09 6.1), and valid
   for everything before, so production, which has no database this round, keeps today's rule.
6. The static bearer's and a checkout's contexts carry `admin: true` on the principal, so
   `decide()` answers every cell with `via: 'admin'` (B4's interim table did the same through the
   agent's scopes); the author of such a request is `agent:bootstrap` or `agent:checkout`.
7. The magic link and the code travel in one mail: the magic link plugin's `sendMagicLink` asks
   the OTP plugin's server only `createVerificationOTP` for a code and composes one mail through
   the templates; the OTP plugin's own `sendVerificationOTP` sends a code only mail when its route
   is called on its own.
8. Sign in limits (03 H; 10 F42): three mails per address per ten minutes in the application (the
   address hashed under the deployment's secret, never stored; past the cap the answer is the same
   200 and no mail leaves), ten per IP per hour in the library's limiter, three attempts per code.
   A checkout's test run turns the library's limiter off with `TURBOSLIDE_AUTH_RATE_LIMIT=off`; a
   hosted process ignores the switch.
9. `BETTER_AUTH_SECRET` is derived from the identity cookie's secret when unset, so a checkout
   needs no variable; the library's cookies are `ts.session_token` and its companions (the library
   has no `__Host-` form; 7.4 allows the prefix "where the library permits it").
10. The account session and the anonymous cookie coexist: sign out (the library's) keeps the
    anonymous cookie, Forget this browser replaces it and clears the mirrors through the response
    header `x-turboslide-forget: 1` beside the new cookie (the boot script and the room client read
    it; B2 and B6 requests). The account session is not ended by Forget this browser.
11. Per deck name uniqueness reads the deck's version log by default (`namesInVersionLog`: the
    human authors other than the caller and the generated labels); B2 binds the roster and the
    owner through `AccountActionDeps.namesInUse`.
12. The picture avatar's URL prefix travels on the choice (`picture.base`), so the chip's URL is
    one string join on every surface, hosted (the public store's URL) and on a checkout
    (`/api/avatar/u/<key>`).
13. The digest queue and the request batcher are in memory per instance and flushed by whoever
    holds them (B2's inbox on its timer, a scheduled function hosted); the mail switch is read
    through `resolveRecipient`, which B2's notification settings answer, and the unsubscribe
    handler calls `setEmailOff` (a seam of the same store).
14. The e2e specs run against the file store, not the tmp store the round two exception names:
    `agent-http.spec.ts` (round one) seeds `decks/e2e-agent` and reads `deck.json` back from disk,
    and `accounts.spec.ts` seeds an access record file the same way; a tmp store would not see
    either. Both specs remove what they create.
15. `/device` is reached by a same origin navigation in the spec because B4's CSRF filter covers
    `/device` on GET and TanStack's check accepts `Sec-Fetch-Site: same-origin` only; the row that
    types the address is marked `test.fail` with the reason and flips when the filter changes
    (request R11).
16. The round one row "the open editor shows the agent write" no longer reads the external
    revision banner: under B2's room the agent's write arrives live and the banner retires for
    live edits (SPEC-3 11.5 R4); the row keeps its budget (the revision advances within one
    second) and reads the author from the version log. Recorded as a change to an existing test
    made for the specification's own reason, not to pass.

### 1. The reading of finding 18

Finding 18 says the `/s/<token>` exchange on the preview answers 403 `forbidden` to every curl
navigation, with or without the identity cookie, cross site or same site. The body in the
verifier's log, `{"error":{"name":"Error","status":403,"code":"forbidden"}}`, is produced by one

`{ error: 'forbidden', capability }`), so `isNavigation()` saw fetch metadata that was not a
navigation on all five variants, including the one the probe believed carried no `Sec-Fetch`
header at all.

The probe was a Node script (`preview-s-exchange-and-quota.log` was written by a `.mjs`, not by
curl), and Node's `fetch` cannot make a navigation: undici appends `sec-fetch-mode: cors` to every
request and overwrites a caller's `navigate` (`b3-fix/undici-probe.mjs` against a local listener:
no headers gives `sec-fetch-mode: cors`; `navigate` plus `document` plus `none` arrives as
`cors, document, none`; `redirect: 'manual'` changes nothing). SPEC-3 6.4 refuses `cors` and
`no-cors` by rule, so the 403 was the route doing what the spec asks, on the preview as it would
locally. The second hypothesis of the finding, a stale record read through the 60 s cache, would
answer 404 (the 404 page), never 403; it is real all the same and is measured in section 2.
