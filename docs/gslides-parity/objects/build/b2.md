Why the row tracks are `auto` and `minmax(<height>px, auto)` and not the `minmax(<row height>, 1fr)` docs/OBJECTS.md 3.3 item 3 wrote. A track whose minimum is a length turns its item's automatic minimum size off (CSS Grid 6.6: the content-based minimum applies only to an item spanning a track whose min sizing function is `auto`), so in a box shorter than the rows the item overflows its track instead of growing it; measured on the first drive with `minmax(54px, auto)`: forty words in the 320 px box gave a 211 px track under a 314 px cell, the text past the last rule. A `1fr` maximum is worse still: with a definite box the flexible tracks share the box and never grow past it. An `auto` track keeps the content-based minimum, so an empty row stands at its line box (the sheet's zero width space, 54 px at 20 px with the rule, the number `tableRowTrack` states), a wrapped cell grows its row, and `align-content: stretch` on the positioned table shares the extra evenly among the auto tracks, which is the behaviour the item describes. A set row height keeps `minmax(<height>px, auto)`, Google's minimum row height, and a table whose rows all carry heights (after a row seam drag, which writes every row) holds its text through the autofit: `readTableRows` reads a row's drawn pitch as never below its text, so `tableGrowMutation` writes `pos.h` up and the tracks get the room.

### The rule, a proposal

docs/OBJECTS.md 3.3 item 3 names the measured autofit for a command ("`commitCanvas`'s `withAutofit` for a command"): the rows' drawn height read on the hidden sheet and `pos.h` written up when they are taller than the box. This round's fix applies a reducer level rule instead for a command that adds rows: the box grows by the added rows' tracks in the same write, whatever the box held. The reasons: the menu's route ends in the store with no stage to measure on (route 1 above), so the measured autofit cannot cover the path a seller uses most without re-routing every plan through the stage; the arithmetic is exact for an added row (an empty row's `auto` track is its line box with the paddings and the rule, `tableRowTrack`, the number the grid gives it), so the ring meets the last rule in every case the measure would find, wrapped rows included (the rows that stand keep their drawn heights since the box grew by the new row alone); it is the edge "+"'s rule (`edgeInsert` grows by the last row's drawn height) and Google's (a row inserted grows the table by its height); and it covers the agent surface (`table.insertRows` over HTTP and MCP), which no stage autofit reaches. Where the two rules differ, a box with slack: the measured rule re-shares the slack and the rows get shorter, this rule grows the box by the row and the rows below stay where they drew. The integrator's sentence for 3.3 item 3 is request 5 below. The measured autofit stands for the paths that already run it (a burst, a resize) and `tableGrowMutation` is unchanged.
