# Turboslide API

Every operation is one named action; the CLI subcommands, the MCP tools and the HTTP endpoints are generated from one table.

## Discovery

1. CLI: `turboslide info --json` and `turboslide slides --json` from a checkout with a `deck.json` upward, or `--deck <dir>`.
2. MCP: `turboslide mcp` over stdio (`--deck <dir>`, `--derived <dir>`, `--author agent:<runId>`), or streamable HTTP at `POST /mcp?deck=<id>` on the studio (initialize first; the `mcp-session-id` header carries the session; `x-turboslide-author` names you). Tools are `deck_<action>` for every implemented action; a tool the server does not list is not implemented, so `tools/list` is the honest capability check. `deck_goto_slide` appears while a studio page is attached to the deck and runs in that page. Resources: `deck://<id>/manifest`, `deck://<id>/slides/<slideId>`, `deck://lint/<id>`, `deck://render/<slideId>/<theme>`, `deck://sheet/<theme>`, `deck://grammar`, `deck://catalog/blocks`, `deck://catalog/icons`, `deck://theme`. The `deck_review` prompt holds the judge lenses.
3. HTTP: `GET /api/agent` for the manifest with the execution rules and what the instance implements, `GET /api/actions/<id>` for one action's contract, `/openapi.json` for the full contract, `/llms.txt` and `/llms-full.txt` for the guides. The studio runs on port 4321. Round three's MCP resources are `deck://<id>/comments`, `deck://<id>/presence` and `deck://inbox`, with `resources/subscribe` (the server sends `notifications/resources/updated` when a comment lands or the roster changes) and `listChanged`.

Read [references/actions.md](references/actions.md) for every action with its input, transports, CLI usage, MCP tool and milestone. An action whose milestone has not landed answers `NotImplementedError` (501); do not retry it.

## The Google Slides parity actions

Fourteen actions cover what a person does in the editor's menus, on every transport that fits them (the generated tables carry the exact inputs). `slide.new` inserts one slide from a layout id with empty Texts and `template` set (`turboslide slide new --layout <layout> --after <slideId>`; the placeholder prompt shows in the editor and an empty Text exports nothing); `slide.duplicate` copies slides after the last selected; `slide.skip` sets or clears `skip` on several slides in one write (a skipped slide leaves the show and the downloads); `slide.applyLayout` keeps the content and never refuses; `slide.import` brings slides and their assets from another deck (`turboslide slide import <sourceDeckId> <slideIds> --after <slideId>`). `block.duplicate` copies blocks with fresh ids, offset 16 px on a freeform slide; `text.replaceAll` replaces a word across every Text and note in one write and counts the replacements (`turboslide text replace <find> <replace> [--match-case]`). `deck.list`, `deck.copy`, `deck.trash`, `deck.restore` and `deck.remove` (`confirm: true`, never over MCP) are the home page and the trash as actions; `deck.set` writes `/title` and `/defaults/*`. `export.text` returns the deck's plain text (`turboslide export txt`), `export.run` takes `format: 'pdf'` with `includeSkipped` and `includeNotes`, `render.slide` takes `format: 'jpg'`, and `view.zoom` (window and MCP) sets the stage scale. Every mutating action takes `baseRevision`; the ones that write several slides do it in one write, so one undo reverts the whole change.

## The canvas actions of round two and the collaboration actions of round three

Every slide is a canvas (docs/gslides-parity/SPEC-2.md section 1): the first canvas write on a slide that is not on the freeform layout converts it losslessly, block by block, measured on a 1x sheet, and the conversion travels in the same write as one `slide.replace` first, so one undo restores the kind. Thirty six actions join the table (105 in all), on every transport that fits them: `slide.toCanvas` (`turboslide slide to-canvas <ids>`) converts with nothing else in the write; `slide.setLayout` to `freeform` is the same measured conversion; `block.set` with a `/pos` path, `block.move` with `z`, `block.insert` with a positioned block (`block insert --pos x,y,w,h`), `block.align` (one object aligns to the sheet), `block.distribute`, `block.order`, `block.duplicate` (16 px offset, on top of the stack) and `diagram.insert` convert first. Objects: `block.rotate` (`--by` or `--to`, `--about each|selection`), `block.flip`, `block.group`, `block.ungroup`, `block.regroup`, `block.crop` (`trim`), `block.mask`, `block.adjust`, `block.resetImage`, `block.shadow`, `block.setAlt`, `block.autofit` (`none|shrink|grow`; `--apply` measures and steps the size down or writes the height), `shape.set` (one of the 135 presets, `adjust`, fill, stroke, width, dash, radius), `line.set` (the seven line kinds, the ten decorations, `connect` to a target's connection site, which follows the target when it moves; `--detach`). Text: `text.style` (the marks `i u s sup sub color highlight` on a plain text range, written as the mark span `[text]{i}`), `text.case`, `text.insert`, `text.list` (`marker bullet|number|rule`, the fifteen presets, `items` and `level` 1 to 9), `text.spacing`, `text.columns`, `text.indent`. Tables: `table.merge`, `table.unmerge`, `table.insertRows`, `table.insertColumns`, `table.deleteRows`, `table.deleteColumns`, `table.distribute`, `table.cellStyle` (fill, a border with weight 0 for none). Charts: a `chart` block with `kind`, `categories` (12 at most) and `series` (6 at most), `chart.setData`, `chart.setKind` (a pie keeps its first series). Backgrounds: `slide.setBackground` and `deck.setBackground` (a colour fill; a background picture is a `picture` block at 0, 0, 1600, 900 at the bottom of the stack, `block.order --move back`). Guides: `deck.guides` (`add`, `remove`, `move`, `set`, `clear`), reported by `deck.info` with `counts.canvas`, `counts.charts` and `counts.guides`; `slide.list` reports `canvas` and `objects` per slide. `slide measure <ids> --json` prints the boxes and the text fit the conversion reads without writing, which is what the hosted studio runs through its render worker. The measured `pos` are identical between the editor, the CLI and the hosted studio in Chromium; the CLI measures in the light theme. Sixty four actions cover multiplayer, comments, sharing, accounts and dithered backgrounds (169 in all; docs/gslides-parity/SPEC-3.md section 12), on every transport that fits them, on a checkout with no server and on a hosted studio with `--to <url>`. Text edits are `text.splice` (insert or replace a range of a Text by plain offset, with the run flags) and `text.mark` (a mark over a range); both transform against concurrent edits on the server, so two writers converge, and `text.replace` keeps its meaning. Comments: `comment.add <anchor> -m <text> --mention <who> --assign <who>` (anchors are `slide:<id>`, `slide:<id>#<blockId>`, a text range, a table cell, a section or the deck), `comment.reply`, `comment.edit`, `comment.delete` (a tombstone; `--restore` within 30 days), `comment.resolve`, `comment.reopen`, `comment.done`, `comment.assign`, `comment.react`, `comment.list` (`--for-me`, `--since <revision>`, `--author-id <who>`), `comment.get`, `comment.link`; `notification.list --unread`, `notification.markRead`, `notification.settings`; `activity.list`; `version.diff <from> <to>` groups a revision window's mutations by author and slide. Sharing on one access record with its own revision: `share.get`, `share.setGeneralAccess --mode restricted|link --role viewer|commenter|editor`, `share.createLink`, `share.rotateLink`, `share.revokeLink`, `share.stop`, `share.invite`, `share.setRole`, `share.remove`, `share.setExpiry`, `share.settings`, `share.requestAccess`, `share.listRequests`, `share.respond`, `share.transferOwnership`, `share.acceptOwnership`, `share.declineOwnership`, `share.claim`, `deck.publish`, `deck.unpublish` (`share.emailCollaborators` is declared and lands in round four). A missing right answers 403 (`ForbiddenError`, the sentence "This presentation is not available to you, or does not exist." is a 404 when the deck must stay hidden) and a revoked link 410 (`GoneError`); the CLI exits 2 with the status in the JSON answer. Presence and sync: `presence.list`, `presence.follow`, `presence.unfollow`, `presence.pointer`, `sync.status`; `deck.follow` (CLI only) tracks a hosted deck into a checkout byte for byte. Accounts: `account.me` (`--avatar-png` on the CLI), `account.setName` (the name rules refuse a reserved, confusable or unsafe name with a fixed sentence), `account.setAvatar`, `account.decks`, `account.sessions`, `account.signOut`, `account.forget`, `account.tokens.create|list|revoke`; `turboslide login --to <url>` runs the device flow and stores an API key in `hosts.json` (`kind: api-key`), `logout` revokes it; `admin.flag`, `admin.bootstrap`, `admin.assignOwner`, `admin.migrateStorage`, `admin.mail.list`. Backgrounds: `picture.dither` (`turboslide block dither <slide>#<block> --photograph | --neutral | --pattern ... | --off`), `picture.materialize` (`--dry-run`, `--prune`, `--scale`; every export reads the files it writes), `slide.setBackgroundPicture` (`--asset`, `--file`, `--url`, `--dither`, `--no-replace`) and `slide.setBackgroundMaterial`. Identity on the transports: hosted, the author is the API key's record (the `x-turboslide-author` header names the run only; `?author=` is ignored) or the browser's session, never the body; on a checkout's dev server a call without a bearer and without a cookie is the checkout holder (`agent:localhost`, the admin of the matrix), so a curl walk sees one caller across its calls; the CLI's `--author` is the file store's principal `local:<name>`. The share, comment, notification, account and admin ids are refused through the window API without the page's nonce (SPEC-3 6.6); the dialogs carry it.

## Write protocol

1. Read the slide you will touch (`slide.get`) and keep its `revision`.
2. Make the smallest change: `block.set` for one property, `slide.update` with a mutation list, `slide.replace` only for a whole slide.
3. Send `baseRevision` and your author: `--author agent:<runId>` on the CLI, the `x-turboslide-author` header (or `?author=`) over HTTP and on the MCP initialize request. A stale revision returns 409 with `currentRevision` and the current document: re-read it, rebase your change, retry once.
4. Take `slide.lease` before a series of writes to one slide. An agent write to a slide another author holds is refused with 409 and the holder unless `force` is set (`--force`, `?force=1` or `x-turboslide-force: 1`); a human's write warns and goes through. Release the lease when done.
5. Re-read from the response. Writes return the normalized slide and its findings, so the re-read is free; text may have been canonicalized.

## HTTP request shape

- `POST /api/actions/<id>?deck=<slug>` with the action input as one JSON object; `deck` defaults to the instance deck. Bodies are capped at 1 MB (25 MB for asset uploads).
- Auth: `Authorization: Bearer <TURBOSLIDE_TOKEN>` on every deployed instance; an instance without a token serves localhost only and answers 401 elsewhere.
- Errors: `{ error: { name, status, message, code?, pointer?, currentRevision?, current?, holder?, milestone? } }`. An unknown field is 400 with `code: unknown_field` and the pointer to the extra key.

## Contract rules

- Unknown fields are rejected with `unknown_field` and a JSON pointer; unknown data survives only under `ext` on a slide, a block or an asset.
- Slides, sections and assets are slugs; blocks are `slideId#blockId`; fields are JSON pointers. Never address by number.
- `section.set` is the only way to reorder; numbers and counts derive from it.
- Errors are `TypeError` (400), `ForbiddenError` (403), `RangeError` (404), `ConflictError` (409), `GoneError` (410), `NotImplementedError` (501), `Error` (500). Do not retry unchanged invalid input; a 403 or a 410 is not retried either.
- Over MCP a tool result carries the output as JSON text and as `structuredContent`; a list is `{ items, count }`; a refusal is `isError` with the same error body in the text. Render tools return PNGs as image content, at most 12 per call.

## Completion

A write is complete when the response carries the new revision and the findings list for the slide. Then render both themes and lint (`turboslide-verify`); a claim about the deck names the revision it was verified at.
