### 2. Decisions inside the specification, recorded once

1. The poll is a short poll: `POLL_MS` 0 on the client and `POLL_MAX_MS` 0 on the server, so every poll answers at once with the queued commands or `[]`. SYNC.md 3.10 asks for the empty answer at once when the instance holds no session and a 20 s pause; the cost row's model (3 polls a minute idle, "about 50 ms of memory") only adds up when no poll is held anywhere, so the hold went to zero for a known session too. A command therefore waits for the page's next poll: up to 20 s when the page is idle.
2. The quick pace after a command: an agent's second and third `deck_goto_slide` land within about a second (`HOT_PAUSE_MS` 1 s for `HOT_WINDOW_MS` 30 s after a command, then the 20 s pause returns). The cost is at most 30 polls of a few milliseconds per command burst and nothing while idle, so the cost rows read the same; without it every command of a sequence would wait up to 20 s. Measured: 18,854 ms for the first command of a sequence, 37 ms for the second (section 5).
3. `DEFAULT_COMMAND_TIMEOUT_MS` 30 s. The pause is 20 s and the earlier 15 s timeout would have failed about a quarter of the commands to an idle page. The test pins `EMPTY_ANSWER_PAUSE_MS + 5 s <= DEFAULT_COMMAND_TIMEOUT_MS`.
4. The hidden rule applies to every page that uses the hook, the editor included (`cost.editor-hidden.calls` is an editor row): the editor's `SessionBridge` (`editor/shell-bridge.tsx`, not this lane's) keeps its prerender gate and the hook treats a prerender as hidden as well, so both readings agree.
5. "An MCP attach names the deck" (question 3's default) is realised as the address the agent opens: nothing on this tree opens a viewer page on an agent's behalf (the CLI has no open command; the Share dialog, the /decks Present links and the home links are a person's), the one agent opener is the MCP e2e's headless page (R1), and a tab cannot learn of an MCP session without a request of its own. So the flag is the mechanism and `deck_goto_slide` reaches a viewer or show tab only when it was opened for an agent, which is the default's own sentence.
6. The embed frame follows /deck: with `?agent=1` it attaches (it never attached before), without it the host page drives it through the frame protocol as before. The rule is one predicate on every viewer address.

### 6. Findings for the integrator and the verifier

1. A closed tab lingers in the registry until the 45 s sweep and takes the next command. A page Playwright closes (and a tab a person closes) never lands its detach: the effect cleanup's fetch dies with the page, as it did before this round, so `attached()` (the most recently seen page on the deck) picks the dead page and the command waits the whole `DEFAULT_COMMAND_TIMEOUT_MS` (now 30 s, was 15 s) before its 504. Measured in the first agent run: the closed `/embed` page's session took a `deck_goto_slide` and answered "the studio session did not answer view.goto within 30000 ms" after 30,005 ms (`build/b5/agent.json` of 20:21Z). Not a regression of this round (the mechanism is the same, the wait 15 s longer) and outside its P0; the fix for the round after is a `pagehide` beacon (`navigator.sendBeacon` to the detach server function needs its URL on the client, which the TanStack client stub does not expose here) or a shorter `DEFAULT_STALE_MS` (35 s would still cover the 20 s pause plus the 10 s hidden grace); named as R7 for the integrator's list, not made.
2. The browser's own hide is not reproducible under Playwright. A covered tab, a popup the page opens, a window minimized over CDP (`Browser.setWindowBounds`) and a tab created in the same window over CDP (`Target.createTarget` with `newWindow: false`) all read `document.visibilityState` `visible`, headed and headless, with and without Playwright's occlusion flags (`ignoreDefaultArgs`), 20:14 to 20:18Z. The driver keeps its pages visible. So `cost.editor-hidden.calls` is not driven by a browser hide on any Playwright base, and its row says so; the product's hidden path is covered three ways instead: the unit test over fakes (section 3), a synthetic `visibilitychange` in the Playwright page (`request-log.mjs --synthetic-hide 1`: the getter answers `hidden` and the event fires, the timers and the network real), and a real hidden page in the Claude desktop app's Browser pane (section 5), whose tab reads `hidden` while the pane is not displayed and never attached. B4's probe reads the same `visible` and writes the row not driven; the verifier should drive the row by hand on the preview (open the editor, switch tabs, read `/api/agent?deck=` at 15 s: no session; switch back: one session within a second).
3. `view.goto` is not on the http transport (`schema/actions.ts`: `transports: ['window', 'mcp']`; `/api/actions/view.goto` answers 404 `not_on_http`), so the drive an agent has is `deck_goto_slide` over MCP; the sentences in `docs/sessions-polling.md` and the hook's earlier comment that name "`view.goto` over /api/actions" describe a path that does not exist on this tree. R3 corrects the manifest's sentence; the docs half is the integrator's.
4. On the memory tier the presence heartbeat is not an HTTP request (no `POST /api/decks/<id>/presence` in any local window), so the idle editor's function requests here are the poll's alone; the blob tier's heartbeat (12 a minute today) is what the production row adds (R6).
