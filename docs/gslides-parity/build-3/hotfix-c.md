## 4 Requests and observations for the verifier and the ship step

1. `apps/studio/src/routes/new.tsx` (no fixer owns it; the ship step or the verifier). After the
   first write on `/new`, `probe-skeleton.mjs` read the live editor and an `EditorSkeleton`
   together in the document for about 600 ms, both `display: grid`, the address already moved to
   `/edit/<id>#s/<slide>`: the skeleton is the route's pending presentation offered for the
   navigation the editor makes after the write (the hash and search follow the new slide), and it
   paints over the editor for TanStack's `pendingMinMs`. On `/edit` a mode change and a slide
   change showed no skeleton. A `staleTime` on the `/new` route (its loader must never run twice
   for one page: a second `readDraftDeck` would be a second draft) or `pendingMinMs: 0` on it
   would close the window; in the same window `window.turboslide` is absent for a moment (`registerStudioAutomation` runs its cleanup and re-installs when the owner element remounts), which is what the round two specs met as `TypeError: Cannot read properties of undefined (reading 'studio')`. This fixer did not change the route because the fix needs the undo
   after the first write (SPEC-2 8.6, `hygiene.spec.ts` row 2) re-verified with the change in
   place. The specs no longer depend on the window (section 2, row 1).
2. Fixer A (the edit route and the room client, finding 33). `ten-tasks` task 4 met
   "baseRevision 3 is stale; the document is at revision 4" because the page's
   `describe().state.revision` follows a server side write (`asset.add`) a moment after the
   write answered; the spec now waits for the revision to move before the next write bases on
   it. With finding 33's fix (the room client rebases or the page waits for the catch up) the
   wait is moot and can stay.
3. Fixer A (`text-editing.spec.ts`). The same `text.replace` to `text.splice` re-pin this fixer
   made in `editor.spec.ts` (SPEC-3 0.4, 3.1) applies to the typing rows there.
4. The check chain (`scripts/check.mjs`, the ship step). The anonymous export quota is 5 per day
   (`ratelimit.ts`, SPEC-3 8.14), counted in memory on the memory tier and reset by a server
   restart. Before this round the route charged it on every POST of a batched export, so the
   fixture's 10 batches could never finish for an anonymous caller (`export-batch.spec.ts` met
   429 `exportsPerDay` at batch 5 on this fixer's server after one earlier run); the route now
   charges the plan and the single call path only (section 2). On one chain server the specs
   still spend the quota: `dither` 2, `charts` 1 (the TXT export), `export-batch` 1 (the plan);
   a fifth anonymous export on the same server process is refused. A quota switch for a
   checkout server would remove the dependence on the count; none exists today.
5. Fixer A (`packages/realtime/client/room-client.ts`, the finding 33 work in progress at the
   time of this fixer's runs). The uncommitted change that holds a page's first flush until the
   replay has caught the stream up (`caughtUp`, `noteCaughtUp`) held the first write of a freshly
   opened copy for 11 s in `probe-objects.mjs` (a text box drawn on `content-rule` of a
   `deck.copy` of gt-brand: `pending 1` from +311 ms, admitted as seq 1 at +11.2 s, the version
   and the checkpoint only after the next key), while the same page read `sync.seq 0` on open.
   With that state every spec whose first gesture is a write on a just opened page waits on it:
   `objects.spec.ts` ran 46 s in run 1 and hung past 4 minutes in runs 2 and 3, `canvas`,
   `text-styles` and `ten-tasks` carry the same shape. This fixer's final run (section 3) was
   made against whatever state that file had at the time; the rows it stalls are named there.
6. The verifier. A dev server that served a run keeps the rooms of the decks the specs seeded by
   file (`e2e-editor`, `e2e-film`, `e2e-tasks`): a second run against the same server process
   reads the room's document, not the re-seeded files (`editor.spec.ts` row 1 met "Block id
   "table" is already used" on the second run). The chain starts a fresh server per run; a
   fixer must restart theirs between runs. `editor.spec.ts` now skips its seeding when the
   block is there.
