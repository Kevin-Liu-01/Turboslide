# 11 Tables, charts and number slides

Google Slides tables, charts and big numbers against Turboslide's rows, plain, scales, board, matrix, details, tiles and composite blocks, read for the Google Slides parity round on 2026-09-11. Part A is Google from public sources only (help pages, the Slides API and Apps Script references, Workspace Updates posts, third party tutorials); nobody signed in and no editor was opened. Part B is Turboslide at commit `8c7056c` read from the code; nothing was measured in a browser. Part C is the gap table and the two traces the brief asked for. Report 05 (A6, A7, A9, B9) lists Google's menu items, report 02 (4.6) the contextual toolbar with a table selected, report 06 (1.3, 1.6, 1.7, 6) Turboslide's blocks and handles, and report 07 names the pricing slide and every slide with numbers as the slides that change for every prospect. This report adds the interaction model at the keystroke level where a public source states it, the document model on both sides, and the three worked cases: a five by six pricing table, a single big number, and a bar chart of four values.

Source tags: G for Google help pages, A for the Slides API and Apps Script references, W for Workspace Updates, T for third party pages. The list at the end carries every URL with the date it was read. A claim marked "unverified" has no public source in the list; the section near the end collects them.

## Summary

1. Google's table is one object with a cell grid, per edge borders, per cell fill, spans, row heights and column widths, editable in place from the toolbar and the right click menu. Turboslide has no table object. The nearest block, `rows`, is a two column key and value list whose key column snaps to ten widths; `matrix` is a numeric grid with one JSON field for every cell; `board` has four fixed columns; `composite` is a layout grid whose inner blocks cannot be selected on the stage. A five by six pricing table with a header row, right aligned prices and a highlighted column cannot be carried by any block today; it can be hand built from about 38 primitives on a freeform slide and then edited one block at a time.
2. Google documents almost nothing about cell navigation. Its Slides shortcut page lists one table key, the cell border selection chord, and its screen reader guide has no table section. Tab, Shift+Tab, Enter and the arrow keys inside a Slides table are unverified from public sources, and the report says so rather than borrowing Docs' behaviour.
3. Google's chart is a picture of a Sheets chart. The Slides API models it as `sheetsChart` with a `contentUrl` that is "the URL of an image of the embedded chart, with a default lifetime of 30 minutes", and unlinked charts are images. Every edit of data or colour is a trip to the Sheets chart editor followed by Update. Report 07 rule 23 already decided Turboslide should edit chart numbers in place; today Turboslide has no chart block, and `scales` draws a marker on a hairline, not a bar.
4. Google's way to show one large figure is the Big number layout ("Layout with a big number heading") or word art, which resizes like an object. Turboslide's statement slide (72 px display) and the h1 heading (88 px) cover the layout; nothing scales past 88 px without a `type/ladder` finding.
5. Export today: `rows` and `plain` leave as hairlines plus text boxes grouped per row, never as a PPTX table; `matrix`, `scales`, `board`, `tiles`, `details` and `composite` are rasters in Editable text mode because they are not in `NATIVE_BLOCK_TYPES`, although `docs/grammar.md` and the catalog say `scales` and `matrix` export native. In Perfect mode the invisible text layer is built from `data-run` elements only, so matrix numerals, board states and addresses and scale values are not in the text layer. There is no PDF builder; `'pdf'` exists only as a type.
6. The smallest change that closes most of the gap is one new `table` block (columns with widths and alignment, rows of Text cells, a header flag, a per column fill, one border style) with Tab and Shift+Tab moving between cells in `InlineText`, a right click menu with the nine row and column commands, `addTable` in the Editable text exporter, and a `chart` block (kind, categories, series) rendered through the declared diagram grammar and edited as a small grid in the inspector.

### A12 Tables and charts in downloads

Google's download page (report 03 c.2, S9) lists the seven formats and says nothing about fidelity. No public page read states how a table or a chart appears in the downloaded PPTX or PDF. The file model implies the answer: a `table` is a native page element with rows, columns and per edge borders (A1), and a `sheetsChart` is an image URL (A3), so a PPTX download would be expected to carry the table as a table and the chart as a picture, and a PDF flattens both. This is an inference from the API, not a verified download, and it sits in the unverified list.

Two discrepancies found while reading: `catalog.ts` and `docs/grammar.md` classify `scales` and `matrix` as `export: 'native'`, while `NATIVE_BLOCK_TYPES` in `schema/src/export.ts` (the list the exporter and the `export/non-native` lint read) holds heading, paragraph, credit, rows, plain, refs, ladder, panel, text, box, shape and rule only; and `ExportFormat` includes `'pdf'` (`export.ts`, `apps/studio/src/server/download.ts` 83, `export-sync.ts` 31) while `packages/export/src` has a `pptx` builder and no PDF builder, and the format's own doc string reads "Book mode through Chromium print (M6)".

### B2 Interaction model today

- Selecting: a click selects a top level block; Tab and Shift+Tab cycle block selection when nothing is being edited (`Editor.tsx` 635 to 645); the stage keys are inert "inside fields and the editable run" (`Editor.tsx` 610 to 621).
- Editing text: a double click on a run or Enter on a selected block makes the run `contenteditable`; Enter commits, Escape restores, blur commits; Cmd B toggles the weight 500 run, Cmd K the link; paste is plain text with line breaks turned into spaces (`InlineText.tsx` 349 to 383). There is no Tab handler in `InlineText`, so Tab while editing falls to the browser's focus order and leaves the run.
- Rows and items: the inspector adds a blank item at the end and removes one item; there is no insert above or below, no reorder within the list, no column commands (`Inspector.tsx` 486 to 541). Inspector text fields commit on Enter or blur and restore on Escape (`inspector/text.tsx` 12 to 14, 35 to 57).
- Handles: the key column edge (ten snap widths), the scale marker (0 to 100), the freeform move chip and eight resize squares. No per row handle, no gridline drag, no border tool.
- Context menu: the stage binds no `contextmenu` handler; the only one in the chrome is on the sidebar rows (`Sidebar.tsx` 248).
- Colour: `Color` is twelve palette names or a hex flagged `color/off-palette`, on box, shape, rule, text and icon only; no cell or row fill exists on `rows`, `plain` or `matrix`.

### B3 Three worked cases

**A five column by six row pricing table with a header row, right aligned prices and a highlighted recommended column.**

No block carries it as a table. `rows` has two columns; `matrix` has numbers only, centred, with no header text and no fill; `board` has four fixed columns of capture, name, state and note. Two constructions exist:

1. A `composite` with `tracks: '220px repeat(4, 1fr)'` and five cells, each holding six stacked `text` blocks (`typography.align: 'right'` on the price columns, weight 500 on the header row) with the recommended column's cell holding six `box` blocks with `fill: 'plate'`. Loss: no shared row rules (each cell stacks independently, so rows align only while every cell is one line), no gridlines, no header semantics, no per edge borders, no spans, and none of the 30 inner blocks can be selected on the stage; every edit goes through the inspector under the composite. Export: the inner `text` and `box` blocks are native in Editable text (text boxes and rectangles within 3 px) and Perfect carries the page raster with all 30 texts in the invisible layer.
2. A freeform slide with 30 `text` blocks, seven horizontal `rule` blocks for the gridlines and one `box` with `fill: 'plate'` behind the recommended column, ordered with `block.order`, lined up with `block.align` and `block.distribute`. Loss: no table object (adding a row is six inserts and a redistribute; there is no duplicate, group or paste), no Tab between cells, no border tool, no vertical alignment. Export: native text boxes, lines and a rectangle in Editable text; Perfect is the raster plus 30 invisible runs. Neither construction produces a PPTX table in either mode.

**A single big number slide.** The statement slide (`big` at 72 px, `measure` in ch) or a content slide with an `h1` heading (88 px) and a paragraph caption covers Google's Big number layout. Loss: nothing scales past 88 px without a `type/ladder` finding; there is no drag to resize the glyphs the way word art resizes; the number and its caption are two blocks with no shared placeholder. Export: native text in Editable text (GT Inter Display with tracking, SPEC 8.6), the raster in Perfect.

**A bar chart of four values.** `scales` gives four rows with an 11 px marker at `value%` on a hairline between two 18 px labels, which reads as a slider, not a bar; it carries no bar fill, no axis, no printed value, and exports as a raster in Editable text. A declared `dia` block can draw four `rects` with `fill: 'ink' | 'plate'`, `lines` for the axis and `texts` at 18, 20 or 26 px, which is a hand declared bar chart with no data binding, exported at 1x as a raster. On a freeform slide four `shape` rectangles with fill plus `text` labels export as native shapes. None is a chart object: no categories, no series, no legend, no value labels tied to the bars. The `numbers/contradiction` lint (the same noun with different numerals across slides) applies to whatever text carries the values.
