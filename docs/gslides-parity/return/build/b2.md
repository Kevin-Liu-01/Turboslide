### 1. What changed, by RETURN.md item

1. **The cover title takes formatting from one click (2.14 item 1; rows `text.title.*`).**
   - `editor-shell.ts` `tailKindOf` reads the selection through `objectOf`, so a fixed kind's
     field (`pseudoBlockOf`: the title's heading and lead, a statement's big line) takes the text
     tail on one click, as a block does.
   - The first format write converts the slide to a canvas in the same write, the way the Align
     rows do through the store's `withCanvas`: `apps/studio/src/editor/convert-first.ts` (new,
     pure) says which slide a write must convert (a mutation naming a field object that is not a
     block of a fixed kind's slide); `controller.tsx` `commit` measures and puts the
     `slide.replace` in front of the mutations (`convertThenCommit`), so one revision and one undo
     step hold both. Every other write keeps its synchronous local apply.
   - The plans whose store action looks the block up before the write (`text.style`, `text.case`,
     `text.spacing` add rows, `text.indent`) carry the reducer's own mutations in one `slide.update`
     when the target is such a field object (`isPseudoTarget`, `slideUpdatePlan`, `flagEditOf`):
     Italic, Underline, Strikethrough, Superscript, Subscript, the three Capitalizations, Add space
     before and after and the indent rows land on the cover title before it converts. Bold, the
     alignments, the size and the line spacings already planned `block.set` and needed only the
     conversion.
   - `currentSize` (editor-shell) and `shownSize` (ToolbarTail) read a heading's size from the
     theme's CSS (`sheet.css`: h1 88, .big 72, h2 and the mood plate's title 44) where they said
     h1 58, big 88, h2 34; Decrease font size on the cover title steps 88 to 72 instead of 58 to 44
     under a drawn 88 (audit-formatting row 6 read "dom size 88").
2. **A Format menu row on a selected word marks the word alone (2.14 item 2; rows
   `formatting.italic.menu-word`, `.superscript.menu-word`, `.subscript.menu-word`, `.context.selection-rows`).**
   `InlineText.tsx` `CHROME_TRANSIENT_SELECTOR` gains `.ts-menubar` and `.ts-menu`: a press on the
   menu bar or a menu plate parks the session as the toolbar does (`blurVerdictOf`: a menu bar
   title and a menu row park without the refocus, so the keyboard's menu walk keeps the focus),
   the shell's plans read the parked range through the Editor's caret facts, and the write lands on
   the word. This also makes the anchored `Menu` plates of the tails (the Align list, the spacing
   list) transient, which is what let the table tail's Align list open on a cell without ending the
   cell session (RETURN.md 2.4 fix 3). Insert > Text box from a parked session still places its box:
   the press on the sheet lands outside every transient surface and ends the parked session in its
   capture phase (`onDocPointerDown`), which the focus round already relied on for the toolbar; driven
   below (the extra row `insert.textbox.while-parked`).
3. **One history entry per typed field (2.14 item 3; rows `text.fontsize.type-one-undo`,
   `text.format-options.field-one-undo`).** The mechanism, read in the source: Enter commits and
   blurs in one event, and the blur's commit read the draft of the render its handler was bound in
   (`ToolbarTail.tsx` `FontSizeField`, `inspector/fields.tsx` `NumberField`), or the browser fired the
   change event on Enter and again on the blur before the write had landed and the second commit
   compared the typed value with the old prop (`inspector/stepper.tsx`, `inspector/position.tsx`
   `Field`). Each field keeps the typed value in a ref cleared before the write, or remembers the value
   it wrote until the document carries it. RETURN.md named `stepper.tsx` as the Width field's
   component; the Width field is `NumberField` in `fields.tsx` (`geometry.tsx` 185 to 189), and X, Y
   and Rotate are `position.tsx`'s `Field`, so the fix is in all four (see section 3 on ownership).
4. **The 1.15 row writes 1.15 (2.14 item 4; row `formatting.spacing.1-15-value`).**
   `SPACING_STEPS[1].leading` and `SPACING_OF['format.spacing.1_15']` are 1.15, a step of
   `TYPE_LEADING` and of `LINE_SPACING_PRESETS`; Single is 1 and Double 2 as before. The label in
   `model.ts` (B1) is unchanged; `text-marks.tsx` `lineSpacingOption` already read 1.15 as the 1.15
   option.
5. **Clear formatting clears the inline marks (2.14 item 5; row `formatting.clear.inline-marks`).**
   The plan adds one `text.mark` per Text of the block clearing `i, u, s, sup, sub, color, hl, b`
   (`CLEARED_FLAGS`; a link stays) over the whole Text, beside the override removals, in the one
   `slide.update`; "Nothing to clear" only when neither an override nor a mark is present. With a
   range selected in a session (the toolbar button parks it) the marks of that range alone go, as
   Google's Clear formatting acts on the selection. The reducer's inverse (`flagRestores`) brings
   every run back in one Cmd+Z.
6. **Text colour on a shape from the toolbar (2.2 the fix; row `shapes.text.colour-toolbar`).**
   `ToolbarTail.tsx` `colorTarget` `textColor` answers `/color` for a shape whether or not the block
   carries the field yet, the branch the focus round added for text boxes.
7. **The toolbar Align list offers Justify (3.2; row `formatting.align.toolbar-justify`).** The
   list already carried `format.alignIndent.justified`; it now filters its items by `isPresent`, so
   Justify shows exactly when B1's flag change makes the row present and a parked row never leaks into
   the toolbar. Driven here with Tools > Advanced tools on (the flag is B1's).
8. **The kept cell pointer (2.4 fixes 2 and 3; rows `tables.cell.align-menu`, `.align-toolbar`,
   `tables.menu.format-table-*` read it).** `editor-shell.ts` remembers the cell a selection names
   per table (`rememberCell`, `withKeptCell`, `forgetKeptCells`) and fills it into the selection
   `buildMenuContext`, `factsOf` and `tailKindOf` read when a table is selected with no cell, clamped to
   the table's rows and columns; `tableCell` in the menu context is true for any selected table, so
   Format > Table is enabled on the table selected by one click and its rows act on the kept cell or
   cell 1,1 (B5's default); a selected table takes the table tail with or without a cell. Module
   state on purpose, read where the selection is read, so no route wiring was needed.
9. **The deck's name follows the heading (2.18; row `decks.name.follows-heading`).**
   `apps/studio/src/editor/auto-title.ts` (the module `controller.tsx` imports for
   `autoTitleMutations`): a write that changes the title slide's heading renames the deck while the
   name still follows it, that is while the deck is Untitled, or named the heading the write starts
   from, or named the last name this rule wrote in the session (`AutoTitleMemory`, kept by the
   controller); a name typed by hand differs from all three and stays. The heading after the write is
   read on a copy of the slide through the reducer (`headingAfter`), so a burst on a title slide
   converted to a canvas (the heading block) follows too, and a format write with the conversion in
   front of it renames nothing. `typing-key.ts` reads past the appended `deck.set /title`, so the
   bursts of one word still fold into one Cmd+Z.
