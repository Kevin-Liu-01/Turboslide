- `apps/studio/src/server/auth/signin-binding.ts` (new): one better-auth plugin. ## HR-SA#2b: the merge asks first

Closes AUTH-4's second half. Before an anonymous id that owns decks is linked to an account, the person answers "This browser has 3 decks made before you signed in. Add them to kevin@example.test?" with Add Them and Keep Them Separate.

- `apps/studio/src/server/auth/identity.ts`: `linkOrAsk` is the one path to a link. An id that owns no decks links as before; an id that owns decks links nothing and opens the question; an id whose browser chose Keep Them Separate (`ts.keep_separate`, the id and a MAC under the identity secret) is not asked again. The session hook (`onSessionCreated`), the request identity (`linkUnderSession`, now through `requestAliases`) and the room's session identity (`room.ts`, which linked on its own before) all go through it. `mergeQuestion` and `answerMerge` serve the page. While the question is open the browser's requests act for its own decks, for that browser alone, so the deck being edited stays open and the account's other browsers do not reach it. The count is the deck index's owned view; a checkout's file store (every deck the caller's) and a runtime with no deck index count none and link as before.
- `apps/studio/src/components/home/sign-in.tsx`: `readSignInFacts` carries `merge`; `answerSignInMerge` (a server function, so the CSRF middleware covers it) links or sets the cookie. `/signin` asks when `merge` is set instead of going on to `next`, and the page host's sign ins (the link, Google, the code) return through `/signin?next=`.
- The plate: the merge step (heading "Decks made in this browser", the question, Add Them and Keep Them Separate, "Decks you keep separate stay in this browser. Sign out to open them again.").
- `room.ts` is not in 4.13's list for this push: its session identity linked the browser's id on every room request with a session, a second silent path the spec's file list missed; the change is the one call.

Cost: a signed in browser whose anonymous id is not linked yet reads that id's owned deck index once per session per instance (the session facts row holds the answer; on the SQLite engine, which caches no session, once per request), and an empty index falls back to the scan of the records that CLEANUP-2 and HR-C#7 replace. A linked browser reads one alias row, as before.

Known gap until DROPDOWNS DD-C#2: the editor's own sign in window (`EditorRoot.tsx`, the dropdown round's file) returns to the deck and asks nothing, so a browser that signs in there keeps its decks to itself, open in that browser, until the person passes `/signin`. The follow-up is two lines in `EditorRoot.tsx` after DD-C#2: the window's `callbackURL` and the code's reload go through `/signin?next=<deck path>`.
