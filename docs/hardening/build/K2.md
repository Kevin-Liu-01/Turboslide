## HR-K2#3: the count of the statements outside the list

`apps/realtime-worker/migrations/0004_db_unlisted.sql` adds `ts_db_unlisted`. `db.ts` adds one per refused statement, or per run statement under the report switch, under the digest the 403 answer and the log line already carry: the first 12 hex characters of the text's SHA-256, its kind and first table name, the refused and run counts, the first and last time. Never the text and never a parameter. At most 500 rows; a known digest still counts past that. A failed count (no table yet) is a log line and never changes the answer. `GET /control/db-unlisted` answers the rows under the database bearer, or the room bearer on a Worker that has no database bearer, as `/db` does.

The migration number: H4 took `0003` for the schema version row, so this is `0004`, and the spec's `0004` for SA#3 and `0005` for O#2c move to `0005` and `0006`.

## HR-K2#5: session tokens hashed at rest

`apps/studio/src/server/auth/token-at-rest.ts` rewrites every statement on `"session"` in the two clients all accounts statements pass through: `D1ProxyClient.query` and `.batch` in `d1-proxy-dialect.ts` (better-auth's D1 facade and the app's Kysely dialect both use them) and `NodeSqliteConnection.executeQuery` in `sqlite-dialect.ts`. A parameter bound to the `token` column (an insert's value, a set item, `= ?`, each item of `in (?, ...)`) leaves as `h1:` and its SHA-256 hex unless it already is one; the rows that come back carry the token again in place of the digest the statement sealed. A row of the table whose token is not a digest (a session from before the deploy, which no cookie reaches) is dropped from every read. A comparison of the token column with any other operator throws a TypeError. Kysely's SQLite compiler serves both engines, so one reading of the text serves both.

better-auth's `/revoke-other-sessions` compares the listed digests with the cookie's token (`session.mjs` 476) and would end the caller's own session as well. It is off (`disabledPaths` in `better-auth.ts`), and `account.signOut` with `all` (Sign out everywhere else) now ends the other sessions by id through the internal adapter's `deleteSession`, which takes the digest as it is. `record-statements.test.ts` reads the route's 404; the statement list is unchanged (the recording still sends every listed statement).

The cookie is signed with `BETTER_AUTH_SECRET` (better-call `getSignedCookie`), so a plain token was never a cookie by itself; the change removes the token from every read of the table (the database bearer's list by user id, the weekly export, `/api/auth/list-sessions`, which returned the tokens of the person's other devices to the browser).

Pins:
