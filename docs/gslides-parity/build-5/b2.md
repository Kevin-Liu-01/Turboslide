The parsers, `packages/store/src/media/` (new; framework free, no Node import, so the function, the CLI, the browser's drop path and the bundle scan run one code):

- `bytes.ts`: the bounds checked readers (`u16be`, `u32be`, `u64be`, `u16le`, `u32le`, `floatBe`, `ascii`, `fourcc`, `startsWith`, `codes`) and `MediaParseError`.
- `sniff.ts`: `sniffMedia(bytes): SniffedMedia | null` over R11 1.2's signature table: `RIFF WAVE` (wav) and `RIFF AVI ` (avi), `ftyp` at bytes 4 to 7 with the major and compatible brands (isobmff), the EBML header `1A 45 DF A3` with the `DocType` read inside it (ebml: webm or matroska), `OggS`, `fLaC`, an ID3v2 tag or a Layer III frame sync confirmed by a second frame at its frame length (mp3, with `tagBytes` and `audioAt`), the ADTS sync with layer bits 00 (adts). A WebP's `RIFF` answers null (the picture sniff's). `SNIFF_WINDOW_BYTES` 65,536 bounds the frame search.
- `isobmff.ts`: `parseIsobmff(bytes): IsobmffInfo` (brand, compatible, timescale, durationMs, fragmented, tracks with handler, codecs, width, height, sampleRate, channels, durationMs). The box walk takes `largesize` (size 1), "to the end" (size 0) and `uuid`, descends `moov`, `trak`, `mdia`, `minf`, `stbl`, `mvex`, reads `ftyp`, `mvhd` (version 0 and 1; all ones is unknown), `mehd`, `tkhd` (the 16.16 size from the last eight bytes, both versions), `mdhd`, `hdlr`, `stsd` (the entry codes, the coded size of a visual entry, the sample rate and channels of a sound entry). Bounds: 64 levels, 20,000 boxes; a `mdat`, `free` or `skip` cut short is tolerated, any other box past the end refuses. A `moov` after `mdat` is reached by skipping `mdat`. `MP4_BRANDS`, `M4A_BRAND`, `QUICKTIME_BRAND`, `isMp4Brand`.
- `ebml.ts`: `parseEbml(bytes): EbmlInfo` (docType, docTypeVersion, timestampScale, durationMs, liveSegment, muxingApp, writingApp, tracks with number, type, codecId, width, height, sampleRate, channels) and `EBML_IDS`. Variable size integers per RFC 8794 (an id keeps its marker, a size drops it, all ones is unknown); a `Segment` of unknown size runs to the end of the buffer (`liveSegment: true`); the walk stops at the first `Cluster`; 16 levels, 20,000 elements. `Duration` times `TimestampScale` over 1e6, null when absent.
- `mp3.ts`: `id3v2Size` (the synchsafe size, ten more bytes when the footer flag is set), `frameHeaderAt` (the MPEG-1, 2 and 2.5 bitrate and sample rate tables, Layers I to III, the frame length), `findFirstFrame` (a header confirmed by the next), `parseMp3(bytes): Mp3Info` (audioAt, header, vbrHeader `xing` or `info` or `vbri` or null, frames, encoderDelay, encoderPadding, durationMs, bitrateKbps, sampleRate, channels). With a `Xing` or `Info` frame count and a LAME tag (`LAME`, `Lavc` or `Lavf` after the Xing data) the encoder delay and padding are subtracted; with none, every frame is walked and its samples summed. A Layer I or II stream is refused by name.
- `wav.ts`: `parseWav(bytes): WavInfo` (formatTag 1 or 3, extensible, channels, sampleRate, bitsPerSample, blockAlign, avgBytesPerSec, dataBytes, durationMs, codec as ffprobe names it), `isRiffWave`, `wavFormatName`. `WAVE_FORMAT_EXTENSIBLE` resolves through the sub format GUID; a `data` size of all ones or past the end is clamped to the bytes present; chunks are walked by their padded sizes; ADPCM, MP3 in WAV, A-law, mu-law and every other tag are refused with the tag named.
- `info.ts`: `mediaInfo(bytes): MediaInfo | MediaRefusal` (never throws on bad bytes), `isMediaRefusal`, `MediaFormat` and `MEDIA_FORMATS`, `MediaPlayability` and `playabilityOf(format, codecs)` (R11 1.1: Chromium builds lack H.264 and AAC, HEVC is Safari's, everything else decodes everywhere), the refusal sentences (`ACCEPTED_MEDIA_SENTENCE`, `UNKNOWN_MEDIA_SENTENCE`, `QUICKTIME_SENTENCE`, `MATROSKA_SENTENCE`), `mediaFormatOfName`, `CONTAINER_OF_FORMAT`, `sniffName`, `mediaFormatProblem(path, bytes)` (the bundle scan's name rule). mp4 against m4a is decided by the tracks: a video track makes `video/mp4` and `mp4`, sound tracks alone make `audio/mp4` and `m4a` (the `M4A ` brand lands there too); a webm with audio tracks alone is `kind: 'audio'` in a `video/webm` container.

### 1.3 Deviations and decisions

1. `Deck.media` stays a second map beside `Deck.assets` (the integrator's day 0 item 7.1 left the fold to B2). The call: keep the two maps. The union moves 96 picture reader sites in 40 files across every lane, merge 1 would conflict on each, and no surface needs it: `mediaAssetForBlock`, `posterOf` and `mediaBytesOf` take the media map, the reducer's `asset.set` and `asset.remove` already route by kind, `diffDecks` reads both, and `validate/media.ts` resolves a block's `source.asset` against `deck.media` and its `poster` against `deck.assets`. SPEC-5 0.16's sentence "one map holds pictures and media" is read as one id space (an id names one record in either map; the validator names a picture id used as a media source and a media id used as a poster).
2. The kind a mime carries is a list (`MEDIA_KINDS_OF_MIME`): `video/webm` carries `audio` too, because the five mimes hold no audio only WebM type and a recording with no video track (R11 6, the MediaRecorder path) is an audio asset in a webm container. An mp4 with sound tracks alone is stored as `audio/mp4` with the `m4a` extension, so `video/mp4` is video alone.
3. The MP3 duration follows ffprobe: a `Xing` or `Info` frame count with a LAME tag has the encoder delay and padding subtracted (the one second tone reads 1000 ms, not the 1152 ms its sixteen frames hold); a bare stream is walked frame by frame (ffprobe's 1152 ms for the same stream without the header, the frames as they are). R11 1.3's Xing formula alone would read 1152 ms against ffprobe's 1000 ms, outside the 20 ms tolerance, which is why the LAME read is in. The VBRI path is implemented from R11 1.3's layout and is untested by a fixture (no encoder here writes one; R11 marks it unverified).
4. The validator's `volume` rule is the zod schema's (`min(0).max(100)` answers `invalid` before the family runs), so `validate/media.ts` does not repeat it; `playbackProblem` keeps it for `media.setPlayback` (day 4), which validates a partial record before the write. The deck's media sum over 300 MB is severity 2 (a defect, not a refusal that would make a stored deck unopenable); the per file cap is severity 3 as 1.2 says. A start or end past a known duration is severity 2 (not in 1.2's list; added for agents, who otherwise learn it in the show).
5. The bundle scan checks a media entry's container against its name (R11 1.2's rule) and not its kind: an `.m4a` holding an mp4 brand file with a video track passes the scan, because the kind is the record's (`validate/media.ts` checks the record against its file's extension). The ADPCM wav passes the scan too (it is a RIFF WAVE) and is refused by the intake's parser.
6. `bars-live.webm` (ffmpeg's live muxer mode) stands in for R11 8.3's `recorded.webm` until `media.spec.ts` captures one with MediaRecorder on day 7; it has the two facts that matter (an unknown Segment size, no `Duration`).
7. ffmpeg's encoders decided two refusal fixtures: `libvorbis` is not built in, so `tone.ogg` holds Opus in Ogg; `bars.avi` holds MPEG-4 part 2 with MP3. Both are refused by container, so the codecs inside do not matter.
8. `INLINE_TYPES` is exported from `headers.ts` (it was module private) so its test pins the nine types; no other module reads it.
9. `apps/studio/src/server/upload.ts` gained the `MEDIA_UPLOAD_CONTENT_TYPES` constant alone; the media grant route that reads it is day 3.

### 2.3 Deviations and decisions

1. The picture effects' pure helpers (`NATIVE_RECOLOR_PRESETS`, `isNativeRecolor`, `duotoneColors`) and the twin variant's readers (`twinVariantOf`, `twinSrcset`, the file names) live in `packages/schema/src/blocks/media.ts`, this lane's runtime module, because the export and render packages both need them and `@turboslide/render` exports neither `./blocks/picture` nor `./blocks/media` (the package.json is the integrator's, R1's second half); the renderer re-exports the three. `TWIN_VARIANT_WIDTH` spells 320 in that module rather than importing `TWIN_VARIANT_SIZE` as a value: `assets.ts` imports `blocks.ts`, which imports this module, so a value import there closed a cycle that left the media block schema undefined while the block union was built (`blocks/media.test.ts` pins the two equal).
2. The Editable text file writes `a:grayscl` and `a:duotone` natively only once B1's extractor shoots those pictures with the filter dropped (`data-native-blips` on the sheet root, the CSS rule is in) and B1's build calls `rewriteRecolorBlips` after the pictures are placed (R9); until then every recolor and the reflection bake into the 2x shot raster, which is the correct picture, with the residual lines `pictureEffectResiduals` writes once B1 appends them. The Perfect raster follows the renderer in both states (0.47).
3. The reflection lifts the box's clip with `clip-path: inset(0 0 -reach 0)`; a mask preset keeps its own `clip-path: path()` (the later declaration wins) and clips the reflection with it, so a masked picture shows no reflection outside its shape; recorded rather than worked around.
4. The duotone list is Turboslide's over the theme's tokens (`unverified: true`), spelt "Colour, light" and "Colour, dark" in the dropdown; Google's labels for its theme derived rows were not read from a page. The semantic hues are the schema's `SEMANTIC_PALETTE` hex values because the sheet declares no `--green` token.
5. The 320 variant is an RGBA PNG for continuous pictures too (SPEC-5 11 says JPEG): `@turboslide/effects/io` has no JPEG encoder and the materials package cannot import `sharp` directly (a dependency is a request); at 320 by 180 the PNG is tens of kilobytes. R14 asks for `encodeJpegRgba` and the writer switches when it lands. The two tone variant is nearest neighbour RGBA rather than a palette PNG for the same reason; both are two colours.
6. `srcset` is written by the renderer, not by `Filmstrip.tsx`: the clone receives rendered HTML, so the picture's `srcset` comes from `renderPicture` when the record carries the variant and `LiveClone` sets `sizes` from its measured width; the `Filmstrip` line MILESTONES-5 names becomes unnecessary and the standalone build must strip `srcset` and `sizes` (R11, B1) so the file inlines the 1600 alone. The slide level picture kinds (`slide.ts`, B4) and the `shot` block (`figures.ts`, B4) do not carry `srcset` yet; R15 offers `twinSrcset` for the two lines.
7. The keyed prefix stores under `d/<deckId>/<assetKey>/<file>` with the record keeping `assets/<file>` (the reader holds the key, so a rotation moves objects and no record); the intake writes keyed only when the hosted dispatcher composes `MediaIntakeDeps.assetKey` (R4) and the store offers `putKeyedAsset` (the blob backend; a checkout writes the plain file). The rotation trigger (a link revoked, a collaborator removed, `share.remove`, `share.revokeLink`, `share.rotateLink`, a general access change to `restricted`) is `records/access.ts`'s write plus `HostedDecks.rotateAssetKey` (R12). Until R4 lands, media follow the picture precedent and the Share dialog carries the interim sentence (R13), as SPEC-5 3.3 allows.
8. The deck index is written from the collection (`blobDecks`), not from B7's write function: the store `storeFor` hands out has its `write` wrapped so a commit notes its row, which keeps this lane out of the document write path (A6). Past the threshold the agreement check is the store's folder listing against the index's ids (one `folders` call the list made already); a listed deck whose manifest moved on another instance keeps its index row until that instance's coalesced write lands (2 s), the same window the manifest walk had through the CDN.
9. The camera photo writes no `source: { kind: 'camera', at }`: the picture `AssetSource` union has no camera member (the media one has), so `asset.add` refuses it; R16 asks for the row and the dialog passes it once it exists.
10. The spotlight's camera is asked once per show at the first spotlight slide through the controller's `camera` option (the Present click is the activation); a refusal leaves the placeholder for the show. The presenter console shows the placeholder because the console never mounts elements (0.17).
11. `view.presentOnScreen` on the server answers `{ supported: false, screens: 0, opened: false }`; the executor is `presentOnScreen` in the dialog module, wired to the row and the window handler by the integrator (R5). The Presentation API is not used (R11 7).
