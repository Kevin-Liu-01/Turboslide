### 2.2 Memory

- The function runs at the project's standard size, 2 GB and 1 vCPU (`docs/hosting-diagnosis.md` 25, read 2026-09-11; `docs/gslides-parity/sync/audit-costs.md` 22, the seven day metric of 2026-09-13 to 2026-09-20). The config's `memory` field is inert (section 1.2).
- `@sparticuz/chromium`'s README asks for 1600 MB or more for the browser alone (`docs/hosting-diagnosis.md` 225 to 227; `docs/hosting-chromium.md` 292).
- The merge of a batched export peaked at 834.6 MiB resident with no browser (`build-2/b6.md` 199); the merge samples its own resident memory every second and answers it as `peakMb` (`export-batch.ts` 103 to 108, 398).
- The stream holds the instance's memory for its life: 265 s of 2 GB per open when a tab is alone on its instance, 21 s as measured on production with instances shared (`docs/SYNC.md` 4.3 as cited by `audit-costs.md` 113 and 154; `research-hosting.md` section 4 item 3). The seven days to 2026-09-20 billed 466.6 GB hours (`audit-costs.md` 45).
- The Durable Object sketch in `research-options.md` 5b priced "a 128 MB object" (read 2026-10-01). The export and render paths above need an order of magnitude more than that per call.
