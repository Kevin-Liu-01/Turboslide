### Correction 5: the speed mark drawings as diagram blocks

Request 17 found each speed mark slide imported as one html escape block, so the first canvas write put the drawing over the text and no part of the slide moved apart from the others. The template's seven speed mark slides therefore come from an import of a scratch copy of the Prototemplate deck in which slides 17 to 23 carry two edits and nothing else (`round1/build/b4/b4b/speed-source.diff`):

2. On the lockup slide, the grounds' classes `ground paper` and `ground ink` become `ground on-paper` and `ground on-ink`, with their two rules. `paper` and `ink` are grammar classes the importer drops (`map-blocks.ts` 45 to 119), and the residual rules that draw the paper ground's hairline and the ink ground's fill would then match nothing.

Two values of the lockup slide's record were then set by hand, each to what the source draws:

- `layout.gap` 36 in place of 44. The source writes `.split { gap: 44px }` and later `.split { gap: 36px }`; the importer takes the first into the layout, which the renderer writes as an inline style, and carries the second as a residual rule, which the inline style beats (read in the sources and the rendered HTML).
- `justify-content: start` back on the grounds' residual rule. The importer drops `start` as the default, but the renderer's `.composite` (`render/src/block-css.ts` 58) sets no `justify-content`, and a grid of `auto` tracks stretches them without it, so the small marks would sit to the right of where the source draws them (read in the CSS, not in a render).
