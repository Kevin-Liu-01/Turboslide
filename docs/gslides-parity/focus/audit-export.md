# Export, print and the agent surface: the audit on production

By the export auditor, 2026-09-15, against https://turboslide.vercel.app (main at ec61c6b, the round four hotfixes and the poll cadence). Headless Chromium through `playwright-core` 1.62.1 from the repo root, Node 24.13.0, viewport 1440 by 900 at device scale 1, at human speed (the mouse moves in steps, 40 to 90 ms per key, real double clicks, real clicks through pointer down and up), through the product's own UI, its window API (`window.turboslide.studio`) and its HTTP surface. Two runs, each on a scratch deck created from `/new` and trashed and deleted forever in a finally block: `untitled-20260916-2ie1` (run 1, 413 s, 37 rows) and `untitled-20260916-lmwb` (run 2, 96 s, 29 rows). Both decks answer 404 on `/edit/<id>` and on `/deck/<id>`. `.turboslide/e2e.lock` was held by another walk when both runs started; this audit did not take it, since each run uses its own deck. No source file was touched. The scripts are `audit-export.mjs` and `audit-export-2.mjs` under the session scratchpad (`focus/export/`); the rows they recorded are `audit-export/rows.json` and `audit-export/rows-2.json` beside the screenshots.

Copy rules: every row reports what happened. A step that could not be driven is "not driven", never passed. Severity 0 means the row works and has no defect; 3 means the seller cannot complete a top task, 2 a wrong or lost result, 1 cosmetic. Need follows research 07 sections 2, 3 and 8: core is a weekly task of a seller, useful helps but a seller finishes without it, park is rarely needed by a seller or is a designer's tool.

## Summary

51 rows: 42 work, 6 are broken, 1 is flaky, 2 were not driven. The console held one repeated entry across both runs, the report-only CSP notice about `upgrade-insecure-requests`, and no product error.

### What works

- File > Download > PDF Document (.pdf): the dialog opens with its sentence "One slide per page, 13.333 by 7.5 inches.", both checkboxes off, Cancel and Download; Escape, Cancel and the X close it; Download shows "Preparing your PDF, about half a minute for 2 slides" and "Your file is ready." with a Details link to the report card; the file arrives from the Blob store as `untitled-<date>-<id>-dark.pdf`, PDF 1.4 by Skia/PDF, two pages for the two unskipped slides; with Include skipped slides checked the sentence counts three slides and the file has three pages. Four PDF runs in run 1 took 1.2 to 4.2 s; run 2 took 1.3 to 5.2 s.
- File > Download > Microsoft PowerPoint (.pptx): the dialog offers Perfect (default) and Editable text as radios with one sentence each, the two checkboxes, and More options (Appearance defaulting to the deck's Dark, Fonts Exact or Standard, Embed fonts enabled only under Editable text, Headings as pictures). Perfect gives a PPTX with `[Content_Types].xml`, two `ppt/slides/slideN.xml` parts, two notes parts holding only the slide number, four media parts, 74 KB in 7 s. Editable text gives two slide parts with the title as a text run in `slide1.xml`, 32 KB in 3.4 s. With Include speaker notes and Include skipped slides the file has three slide parts, three notes parts, and the talk track inside `notesSlide1.xml`.
- File > Download > Plain Text, Web page (.html) and Turboslide bundle (.zip): the text file holds the title, the HTML file (561 KB) starts with `<!doctype html>` and holds the title with the snackbar "The web page is ready", the bundle zip (403 KB) holds `deck.json` and the three slides.
- File > Print settings and preview, File > Print and Cmd+P all land on `/print/<id>`: two pages, the layout dropdown with "1 slide without notes", "1 slide with notes" and five disabled handout rows, Include skipped slides off, Close preview, Download as PDF and Print. "1 slide with notes" shows the talk track under slide 1 and "No speaker notes for this slide" under slide 2. Include skipped slides raises the count to three and marks the skipped page. Print calls `window.print()` once. Close preview returns to the editor.
- Help > Help lists the ten how-tos, the last being "Send a PDF or a link"; Help > Keyboard shortcuts opens, filters to "Print, Cmd P" on a search, and closes on Escape; Help > Search the menus finds every Download row.
- The window API: `describe()` answers version 1, owner editor, 156 actions, and the deck facts in `state`; `deck.info` and `slide.list` answer the three slides with one skipped; `block.set` with a stale `baseRevision` is refused with "ConflictError: baseRevision 4 is stale; the document is at revision 5" and with the current base writes revision 6 and reads back.
- The HTTP surface: `GET /api/agent` answers 401 without a bearer and 200 with the agent bearer (156 window actions, 150 implemented, 19 not implemented, 148 on http, `auth.required` true, the instance on Node v24.18.1 with the typescript effects backend); `GET /openapi.json` answers OpenAPI 3.1.0 "Turboslide agent API" 0.1.0 with 153 paths and `cache-control: public, max-age=300`; `/llms.txt` answers 200; `/mcp` answers 401 without a bearer.

### What is broken, with the mechanism seen

1. File > Download > JPEG image and PNG image (current slide) open a new tab that shows `{"error":{"name":"Error","status":401,"message":"bearer token required: send Authorization: Bearer <TURBOSLIDE_TOKEN>","code":"unauthorized"}}` (three tries each, rows 22 and 23; `popup-1.png`). Mechanism: `packages/chrome/src/EditorShell.tsx` runs the row as `render.slide` and then `window.open(images[0], '_blank', 'noopener')`; the URL is `/api/render/<slideId>?deck=<id>&theme=light&scale=2&revision=N`; `apps/studio/src/routes/api/render.$slideId.ts` refuses a full size render without the bearer whenever `TURBOSLIDE_TOKEN` is set, and production sets it; a browser tab carries no Authorization header. The same URL fetched with the agent bearer answers 200 `image/png` (row 24), so the route renders and the tab is what fails. Two smaller points on the same rows: the JPEG row's URL carries no `format=jpg`, because the editor's `render.slide` handler in `apps/studio/src/editor/controller.tsx` forwards only `slideIds`, `themes` and `scale` to `renderSlideImages`; and no theme is passed, so the server default puts the light render first on a dark deck. Severity 2, need useful.
2. Download as PDF with Include speaker notes checked produces the same two pages as the plain PDF (row 15): four observations across the runs, each file the same length as the plain PDF with two or four differing bytes (the CreationDate and ModDate seconds), the title in the inflated content streams and the note text never. The dialog sends `includeNotes: true` with `export.run`; the PDF that comes back has no notes layout, and the dialog's own sentence says "One slide per page". Severity 2, need useful.
3. The print page's Download as PDF ignores the state of the preview (rows 31 and 32): with Include skipped slides checked and three pages shown ("01 / 03" in the frame), the file has two pages (three observations); under "1 slide with notes" the file has two pages and no note text. Mechanism: `apps/studio/src/routes/print.$deckId.tsx` `downloadPdf` sends `{ format: 'pdf', slideIds: <the ids shown> }` with no `includeSkipped` and no notes flag, so the export drops the skipped id and renders the default two pages; the file is the same `untitled-<id>-dark.pdf` at the same size as the editor's default PDF. Severity 2, need useful.
4. The Documentation link in Help > Help points at `/docs`, which answers 404 on production; `/help` answers 404 too (row 39). `packages/chrome/src/dialogs/Help.tsx` hard codes `href="/docs"` and the route list at ec61c6b has no docs route. Severity 1, need useful.
5. The first click on File after Close preview brings the editor back is lost (row 35, flaky): on both runs the first click showed the File button's tooltip and pressed state and opened no menu within 8 s, and the second click opened it. No mechanism traced; the active element was `body` before each click and the editor reported settled. Severity 1, need core.

Not driven: the ODP and SVG rows are present and disabled with the Not available clause, so nothing could be started (row 27); Help > "improve" (the GitHub issue row) was not clicked because the audit matched labels on problem, issue or feedback (row 42). Save as PDF inside the browser's print dialog cannot be driven headless; `window.print()` was seen called once, and the CDP print of the page under the print stylesheet produced four pages for two slides, which is what the dialog would show as its page count (row 33).

### What a seller needs here

Per research 07, a seller's export tasks are sending a PDF or a link after the call and a PowerPoint when the customer asks for one, with skipped slides and speaker notes left out unless asked. All of that works on production today: the PDF and the PPTX arrive with the right page and slide counts, notes and skipped slides are off by default and the PPTX honours both checkboxes. The paths that do not work are secondary for a seller: the slide image rows (JPEG, PNG) fail for everyone on production, the PDF's Include speaker notes checkbox promises something the file does not carry, the print page's Download as PDF does not follow the preview, and the help link is dead. Under Kevin's directive to keep the features that work and drop the rest, the candidates in this area are the JPEG and PNG rows (fix the tab so it carries the render, or remove the two rows), the Include speaker notes checkbox on the PDF dialog (remove it until the PDF carries notes), the print page's Download as PDF button (send the preview's state, or leave the seller with Print and Save as PDF), and the Documentation link (point it at a page that exists, or remove it). The Print button, the shortcut, the PPTX dialog and the PDF default path need no change from what this audit saw. The file name by deck id (`untitled-20260916-2ie1-dark.pdf`) is a cosmetic point a seller renames before sending.

## Method

One deck per run from `/new`: the heading typed at human speed and committed with Escape (the first write creates the deck), two slides added through Slide > New slide, the third skipped through Slide > Skip slide, a speaker note typed into the notes field of slide 1. Every File > Download row driven through the menu (File, hover Download, click the row), every dialog control clicked at its visible box, every download saved through the browser's own download event and checked on disk (`%PDF-` header and the `/Type /Page` count for a PDF; `unzip` listing of `ppt/slides/slideN.xml`, `ppt/notesSlides/notesSlideN.xml` and `[Content_Types].xml` for a PPTX, with `unzip -p` for the text runs; the doctype and the title for the HTML; `deck.json` for the bundle). The tabs the JPEG and PNG rows open were captured, read for their URL, content type and body, screenshotted, and their URL fetched again from the page's own context and once with the agent bearer from `~/.config/turboslide/hosts.json` (the token was read by the script and never printed). The print page was driven through its controls; `window.print` was replaced by a counter for one click and restored by the page's reload. The window API was driven from `page.evaluate`, the HTTP surface with node `fetch`. A failed interaction was repeated three times before it was called broken; a success on the second or third try is flaky. The cleanup ran in a finally block: File > Move to trash, then Delete forever on `/decks/trash` with its confirmation, then `GET /edit/<id>` and `GET /deck/<id>` until both answered 404.
