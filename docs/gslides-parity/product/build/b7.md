### 2. The assist route

`POST /api/assist?deck=<id>` with `{ action: 'assist.propose' | 'assist.accept', input }`, the shape B6's note R9 names, from the seller's page with its cookies or an agent with the bearer. In order (`server/assist-route.ts handleAssistRequest`): POST alone (405 with `allow`); the same origin rule unless the request carries a bearer (a bearer agent sends no Sec-Fetch-Site and no Origin, as on the room routes); `application/json`; one JSON object under 1 MB with an `action` of the two and an `input` object; the deck id as a slug (404 `unknown_deck` otherwise); `authorize()` with the request's identity (`room.requestIdentity`, so the bearer is the bootstrap agent and the cookie the principal), `comment` to propose and `write` to accept, the denial answered as `denialBody` shapes it and before any switch is read; the `assist` switch (503 with "The assistant is off on this Turboslide" and `retry-after: 60`); the `readOnly` switch on an accept alone; the two assist quotas on a propose alone (`checkAssistQuotas`, 429 with the sentence and `retry-after`); then the action on the deck dispatcher under the caller's author. The handlers are B6's `registerAssistActions` (`server/assist.ts`): the route registers them on the per request dispatcher when the dispatcher lacks them, with `logAssistLine` for the per call line of 6.5, so `/api/assist` serves the panel before and after the integrator's R3. Every refusal is one JSON object `{ error: <code>, message: <sentence> }`: `method`, `cross_site`, `content_type`, `invalid_json`, `invalid_input`, `unknown_deck`, `unauthorized`, `forbidden`, `not_found`, `gone`, `unavailable`, `rate_limited`, `conflict` (with `currentRevision`, `current` and `holder`), `not_implemented`, `model` (a provider's 5xx or the model's latency: 502 with `retry-after: 5`), `error` (500 with "The assistant could not answer; try again"); never a stack. One log line per call: `turboslide assist: <action> <status> <ms> ms deck=<id> identity=<label>`, never the deck text; B6's line carries the tokens.

The checkout file is the switch's store on a checkout (`.turboslide/flags.json`, `{"assist": false}`); hosted, the memory and redis channels' `flag()` refuse a name the schema lacks, so until request R2 lands the assist reads its default, on, and the flip works through the file alone. `flagOn` treats that refusal as the default without a `redis.unavailable` line, for the assist alone.

Driven by hand on 4417 (curl, the fixture model, a scratch deck `gt-pitch-for-acme` made over the agent surface, trashed and deleted forever at the return): propose with `intent: 'notes'` answered 200 with one signed card ("Slide 1: speaker notes, 19 words", one `slide.set /notes` mutation) in 30 ms; the same card with one byte of its signature changed answered 403 "This proposal is not one the assistant made for this presentation"; accept answered 200 `{ revision: 1, slideIds: ['title'], sentence }` and `deck.info` read revision 1; the same card again answered 409 "The slide changed while this was written; ask again" with `currentRevision: 1`.
