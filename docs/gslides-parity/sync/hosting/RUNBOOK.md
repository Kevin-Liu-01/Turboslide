# The hosting move runbook

The rehearsal of `docs/HOSTING-MOVE.md` 2.2, the cutover of its section 5 and the rollback of its section 6 as numbered steps with every command, written 2026-09-21 by B6 of the sync round. Every command line is marked: **Kevin** for anything that creates, changes or deletes a Vercel or GitHub object (a project, a store, a transfer, a variable, a deployment, a rule, a setting), **pipeline** for a command that reads, and for the scripts of the repository. Nothing in this file has been run against a real store, project or deployment except the read only checks named in section 6; nothing was created, changed or deleted on Vercel or GitHub while it was written.

Every `vercel` flag below was checked against Vercel CLI 58.4.4's own help on 2026-09-21 (`cli-help-58.4.4.md` beside this file holds the blocks; section 7 maps each command to its block). The dashboard is the path of record where the plan names it (the store transfer and connection, the project settings, the Git Sources override, the analytics toggles, Instant Rollback); the CLI form stands beside it where a flag exists. `vercel env ls` is the spelling the plan and the audits use; the help names the subcommand `list` and accepts `ls`.

Placeholders: `<team address>` is `https://turboslide-general-translation.vercel.app` until the team project exists and names its alias (2.3); `<ship json>` is `docs/gslides-parity/focus/ship-<commit>.json` of the ship; `<store id>` is a `store_...` id from `vercel blob list-stores --all --json`. A secret is never typed on a command line and never printed: a token reaches a command through the environment of a subshell (`( set -a; . <file>; set +a; <command> )`) from a file outside the repository that is deleted afterwards, or through the CLI's own prompt (`vercel env add` without `--value` asks for the value).
