## 3. Decisions, and the deviations recorded for Kevin (SPEC 15.11)

1. **The PDF is printed at the sheet's own size and scaled by the printer.** The print document
   lays every page out at 1600 by 900 px and `page.pdf({ scale: 0.8 })` puts it on the 960 by 540
   pt page. A CSS `zoom` or `transform` of 0.8 made Chromium snap every hairline to whole CSS
   pixels before scaling (each rule half a raster pixel off and a pixel wide; 0.27 to 0.63 percent
   per page against the 2x render), and with a transform the print also shrank the whole page by
   1280 over 1600 (every frame at 80 percent of the page). With the print scale the rails land on
   the pixel: 0.003 to 0.035 percent on the fixture.
2. **`contain: strict` on the page box.** Without it Chromium's print fragmentation dropped whole
   blocks from any page that had a page after it: the swatches of `color` and the twelve tile
   pictures of `engines` were absent from the GT deck's PDF while the same slides printed alone
   were complete (bisected: `color` printed as page 2, 5, 10, 12, 14, 16 and 17 of a document it
   ended, and lost the block as page 18 of 20 or as page 1 of 2). The gate found it.
3. **The PDF gate rasterizes at 3200 by 1800, not `pdftoppm -r 144`** (SPEC 7.6). The diff needs
   the page on the 2x render's pixel grid; 144 dpi gives 1920 by 1080, which matches no render.
   pdftoppm is still the first choice, pdftocairo the fallback, the residual names the one that ran.
4. **Picture regions are compared separately and never gated.** The PDF holds the twin bytes and
   every viewer resamples them with its own filter: a 1x dither twin upscaled to 2x differs by 20
   percent between poppler and Chromium (`mood-dictionary`), a downscaled screenshot by 2 to 6, the
   dither canvas by 9, where the text around them sits at 0.02. Gating them would fail every deck
   with a picture for a difference the file does not carry. This is the reading the flatten loop
   already gives regenerated pictures (SPEC 8.5); the report carries `pictureFraction` per page and
   names the worst.
5. **Notes travel only when asked** (SPEC 7.2.13, decision 15.2): `buildPptx` writes `addNotes`
   under `includeNotes` only. Before this round every export carried the notes; the fixture test
   asserts both forms.
6. **The verify pass runs inside `exportPptx`** when asked, per theme, so the table fallback of SPEC
   7.3 can rewrite a file and verify it again. The CLI's separate `verifyPptx` calls (per theme and
   then the merged report, which rendered both files a second time) go away in the requested
   `export.ts`; the merged report is the union of the verified per theme reports.
7. **The table cell ids stay out of the report's `verify.blocks`** because `blockIdSchema` refuses
   `table/1/2`; they live in the verify summary and the `onSlide` verifications, which is where the
   fallback reads them.
8. **`data-counter` on every slide root** replaces the extractor's hand written counter and the
   runtimes' own count, so a download without skipped slides numbers what it holds (SPEC 7.2.1) and
   `defaults.counter` reaches every surface (SPEC 7.2.4). B4's stage and B6's slideshow should read
   `deckCounter(deck)` and `slideCounter` the same way (section 6).
9. **The numeral of a numbered list sits outside the Text's carrier** as `data-num`, so the inline
   editor never reads it as copy; the measurer exports it as its own run.
10. **The block link wrapper is an anchor outside the editor and a span inside it.** The measurer
    reads the wrapper whose first element is the block, so a block inside a linked composite is not
    mistaken for a linked one.

## 6. Notes for B3, B4, B5 and B6

- B3, the layout grid: `renderThumb(deck, slide, theme, { prompts: true })` draws the prompts in a
  tile; without it a thumbnail draws nothing for an empty Text.
- B4, the stage: `RenderOptions.live` draws the prompts (`.prompt[data-prompt]`, unselectable,
  `pointer-events: none`) and the inert link wrapper (`.link[data-link]`); the numeral of a numbered
  item is `.num[data-num]` beside the carrier; a table cell carrier is `.td[data-run]` inside `.tr`
  inside `.table`, one `.para` span per paragraph always. The counter text of a slide is its
  `data-counter` (`slideCounter` in `@turboslide/render/deck`).
- B5, `/print/:deckId`: `renderPrintDocument` from `@turboslide/render/print` is the whole page;
  a browser print dialog shrinks the 1600 px pages onto 960 by 540 pt by itself.
- B6, present mode and the standalone runtime: `data-counter` on every slide, the slide link
  keywords, and `#ts-notes` in a standalone built with `includeNotes`.
