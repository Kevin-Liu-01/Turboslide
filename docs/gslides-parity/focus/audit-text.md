# Focus audit: text entry and formatting

Auditor for the area "Text entry and formatting", focus round, 2026-09-15, against production https://turboslide.vercel.app (round four, client bundle `/assets/index-CYGrLim1.js`). Headless Chromium through `playwright-core` 1.62.1 from the repository's `node_modules`, Node 24.13.0, viewport 1440 by 900 at device scale 1. No source file was changed. The scripts live under the auditor's scratchpad (`focus/text/audit-text.mjs`, `audit-text-2.mjs`, `audit-text-3.mjs`) and import nothing from the repository but `playwright-core`. Evidence screenshots are in `focus/audit-text/`; the raw tables are `rows.json`, `rows-2.json`, `rows-3.json` beside them.

## Method

Three passes, each on its own deck created from `/new` and driven through the product's own controls: the runs by `data-run`, the menus and buttons by `data-control`, the toolbar tail's text controls, the colour plates, the align and spacing lists, the run's link popover, and the Find and replace dialog. Every observed value is read from the DOM and from `window.turboslide.studio` (`describe().state`, `slide.get`). Human speed throughout: the mouse moves in steps with a pause between them, keys land 40 to 90 ms apart, words are separated by pauses of 250 to 600 ms where the interaction says "with pauses", double clicks are the browser's own, and the text box drag holds the pointer from down through the move stream to up. A failed interaction was repeated three times before it was called broken; a pass on a later try is flaky; an interaction the script could not drive is not driven with the reason.

Pass one (deck `untitled-20260916-nb3i`) drove the whole brief. Its rows for a new text box exposed refused text bursts, and its retries stacked three boxes at one point, so from the toolbar section on it clicked through a stuck refusal card and read the wrong block. Pass one's placeholder rows and its finding on the fresh text box stand; its toolbar and menu rows are superseded by pass two (deck `untitled-20260916-itw2`), which used one box per place, dismissed the refusal card before every click, and confirmed the selected block through `describe().state.blockId`. Pass three (deck `untitled-20260916-tsb3`) isolated the interactions that pass two still confounded by marks piling up on one reused box: each got its own fresh box with its text set clean first. All three decks were moved to trash, deleted forever, and answer 404 on `/deck/<id>` and `/edit/<id>`.

## Summary

### What works

Placeholder and text entry are solid. On the title and subtitle placeholders a single click and a double click open the editor, typing a sentence with spaces, punctuation and a number at human speed lands correctly, and the first write creates the deck and moves the address to `/edit/<id>`. Every caret and selection interaction the brief lists behaves: click to place the caret mid word, Home, End, arrows, Shift with the arrows and with Home and End, Backspace across a word, Option+Backspace, Delete, and Cmd+A. Enter and Shift+Enter make new lines in the multiline subtitle and end the single line title (the title commits on Enter by design; no text is lost). The keyboard mark routes work: with a word selected in the text session, Cmd+B, Cmd+I, Cmd+U and Cmd+Shift+X apply the mark to that word. The toolbar Bold button, the font size plus and minus, alignment, line spacing, highlight colour, indent and outdent, and clear formatting all apply. The Format menu text rows are enabled and apply. Find and replace, the seller's top task, works end to end: it counts the matches and replaces every occurrence across the deck. Autosave persists every edit across a reload. A long title wraps and stays within the sheet.

### What is broken, and the mechanism seen

- Links (severity 3, core). Cmd+K opens the link popover and the field accepts the URL, but pressing Enter inserts the URL as literal text at the caret and does not wrap the selected word. The stored text becomes "https://example.com/acmeSee the proposal online". The selection is lost when the field takes focus, so the link is created against a collapsed caret. Present mode then has no link to click. A seller building a clickable agenda or sending a deck with a proposal link cannot do it, and the caption is left garbled.
- Bulleted and numbered lists from the toolbar (severity 2, core). Clicking the toolbar Bulleted list or Numbered list button on a selected text box does nothing: the block stays a plain text block with no marker. The working route is Format > Bullets & numbering > Bulleted list and then picking a preset, which does convert the block. A seller reaching for the toolbar bullet button, the Google gesture, gets no list.
- Autofit in a text box (severity 2, core). A text box stores autofit "grow" but does not grow to hold typed text; a long paragraph overflows the box while the box height stays fixed, so the overflowing text shows outside the frame on the slide.
- Toolbar text-style buttons act on the whole box, not the selected word (severity 2, core). With a word selected inside the text session, clicking the toolbar Italic button (and the same for the other style controls that route through it) blurs and ends the session, then applies the mark to the entire box. A seller who selects one word and clicks Italic italicises the whole caption.
- Text colour in a text box (severity 2, useful). Opening Text color with a word selected does not apply a colour to a plain text box; the colour target resolves to nothing for that block type, so a coloured number on a results slide cannot be set this way. Highlight colour, by contrast, works.
- Text box burst reliability under stress (severity 2, core). A single clean text box typed once stores its text correctly. But rapid successive inserts, or re-typing into a box after a burst was refused, produce the reject card "A change was not applied: text.splice: N plus 0 is outside a text of M characters", the save status turns to "Couldn't save, retrying", and refused bursts re-send characters so words double. This is the class of loss a seller would hit when tailoring several captions quickly.

### What a seller needs here

Per research/07-sales-users.md the sales user's weekly text work is: retype the cover name and a few numbers, rename the customer across a cloned deck, tailor a caption, and build the occasional bulleted agenda or a link to a proposal. The core of that already works: placeholder editing, all the caret and keyboard interactions, keyboard bold and italic on a word, alignment, and find and replace. The gaps that matter for the seller are, in order: links do not attach to text and leak the URL into the caption (severity 3); the toolbar list buttons do nothing so bullets need the Format menu instead (severity 2); a long caption overflows its box because autofit grow does not resize it (severity 2); the toolbar style buttons hit the whole box rather than the selected word (severity 2); and text colour cannot be set on a text box (severity 2, lower because sellers rarely recolour text). Font family is intentionally absent (the theme font is the brand; the control ships disabled). Font size, alignment, spacing, highlight, indent, clear formatting and the Format menu rows are all present and working.
