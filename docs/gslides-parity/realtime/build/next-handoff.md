1. R4, the Google button. `SignIn.tsx` draws Continue with Google as a solid ink button with no G (audit-brand-surfaces line 49). Google's sign in branding guideline, fetched 2026-10-01 (https://developers.google.com/identity/branding-guidelines), asks for the standard colour G on a light fill `#FFFFFF`, a dark fill `#131314` or a neutral fill `#F2F2F2`, with the label beside it. The program's default (question 25) is that the button follows the guideline: the light button on light chrome, the dark one on dark chrome, the G as an inline brand mark, the label in Inter. If this round does not take it, the next program ships it as hotfix H11.
2. R1 and R4, sign out. The account menu's Sign out row sends `account.signOut` with `{}`; the server finds no session for an undefined `sessionId` and answers `signedOut 0` (`packages/chrome/src/menus/model.ts` 906 on main, `apps/studio/src/server/auth/actions.ts` 480 to 495). A signed out browser keeps its anonymous cookie, which is aliased to the account, so it still renders as the account with the badge (`packages/identity/src/resolve.ts` 215 to 220). The program's hotfix H3 calls `EditorAccount.signOut()` from the row and mints a new anonymous cookie on sign out the way `account.forget` does (actions.ts 513 to 523). If the realtime round's accounts rows read sign out, they read this defect.
